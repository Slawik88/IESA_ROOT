## 🧭 Навигация и Архитектура

### Общее
Навигация реализована через `useState<Tab>` в `App.tsx` — **нет react-router**, нет URL-хэшей, нет history API. Вся маршрутизация — это единый `tab` стейт с нижней навигационной панелью (18 табов + 1 админский).

### Находки

- 🔴 **Нет поддержки кнопки "Назад" в Telegram** (App.tsx, ~строка 155)
  - `tg.BackButton` не используется нигде. Нажатие «Назад» в Telegram **закрывает Mini App** вместо возврата на предыдущую вкладку.
  - Это критично: пользователь на вкладке "Гача" → нажимает Back → Mini App закрывается полностью.

- 🟠 **18 табов в горизонтальном скролле** (App.tsx, ~строка 162)
  - BASE_TABS содержит 18 элементов. На экране 320px видны лишь ~5-6. Остальные скрыты за скроллом.
  - Пользователь может не знать что есть Stars, Promo, Boss, Season, Achievements — они «за экраном».
  - Нет индикатора (точки, стрелки), что есть ещё табы.

- 🟡 **Неоптимальный порядок табов** (App.tsx, строка 66)
  - `settings` стоит перед `stars`/`promo`/`boss` — настройки нужны редко, но занимают место перед геймплейными вкладками.
  - `shards` и `talents` стоят рядом, но между ними и `boss` есть `settings`, `stars`, `promo`.

- 🟢 **ErrorBoundary** (App.tsx, строка 9)
  - Глобальный ErrorBoundary перехватывает крэши любой вкладки и показывает user-friendly сообщение + кнопку «Попробовать снова».
  - Ошибки автоматически отправляются на `/api/frontend_error_log`.

- 🟢 **AppContext** (AppContext.tsx)
  - Грамотный глобальный стейт: `userData` кешируется, `refreshUserData()` переиспользуется в любом месте.
  - Тема применяется на `<html>` атрибутом `data-theme` при загрузке.

- 🟡 **Нет deep linking** 
  - `start_param` из Telegram парсится только для `chatId`. Секция (например `_gacha`) парсится, но не используется для установки начального таба.
  - Если бот отправляет ссылку на "магазин" — пользователь всегда попадает на "Профиль".

## 👤 Profile.tsx

### Общее
Самая большая страница (~600+ строк). Показывает: данные пользователя, чекин, питомца, экспедиции, семейный кошелёк, облигации, подарки, историю кошелька, развод, биографию.

### Находки

- 🟠 **Слишком много стейта** (~строка 64-90)
  - 25+ `useState` в одном компоненте. Не разбит на под-компоненты.
  - Изменение любого стейта вызывает полный перерендер всего профиля.

- 🟡 **Дублированный fetch UserData** (~строка 101)
  - `Profile` вызывает `fetchUserData(chatId)` напрямую, хотя `AppContext` уже держит `userData`.
  - Двойной запрос при каждом заходе на профиль (один из AppContext, один из Profile).

- 🟠 **Секция экспедиций не показывает ошибки** 
  - `fetchExpeditions` ловит ошибку в catch, но не показывает пользователю. Молчаливый провал.

- 🟡 **Развод: двойное подтверждение через `useState`** (~строка ~80)
  - Кнопка «Развод» → появляется ещё одна кнопка «Точно развестись?». Если пользователь случайно нажмёт дважды быстро, развод произойдёт.
  - Нет debounce или временной задержки на второе нажатие.

- 🟢 **Skeleton-загрузка** 
  - При загрузке показывается skeleton вместо спиннера — хорошая практика.

- 🔵 **Рекомендация**: разбить на 5-6 подкомпонентов (PetSection, FamilySection, ExpeditionSection и т.д.)

## 🎲 Gacha.tsx

### Общее
Призыв ×1 / ×10 / ×50. Фазы: idle → rolling → result. Анимация для legendary.

### Находки

- 🟢 **Отличная UX-анимация**
  - Legendary overlay с сиянием, pulse-анимация при ролле, чёткие фазы состояния.

- 🟡 **Цены захардкожены** (строка 12-14)
  - `SINGLE_PRICE = 80`, `MULTI_PRICE = 700`, `BULK_PRICE = 3500` — не с бэкенда.
  - Если бэкенд изменит цены, фронт будет показывать устаревшие.

  - ×50 стоит 3500 Моры — крупная покупка, но нажатие кнопки сразу начинает ролл без подтверждения.
  - Случайный тап → мгновенная трата.

- 🔵 **Нет отображения текущего баланса** на экране Гачи
  - Пользователь не видит сколько у него Моры, пока не вернётся на Профиль.

- 🟢 **Free rolls** 
  - Бесплатные роллы отображаются отдельной кнопкой с отчётливым стилем.

## 🏦 Bank.tsx

### Общее
Вклады, новые депозиты, переводы, займы.

### Находки

- 🔴 **`window.confirm()` не работает в Telegram Mini App** (строка 204)
  - `window.confirm()` блокируется в WebView Telegram на iOS и некоторых Android.
  - Вызывается при досрочном закрытии вклада: `if (earlyMsg && !window.confirm(...)) return;`
  - Результат: пользователь не может закрыть вклад досрочно на iOS.

- 🟡 **Дублированная система тостов** (строка 29-30)
  - Bank.tsx реализует свою пару `toast`/`toastError` через `useState` + `setTimeout`.
  - При этом `ToastContext` уже существует глобально. Но Bank.tsx его не использует.

- 🟢 **Skeleton loading** — при загрузке данных банка.

- 🟢 **Вкладки** — чистые суб-табы (Вклады / Вложить / Перевод / Займы).

- 🟠 **Перевод: нет лимитов на UI** 
  - Можно ввести отрицательное число или 0 в поле суммы перевода (бэкенд проверит, но UI не предупредит).

## 💎 Shards.tsx

### Общее
Осколки и крафт. Показ стэша, каталог рецептов, массовый крафт.

### Находки

- 🔴 **Bulk Craft — N последовательных API-запросов** (строка ~60)
  - `doCraftBulk()` делает `for (let i = 0; i < maxCrafts; i++) { await craftShard(...) }` — если maxCrafts=20, это 20 последовательных HTTP-запросов.

  - При плохом соединении: timeout, частичный крафт без отката.

- 🟡 **Собственная toast-система** (строка 22)
  - `useState<{ msg: string; ok: boolean } | null>` — не ToastContext.

- 🟢 **Модалка с деталями** — при тапе на осколок показывается рецепт.

## 🗡️ BossFight.tsx

### Общее
Тактический соло-бой с боссом. ATB-система, стамина, QTE (Telegraph + Weak Spots). ~850+ строк.

### Находки

- 🔴 **5-6 параллельных `setInterval`** (строки 256, 265, 274, 304, 374)
  - Во время боя запущены: stamina regen, fight timer, boss auto-attack, telegraph warning, weak spot spawner, boss attack interval.
  - При unmount/переключении вкладки — потенциальные утечки памяти (хотя cleanup есть, race conditions вероятны).

- 🟠 **Stale closures** 
  - `useCallback`-обработчики атаки захватывают стейт на момент создания. При быстрых кликах стамина может не обновиться корректно.

- 🔴 **Нет timeout/guard** для боя > 120 сек (константа `BOSS_FIGHT_TIMEOUT_SECONDS = 120`)
  - Клиентский таймер может разойтись с серверным. Если бэкенд уже закрыл сессию, клиент продолжает бить.

- 🟡 **850+ строк в одном файле** 
  - Не разбит на подкомпоненты. Victory/Defeat/FightUI/Lobby — всё в одном.

- 🟢 **VictoryShards анимация** — красивые частицы при победе.

- 🔵 **Рекомендация**: разбить на BossLobby, BossFightUI, BossVictory, BossDefeat.

### api.ts

- 🟢 **Единый request()** — все запросы через одну обёртку с initData заголовком.
- 🟢 **Типобезопасность** — все функции типизированы.

- 🔴 **Нет AbortController** 
  - Ни один API-запрос не использует AbortController. При быстром переключении табов — race conditions.
  - Пример: пользователь открыл Bank → быстро переключил на Shop → ответ Bank обновляет стейт Shop.

- 🟡 **Нет retry-логики** 
  - При network error запрос просто фейлится. Нет автоматического retry.

- 🟡 **Нет rate-limiting на клиенте** 
  - Пользователь может спамить кнопками покупки, каждая отправляя запрос.

## 1. АРХИТЕКТУРНЫЕ ПРОБЛЕМЫ

### 1.1 🔴 Отсутствие роутинга — невозможность deep-link и Back-кнопки

**Файл**: `App.tsx`  
**Строки**: ~L60–L80

Вся навигация построена на `useState<Tab>`, без URL-маршрутов. Следствия:
- Кнопка «Назад» Telegram закрывает приложение вместо возврата на предыдущую вкладку
- Deep-links из бота (`startapp=XXX_profile`) парсятся в `useTelegram.ts`, но после перехода на другую вкладку и возврата — состояние теряется
- Невозможно поделиться ссылкой на конкретную вкладку
- При перезагрузке приложения всегда открывается вкладка по умолчанию

**Рекомендация**: Минимальный URL-hash router (`#/profile`, `#/gacha`) или Telegram BackButton API.

### 1.2 🟠 Toast-система фрагментирована — 3 разные реализации

| Реализация | Файлы |
|------------|-------|
| **ToastContext** (глобальный) | `ToastContext.tsx`, `Season.tsx`, `Quests.tsx` |
| **Локальный useToast хук** | `Casino.tsx` (собственный), `Talents.tsx`, `Stars.tsx` |
| **Локальный useState** | `Profile.tsx`, `Settings.tsx`, `Inventory.tsx`, `Shop.tsx`, `BossFight.tsx`, `CoupleBoss.tsx`, `Auction.tsx`, `Loans.tsx` |

**Проявления**:
- `ToastContext.tsx:L62–L69` — тосты отображаются сверху (`top: 12px`)
- `Casino.tsx:RouletteSection` — тост `fixed top-4 left-1/2` с другим стилем
- `Inventory.tsx` — тост `fixed top-4 left-1/2` с `border: 1px solid var(--accent)`
- `Auction.tsx` — тост на `bottom-20` (уникальное позиционирование)
- `Profile.tsx` — `setTimeout(() => setToast(null), 3000)` без cleanup на unmount

**Последствия**: Если пользователь быстро переключает вкладки, `setTimeout` в `Profile.tsx` может обновить state unmounted компонента. Визуально тосты прыгают между верхом и низом экрана.

**Рекомендация**: Перевести все страницы на `ToastContext`. Удалить локальные реализации.

### 1.3 🟠 Отсутствие AbortController на всех API-вызовах

**Файл**: `lib/api.ts` — функция `request()` L68–L80

Ни один `useEffect` с `fetch` не использует `AbortController`. При быстром переключении между вкладками:
- Запросы старых вкладок продолжают выполняться
- Результаты могут применяться к уже unmounted компонентам
- React выдаёт warning `Can't perform a React state update on an unmounted component` (удалён в React 18, но утечка памяти остаётся)

**Затронуты**: Все 23 страницы — каждая делает fetch в `useEffect` без abort.

### 1.4 🟡 Дублирование fetchUserData в Profile.tsx

**Файл**: `Profile.tsx` ~L30–L50

`Profile.tsx` самостоятельно вызывает `fetchUserData(chatId)` и хранит результат в локальном state, хотя `AppContext.tsx` уже предоставляет `userData` и `refreshUserData()`. Это приводит к:
- Двойному запросу при открытии профиля
- Рассинхронизации данных между Profile и глобальным контекстом

### 1.5 🟡 Два значка Gem для разных вкладок

Вкладки `Stars` и `Shards` обе используют иконку `Gem` из lucide-react. Пользователь не может визуально отличить их в навигационной панели.

### 32.2 🟡 ErrorBoundary отправляет stack trace на сервер

**Файл**: `App.tsx` — `ErrorBoundary`

Stack trace отправляется на `/api/frontend_error_log`. Убедиться, что в production stack traces не содержат чувствительных путей.

### 32.3 🟡 Нет sanitization пользовательского ввода в bio

Profile.tsx позволяет вводить bio без sanitization на клиенте. Если бэкенд не фильтрует — возможен stored XSS (React экранирует по умолчанию через JSX, но если bio используется как `dangerouslySetInnerHTML` где-то ещё — риск).
