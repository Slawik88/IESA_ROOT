# Аудит интерфейса сайта Домового — 2026-11-03

Полный разбор сайта (Telegram Mini App): дизайн, расположение элементов, удобство, доступность, тексты,
производительность, стек. Проверка велась на живом сайте с демо-данными: экраны сняты на 320 / 390 / 768 /
1280 px (владелец, жилец без прав, дом без данных, новичок без дома), плюс автозамеры (Playwright:
цели касания, размеры шрифтов, контраст, переполнения, имена для скринридера, вес и скорость загрузки).
Критерии — [`UI_REQUIREMENTS.md`](UI_REQUIREMENTS.md). **Статус работ: анализ и стандарт готовы, переработка
интерфейса начата, но не завершена (раздел «Что осталось»). Действующий интерфейс этой веткой не изменён.**

## Почему интерфейс «ужасный»: главные причины

1. **Слои CSS воюют друг с другом.** Основной стиль плюс блок «Midnight surfaces…» на 140 строк переопределяет
   его целиком; отсюда поломки ниже. За 2 ноября было 4 перерисовки поверх друг друга.
2. **Раздел «Дом» местами сломан**: переключатели прав стоят колонкой (квадрат над текстом по центру),
   в графике уборки имя жильца по центру над списком вместо строки (`label{flex-direction:column}` перебивает
   `.permission-row` / `.schedule-row`).
3. **Мелкий текст**: на главной 53 из 77 надписей мельче 13 px, в истории 74 из 105; минимум 10,5 px.
4. **Много спрятанного и обрезанного**: дата, категория и «недавнее» в форме — в аккордеонах; название дома в
   шапке «Квартира на Са…»; в записи автор режется («· Бо…»).
5. **Логика важного нарушена**: «Моя уборка» показывает самую старую просрочку, а сегодняшний день прячет
   за «Ещё дней: 2»; «Нужно подтвердить» спрятано в сворачиваемый блок.
6. **Несистемные элементы**: `window.confirm` (в Telegram выглядит чужеродно), нативный «Choose File / No file
   chosen» по-английски, текстовые «⌄ ‹ › ×» вместо значков, у каждой настройки своя кнопка «Сохранить».
7. **Нет «родного» вида в Telegram**: не заданы цвета шапки/фона/нижней панели, нет вибро-отклика, свайп-закрытие
   не отключается при вводе.

Что **в порядке** (замерено): контраст текста ≥ AA везде; цели касания ≥ 44 px везде; горизонтальной
прокрутки нет на 320/390/1280; консоль без ошибок; CLS = 0; 189 тестов и ruff зелёные; тёмная палитра и
локальный шрифт соответствуют решению владельца.

## Стек: оценка

FastAPI + ванильный JS без сборки + SQLite/PostgreSQL — подходит проекту (мало зависимостей, легко деплоить).
Узкие места не в выборе технологий, а в организации: монолитный `app.js`, два слоя CSS, отсутствие кэша статики,
шлюз Предвестника пересылает только `content-type`/`cache-control` (ни `ETag`, ни сжатия) — поэтому кэшировать
можно только версионированными адресами. Менять стек не нужно.

## Что сделано в этой ветке

- `docs/UI_REQUIREMENTS.md` — стандарт интерфейса и чек-лист приёмки (≈ 250 проверяемых пунктов).
- Бэкенд (обратно совместимо, 189 тестов зелёные): в ответах `/invite` поле `link` (ссылка на бота);
  `upcoming` (ближайшие дни уборки) в обзоре дома; `GET /v/<отпечаток>/…` — статика с `immutable`-кэшем;
  заголовки безопасности больше не затирают собственные; прежние короткие адреса файлов сохранены.
- Шрифт `fonts/onest.woff2` (32 КБ вместо 189 КБ; начертания 400–700, табличные цифры) — пока не подключён.
- Ядро нового фронтенда `web/static/js/`: `format.js`, `i18n.js` (ленивые переводы по языкам), `telegram.js`,
  `api.js` — пока не подключены.

## Рецепт стенда (временные скрипты жили вне репозитория и пропадут)

- Подпись входа: `hash = HMAC_SHA256(HMAC_SHA256("WebAppData", bot_token), "\n".join(sorted("k=v")))`, поля
  `auth_date`, `user` (JSON) — как в `tests/test_web.py::signed`.
- Запуск: `DOMOVOY_DATABASE_URL=sqlite://<файл> DOMOVOY_BOT_TOKEN=<тестовый>`, `web.app.create_app()` под uvicorn;
  демо-данные — через `services.households/money/cleaning` (дом, 3 жильца, взносы, траты, просрочки уборки).
- Страницу открывать с подменой `telegram-web-app.js` (скрипт с `initData` и заглушками `WebApp`).
- В общем venv нет `defusedxml` и `openpyxl` (они в `domovoy/requirements.txt`) — ставить отдельно.
- Playwright и Chromium уже есть (`.venv`, `%LOCALAPPDATA%\ms-playwright`).
