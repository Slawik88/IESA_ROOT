# Обмен денежными операциями

На сайте откройте «История» → «Файлы» (есть также кнопка под списком).
В боте сохранён раздел «Деньги и операции» → «Экспорт и импорт».
Excel/XLSX, CSV и TSV открываются в Excel / Google Sheets, JSON подходит для переноса.
PDF и банковские выписки произвольной структуры не поддерживаются.
Файл — до 2 МБ и 1000 операций. Для большей истории выгружайте отдельные месяцы.

В кабинете «Текущая выборка» выгружает **все** найденные операции с учётом поиска,
жильца, категории, оплаты и сортировки, включая записи за пределами видимой
страницы. Другие варианты — месяц без фильтров или вся история. На итогах
журнала считаются те же записи. В боте по-прежнему можно выбрать месяц / всю историю.

## Добавление прошлой операции

На сайте нажмите «Записать расход» или «Внести деньги» и раскройте строку даты.
В боте — «Трата» или «Внести деньги», затем «Дата»:
можно выбрать сегодня/вчера или написать `25.10.2026` либо `2026-10-25`.
У взноса есть отдельная кнопка «За какой месяц»: дата платежа и месяц учёта
могут отличаться. До нажатия «Сохранить» операция существует только как черновик.

## Импорт

1. Скачайте шаблон или экспорт. На сайте шаблоны и ID авторов находятся в «Загрузить из файла» → «Шаблоны и заполнение».
2. Заполните строки и пришлите файл боту. Человек должен уже состоять в доме;
   импорт не создаёт аккаунтов и не приглашает участников.
3. Проверьте число новых трат и взносов, дубли, ошибки и изменение общего котла.
4. Нажмите «Подтвердить импорт». Если есть ошибки, исправьте файл и загрузите снова:
   частичного импорта нет. При повторной загрузке уже записанные ключи пропускаются.

Право `import_transactions` позволяет переносить подтверждённые взносы и возвраты
как уже состоявшиеся операции. Владелец выдаёт его только тому, кто ведёт учёт.
Текущая настройка подтверждения новых взносов не изменяет статусы из файла.
При импорте исторических операций уведомления о каждой строке не рассылаются.

## Поля

| Поле | Значение |
|---|---|
| `source_key` | Постоянный уникальный ключ операции. Например `october:001`. Из экспорта не менять. Если пусто, вычисляется из содержимого; одинаковые записи без ключа считаются дублями. |
| `kind` | `expense` — трата; `contribution` — взнос. |
| `date` | День операции: `2026-10-25` или `25.10.2026`, не позднее сегодняшнего дня дома. |
| `month` | Месяц учёта: `2026-10`. Если пусто, месяц даты. Для траты обязан совпадать с датой; для взноса может отличаться. |
| `member_tg_id` | Telegram ID действующего участника целевого дома. |
| `member_name` | Справочное имя из экспорта; автор определяется по ID, не по имени. |
| `amount` | Положительная сумма в единицах валюты: `120.50`, `120,50`. В JSON задавать строкой, чтобы не терять копейки. |
| `category` | Категория траты, до 24 символов. Если отсутствует в доме, создаётся при подтверждении импорта. Можно оставить пустой. |
| `mode` | Для трат: `house` — из котла, `personal` — за свои. По умолчанию `house`. Для взноса пусто. |
| `status` | Для взносов: `declared`, `confirmed`, `rejected`. По умолчанию `confirmed`. У трат всегда `confirmed`. |
| `reimbursed` | `0` или `1`: личная трата возвращена из котла. Для взносов и трат из котла только `0`. |
| `description` | Описание траты до 200 символов. Для взносов пусто. |
| `currency` | Символ валюты дома. Если указан другой, импорт блокируется: конвертации нет. |

CSV: UTF-8 с BOM или без, разделитель `;` (поддерживается и `,`). TSV: UTF-8, табуляция.
Нужны как минимум колонки `kind`, `date`, `member_tg_id`, `amount`.
Значения со знаками формул в CSV/TSV защищены апострофом; обратный импорт снимает
защиту. Это не изменяет описания операций. Чеки и вложения в файлы не входят.

XLSX: скачайте шаблон Excel и заполняйте единственный лист «Операции». Названия
колонок совпадают с CSV. Суммы и Telegram ID в экспорте записаны текстом, чтобы
Excel не округлял значения. При чтении поддерживаются и обычные даты/суммы Excel;
длинный ID нужно оставить текстом. Формулы нужно заменить значениями. Книги с
паролем, макросами, дополнительными листами или превышенными размерами отклоняются.
Импорт проверяет всю книгу до записи; ошибки указывают номер строки на листе.

JSON:

```json
{
  "format": "domovoy-money",
  "version": 1,
  "transactions": [
    {
      "source_key": "october:001",
      "kind": "expense",
      "date": "2026-10-25",
      "member_tg_id": 100,
      "amount": "120.50",
      "category": "Продукты",
      "mode": "house",
      "description": "Молоко"
    }
  ]
}
```

Замените `100` на реальный ID жильца из окна импорта. Шаблоны пустые намеренно:
пока не заполнены, импортировать в них нечего. Другой формат JSON не распознаётся.

## Повторы и исправления

Ключ уникален внутри целевого дома. Совпадающий ключ и содержимое — пропуск.
Совпадающий ключ с изменённой суммой или другими полями — ошибка; импорт не
редактирует прежнюю запись. Новый ключ создаёт отдельную операцию и не отменяет
старую. Не используйте смену ключа как способ исправления уже проведённой траты.

Экспорт и обратный импорт в тот же дом не создают дубли. Файл другого дома можно
загрузить при условии, что все указанные авторы уже состоят в целевом доме.
Экспорт отражает состояние операций на момент выгрузки; фотографии чеков,
права и настройки дома им не переносятся. Это обмен операциями, а не резервная копия БД.

После ручного исправления или возврата экспорт содержит текущее состояние записи;
его обратный импорт в тот же дом считается дублем. Старый файл с прежней суммой /
статусом того же ключа получит конфликт, а не отменит изменение. Исходные контрольные
суммы запросов сохраняются отдельно от сравнения текущего содержимого: повтор
первоначальной отправки сайта не создаёт новую запись даже после правки.

## Валюта

По умолчанию используется CHF. Явно выбранная валюта дома сохраняется.
Конвертация не выполняется: файл другой валюты будет отклонён, а не переименован.
Изменение обозначения валюты дома не меняет сами суммы и старые ключи импорта.
