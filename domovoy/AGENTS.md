# Домовой — правила для агентов

**Проект:** Telegram-бот «Домовой» (@Domovskii_bot) — график уборки и Баланс
Квартиры. Мультидоменный: каждый дом — изолированное пространство со своими
людьми, графиком, деньгами и настройками. Замысел продукта: [`DESIGN.md`](DESIGN.md).

## Запуск и проверки

```bash
cd domovoy
python -m pip install -r requirements.txt          # runtime (aiogram 3, sqlite/pg)
python -m pip install -r requirements-dev.txt      # инструменты проверки
python -m pytest tests -q                          # тесты (обязательно перед коммитом)
python -m ruff check .                             # линтер (обязательно перед коммитом)
python -m bot                                      # локальный запуск; токен из .env
```

С 2026-11-13 production — Droplet `projects-fra1`, `104.248.46.216`:
служба `domovoy.service`, Python `/opt/iesa/venv311/bin/python` (3.11.14),
окружение `/etc/iesa/domovoy.env`. Служба отделена от `predvestnik.service`.
Старый общий контейнер App Platform удалён; `scripts/run_bots.sh` не использовать
для production. Git push не обновляет службу автоматически.

БД: на проде PostgreSQL через `DOMOVOY_DATABASE_URL`, локально — sqlite в `data/`.
Схема создаётся идемпотентно при старте. Loopback-БД `domovoy` на Droplet —
production: не направлять туда тесты и не подставлять её DSN в `.env.test`.

Закрытый кабинет Домового обслуживает `web/app.py` на loopback `127.0.0.1:8011`.
Он находится на домене/базовом пути Предвестника через отдельный gateway, но не
должен появляться в его UI, ссылках, OpenAPI, sitemap или публичных патч-нотах.
Вход формируется из `DOMOVOY_BOT_TOKEN`; существующий токен нужен также процессу
Предвестника для gateway. В production `DOMOVOY_WEB_BASE_URL` явно задан новым
независимым HTTPS-входом из документа хостинга. Старый fallback на IESA в коде —
не действующая конфигурация; переменную не убирать. Подписи и права проверяются
отдельно. Интеграция и ограничения описаны в `DESIGN.md`.

## Сайт: как смотреть и проверять

```bash
cd domovoy
python tools/demo_server.py            # демо-данные и эмуляция Telegram: http://127.0.0.1:8011/?u=1001 (&theme=light, &platform=android|tdesktop)
python tools/ui_check.py               # сценарии в браузере + аудит на разных размерах и языках (нужны playwright и chromium)
node --check web/static/js/main.js     # синтаксис каждого .js (то же для остальных файлов)
```

Интерфейс — ES-модули без сборки (`web/static/js/`), один `app.css`. Любой видимый текст — `t("русская строка")` и перевод в
`js/i18n/{uk,fr,de}.js` (тесты не пропустят строку без перевода). Текст ошибки сервера (`DomainError`, `AmountError`) переводится так же:
нет строки в трёх каталогах — падает `test_every_server_message_is_translated`. Никаких `window.confirm`, `innerHTML` с данными, `style=` в разметке,
текста мельче 13 px и целей касания меньше 44 px. Правка файлов в `web/static` сама меняет адрес статики (отпечаток содержимого).

## Слои и направление зависимостей

```
core/           ← константы, реестры прав и настроек, деньги. Не знает ни про бот, ни про БД
services/       ← вся логика: дома, права, график, деньги, уведомления, планировщик
infrastructure/ ← адаптер БД (sqlite/pg), схема, репозитории (только SQL)
bot/            ← тонкий адаптер Telegram: ввод/вывод, никаких правил
```

Зависимости направлены внутрь. Логика в обработчиках — ошибка слоя.

## Основа «гибкой настройки» — реестры

- [`core/settings_registry.py`](core/settings_registry.py) — настройки домов
  и персональных уведомлений. Новая настройка = одна запись в реестре: меню,
  валидация и хранение подхватываются сами.
- [`core/permissions.py`](core/permissions.py) — гранулы прав. Владелец имеет всё,
  остальным выдаёт владелец; новая механика = новая запись в реестре.
- Проверка прав — только через `services.households.can/require`, из бота напрямую
  роли не проверяются.

## Непреложное

- Деньги — целые копейки (`core/money.py`), float для валюты запрещён.
- Даты — строки `YYYY-MM-DD`; «сегодня» дома — `services.settings.house_today`
  (у дома свой часовой пояс, настройка `tz_offset_hours`).
- Напоминания отмечаются в `scheduler_log` — после рестарта ничего не уходит дважды.
- Локальные секреты — в `.env`, production — в `/etc/iesa/domovoy.env`;
  значения в гит и ответы не попадают.
- Скрытый супер-доступ разработчика: `DOMOVOY_SUPERADMIN_TG_IDS`, команды `/dev_*`;
  в пользовательских интерфейсах не афишировать.
