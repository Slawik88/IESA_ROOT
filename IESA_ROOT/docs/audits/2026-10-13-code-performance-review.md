# Ревью и оптимизация IESA — 13 октября 2026

Работа выполнена в Django-проекте `IESA_ROOT/`, поверх существующих
незакоммиченных изменений. `frontend/` и `predvestnik_v2/` не изменялись.
Изменения не опубликованы и не закоммичены.

## Исправления

| Участок | Проблема | Результат |
|---|---|---|
| Регистрация на событие | Результат `get_or_create` присваивался `_`, перекрывая функцию перевода; обе ветки сообщения вызывали ошибку | Отдельная переменная; тест первой и повторной регистрации |
| Активность пользователя | DatabaseCache при каждом запросе; `User.save` запускал сигналы, включая генерацию QR в Spaces | Без запросов для свежей активности; один условный UPDATE для устаревшей; защита от конкурентной перезаписи |
| Личный профиль | Загружались все объекты лайков и комментариев постов ради count | Независимые SQL-счётчики, один запрос для карточек с автором |
| Публичный профиль | Загружались неиспользуемые связи и все опубликованные посты автора | Без prefetch; пагинация, доступная по имени и номеру карты; черновики скрыты |
| Статистика визитов участника у партнёра | Три отдельных запроса count/sum/count | Один aggregate |
| Уведомления | Шаблоны, polling и SSE независимо считали непрочитанные | Общий сервис с существующим кэшем на 30 секунд и инвалидацией |
| SSE | Цикл мог заснуть до 60 секунд при заявленном лимите 50 секунд | Ожидание ограничено остатком времени; выход на границе лимита |
| Изображения/iframe | Новые HTMX-элементы не обрабатывались общим загрузчиком; наблюдатели создавались без элементов | Один переиспользуемый observer, WeakSet, очистка удаляемых узлов, fallback без IntersectionObserver |
| Изображения первого экрана | Глобальный скрипт назначал lazy даже видимым изображениям | Для видимых изображений без явно заданной стратегии используется eager |
| Community UI | Три новых observer на каждый settle; повторные таймеры countdown и анимации | Переиспользование observer, регистрация только новых элементов, очистка countdown при удалении |
| Частицы главной | RAF продолжался вне экрана; квадратный корень вычислялся для каждой пары | Остановка вне экрана и скрытой вкладки; sqrt только для близких пар |
| Подсветка поиска | Поиск внутри уже экранированного HTML портил entities и мог повторно подсвечивать вставленные теги | Один проход по исходному тексту, раздельное экранирование, без вложенных mark |
| Мобильная карточка блога | Пустая featured-обложка растягивалась примерно до 580 px | Высота 150 px, заголовок ближе к обложке |
| Галерея | Нестабильный порядок при одинаковом времени загрузки | Дополнительная сортировка по pk |
| Service worker | Обычные имена CSS/JS бессрочно брались из CacheStorage | Фоновое обновление обычных файлов; хешированные файлы используют кэш; версия v6 |
| Чистота кода | 34 неиспользуемых импорта, мёртвая предзагрузка, пустой PerformanceObserver, лишние переменные | Удалены; импорты регистрации сигналов и публичные экспорты сохранены |
| Статика | Три ссылки на отсутствующие sourcemap мешали строгой сборке | Удалены только комментарии sourceMappingURL для отсутствующих карт Leaflet/Bootstrap |

## Границы результатов

Проведены статический анализ Python и JavaScript, ревью основных путей Django,
проверка существующего набора тестов и выборочные браузерные проверки. Это не
доказательство отсутствия всех возможных дефектов каждой бизнес-функции.

Тесты выполнялись на изолированной SQLite. Production PostgreSQL, Spaces,
внешняя отправка почты/Telegram и поведение при реальной нагрузке не проверялись.
Общий процент ускорения сайта и полевые LCP/INP/CLS не измерялись. В локальной
галерее нет набора реальных фотографий для полноценной проверки просмотра.
Кэш уведомлений сохраняет прежнее окно актуальности до 30 секунд.

Существующий отчёт `2026-10-12-performance.md` описывает более ранние исправления;
его измерения не выдаются за результаты текущего прохода.
