# Оптимизация IESA — 12 октября 2026

Изменения выполнены локально в Django-проекте `IESA_ROOT/`. Существующие изменения
авторизации сохранены. `frontend/` и `predvestnik_v2/` не изменялись. На production
изменения не выкладывались.

## Результаты

| Участок | До | После |
|---|---|---|
| Прогретые секции главной, DatabaseCache | 7 чтений кэша | 1 запрос `get_many`, включая закэшированный `None` президента |
| Статистика админки | 25 запросов счётчиков | 7 агрегатов, по одному на таблицу |

| Карточки блога и результатов поиска | Дополнительные `.count()` на каждую карточку | Использование аннотированных счётчиков; автор в основном запросе |
| Рекомендованные посты | До 10 дополнительных запросов на 5 карточек | Счётчики в запросах рекомендаций |
| Комментарии HTMX | 4 запроса, загрузка объектов лайков | 2 запроса: комментарии с авторами/счётчиками + ответы с авторами |

| Статика без Spaces | Устаревший `STATICFILES_STORAGE` | `STORAGES`, совместимый с Django 5.2; хеширование и gzip |

Также добавлена инвалидация кэша главной при изменении/удалении Product. Поиск по
популярности теперь считает реальное количество лайков и комментариев: прежний
JOIN перемножал их и завышал показатель вовлечённости. Неиспользуемая предварительная
загрузка комментариев на странице поста удалена: страница получает их отдельным
HTMX-запросом.

пост, 50 лайков, 100 комментариев, 200 просмотров. Пять запусков каждого варианта,
материализация списка, проверка одинаковых счётчиков `(50, 100, 200)`.

- Прежний запрос: 1455.63, 1559.60, 1676.86, 1396.55, 1346.13 мс.
- Новый запрос: 6.35, 4.61, 4.97, 2.78, 6.18 мс.
- Медиана: **1455.63 → 4.97 мс**.

Это синтетическое измерение конкретного SQL-запроса; оно не является замером
ускорения всего сайта или прогнозом latency PostgreSQL в production.

Локальная копия `dev.sqlite3` приведена к существующим миграциям для проверки
в браузере; исходная `db.sqlite3` не изменялась. Галерея в локальной копии пустая,
поэтому открытие реальной фотографии не проверено. Production PostgreSQL,
нагрузочное тестирование и полевые Core Web Vitals не измерялись. Для оценки
пользовательского эффекта после развёртывания нужны замеры LCP/INP/CLS и latency
на реальных данных и устройствах. Персональные страницы не переводились на
общедоступное кэширование ради ускорения.
