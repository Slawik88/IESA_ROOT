# Предвестник — правила для агентов

**Проект:** Telegram-бот + FastAPI мини-приложение (игра). PostgreSQL, прод на DigitalOcean,
деплой автоматом из основной ветки репозитория. Подробности устройства — в коде и документации
проекта, здесь только то, что обязан знать каждый до первой правки.

## Обязательное чтение (любой агент, любой вендор)

| Когда | Документ |
|---|---|
| До первой правки кода | [`CLEAN_CODE.md`](CLEAN_CODE.md) — единый стандарт кода: принципы, дисциплина слоёв, анти-мусорный регламент, git-гигиена, Definition of Done |
| До завершения любой задачи | [`AUTONOMOUS_AGENT_POLICY.md`](AUTONOMOUS_AGENT_POLICY.md) — как доказать, что изменение работает: матрица отказов, сквозная проверка |
| В автономном режиме | [`AUTONOMOUS_MODE.md`](AUTONOMOUS_MODE.md) — протокол самостоятельного цикла работа → проверка → ревью |
| Если изменение видно игроку | [`docs/PATCH_NOTES.md`](docs/PATCH_NOTES.md) — патч-нот в официальный канал обязателен |
| Если пишешь или правишь **любой текст для игрока** (подсказка, «Как играть», справка, Путеводитель, описание дара или награды, ответ бота) | [`docs/PLAYER_COPY.md`](docs/PLAYER_COPY.md) — как переводить на понятный язык: читатель-новичок, правило «ноль вопросов», блоки вместо простыни, таблица замен терминов |
| Если задача — часть **дорожной карты по сессиям** (стабильность, Путеводители, админка, дизайн, косметика, чат-бот; номера S01–S25 и S23a) | [`docs/roadmap/README.md`](docs/roadmap/README.md) — правила конвейера, журнал `STATUS.md`, готовые промпты `sessions/`, окружение `ENV.md`. Журнал обновляет каждая такая сессия |

Эти документы не заменяют друг друга: CLEAN_CODE отвечает «каким должен быть код и чего
в репозитории нет», POLICY — «как доказать работоспособность». Один без другого не работает.

## Слои и направление зависимостей

```
core/           ← константы, реестры, чистые определения. Не знает ни про бот, ни про веб
services/       ← бизнес-логика игры. Не знает, кто её вызывает
infrastructure/ ← доступ к данным (SQL в репозиториях)
bot/, FastAPI/  ← адаптеры: Telegram и веб. Тонкие, делегируют логику сервисам
```

Правило одной стрелкой: **зависимости направлены внутрь.** Сервис, который импортирует
адаптер, — ошибка слоя; адаптер, в котором живёт бизнес-логика, — та же ошибка с другой
стороны. Бот и сайт — два окна в одну систему: правило, работающее для денег, предметов
и прав, реализовано один раз в общем слое.

## Факты проекта — где искать

Факты (цены, лимиты, механики, команды) живут в коде: константах, реестрах и сервисных
функциях. Документация проекта описывает их для человека, но источником истины является
код. Прежде чем предполагать — посмотри в код; прежде чем править поведение — сверься
с документацией и обнови её в том же коммите.
