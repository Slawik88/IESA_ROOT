# Predvestnik v2 — правила работы агента

## Старт сессии

Прочитать только этот файл, `.codex/CURRENT_STATE.md` и `.codex/MEMORY_INDEX.md`.
Затем один раз проверить
`git status --short`. Не читать всю историю, весь репозиторий или все Markdown-
файлы. Сначала искать через `rg`, затем читать минимальный диапазон строк.

## Архитектурные границы

```text
core/           константы и реестры, без внешних зависимостей
services/       бизнес-логика, без bot.* и FastAPI.*
infrastructure/ SQL и repositories
bot/            Telegram-адаптер
FastAPI/        Web/API-адаптер
```

Не трогать старый `frontend/`, корень `IESA_ROOT/` и несвязанные пользовательские
изменения. Перед правкой файла проверить его текущий `git diff`.

## Маршрутизация документации

Читать документы только при совпадении с задачей:

```text
UI/UX              PRODUCT.md, DESIGN.md
Reconstruction     GAME_RECONSTRUCTION_3_0.md, BATTLE_VFX_CONCEPT.md
экономика          ECONOMY_LEDGER_CONTRACT.md
косметика          COSMETICS_COLLECTION_DESIGN_RULES.md,
                   COSMETICS_LIFECYCLE_POLICY.md
release             PRODUCTION_RELEASE_CHECKLIST.md
очередь             docs/audits/AUTONOMOUS_RELEASE_BACKLOG.md
автономный режим   AUTONOMOUS_MODE.md, AUTONOMOUS_AGENT_POLICY.md
общая архитектура   BASE_PROMPT.md
подробная тема      соответствующий файл ai_knowledge/
```

Большие документы читать по найденному заголовку и диапазону строк. Полное
чтение разрешено только если без него невозможно проверить контракт.

## Рабочий цикл

1. Сформулировать одну текущую гипотезу и список конкретных файлов.
2. Выполнить узкий поиск `rg` и прочитать только связанные фрагменты.
3. Для маленькой задачи: изменить → запустить точечную проверку.
4. Для cross-stack/экономики/migration/release: прочитать нужный контракт,
   проверить цепочку `UI/бот → API → права → service → SQL → cache/cron`,
   затем выполнить соответствующий verify-gate.
5. Не пересказывать уже известный контекст; фиксировать новые факты только в
   `.codex/CURRENT_STATE.md` или релевантном файле из `.codex/MEMORY_INDEX.md`.

Полный автономный режим и обязательная read-only критика субагентом сохраняются
для задач, к которым они применимы. Не запускать этот режим механически для
локального текстового или очевидного bugfix-изменения.

## Инструменты и вывод

Ограничивать вывод команд (`rg -m`, диапазоны строк, `Select-Object -First`).
Не печатать большие логи, полные файлы и повторный diff без изменений.
После правки проверять только затронутые файлы, `git diff --check` и релевантные
тесты.

## Завершение и handoff

Перед завершением незакрытой работы обновить `.codex/CURRENT_STATE.md`: цель,
доказанную причину, изменённые файлы, проверки, риски и один следующий шаг.
После завершённой задачи удалить устаревшие пункты из состояния.
