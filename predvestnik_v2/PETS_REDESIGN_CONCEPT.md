# ПИТОМЦЫ 2.0 — редизайн вкладки под язык Казармы (СОГЛАСОВАНО 2026-07-09)

> Источник: разговор с пользователем 2026-07-09 — понравилось, как выглядит и
> работает Казарма боевых юнитов (Боёвка 3.0), запрошено адаптировать тот же
> визуальный/интеракционный язык под мирных питомцев. Дизайн согласован по
> частям в диалоге (5 раундов вопросов), ниже — итоговая спека для реализации.
> Второй запрошенный проект (анимации по всему сайту) — отдельная спека,
> делается ПОСЛЕ этой (см. `NOT_IMPLEMENTED.md`).

## 0. Что не меняется (сознательно вне скоупа)

- **Бестиарий** — отдельная вкладка, справочник по видам, не трогаем.
- **Бэкенд/API** — вся текущая логика (`FastAPI/routers/zoo.py`,
  `infrastructure/repositories/zoo.py`, `services/zoo.py`) остаётся как есть.
  Это чисто фронтенд-редизайн существующих данных, никаких новых полей/
  эндпоинтов не требуется — все нужные данные (`placement`, `fatigue`,
  `pet_level`, `duplicates_collected`, `max_slots`, `bought_slots`,
  `vip_extra_slot`, `at_slot_cap`, `slot_next_price`) уже отдаются `/zoo/`.
- **Особые виджеты видов** (Хомяк-копилка/Волк-отдых/Единорог-иммунитет,
  лаунчер похода) — логика и API-вызовы не меняются, только визуальная
  подгонка карточек-баннеров под общий стиль (без структурных изменений).
- **Действия внутри карточки питомца** (кормёжка, применение предметов,
  перемещение между слотами) — вся функциональность сохраняется 1:1, меняется
  только вёрстка/оформление модалки.

## 1. Структура вкладки

Было: 3 вкладки («Мои питомцы» = актив+пассив, «Склад», «Бестиарий»).
Стало: **2 вкладки** («Мои питомцы» = единый экран, «Бестиарий» без изменений).
«Склад» как отдельная вкладка исчезает — все питомцы видны в одном гриде
ниже слотов (см. §3), с бейджем места, если стоит в слоте.

Порядок сверху вниз на «Мои питомцы»:
1. Полоска активного похода (`zoo-exp-wrap`) — без изменений.
2. **Слоты** (§2).
3. Виджеты вида (Хомяк/Волк/Единорог) — без изменений в логике, только
   визуально подгоняются под общий стиль карточек (`--r` радиус, `--border2`,
   уже используются — просто следим за консистентностью после переверстки
   остального).
4. **Ростер** — грид всех питомцев (§3).

## 2. Слоты

Аналог `bk-slot`/`bk-squad` из Казармы (`app.11.js`/`app.css`), но с поправкой
на асимметрию активный/пассивный (у питомцев активный слот всегда ровно один
и даёт полный бонус вида, пассивные — несколько и бонус слабее — это НЕ то же
самое, что фронт/фланг/тыл у юнитов, которые все играют разными правилами
позиционирования, но статы одинаковы).

- **Активный** — один крупный слот-герой над рядом пассивных (шире и заметнее,
  не часть общего ряда). Пусто → плейсхолдер «➕ Выбрать активного». Занято →
  эмодзи вида + имя + `Ур.X/10` + тонкая полоска усталости.
- **Пассивные** — ряд компактных слотов (`bk-slot`-размер), по одному на
  каждый слот из `max_slots + vip_extra_slot` (за вычетом активного).
  Пустой слот в пределах открытых — плейсхолдер «➕». Слот сверх открытых —
  не рисуется (открывается кнопкой ниже).
- **Кнопка «Купить слот»** — переезжает из отдельного блока-счётчика (текущий
  `occupied/totalSlots` header) прямо под ряд пассивных слотов: `🛒 Купить
  слот за N💎` либо `🔒 Слоты докуплены (X/max)` если `at_slot_cap`. Мелкая
  подпись под кнопкой — то, что раньше было в header (базовых/докуплено/VIP),
  одной строкой.
- **Тап по слоту** (пустому или занятому) → тот же пикер, что сейчас
  открывается для выбора питомца в слот (переиспользуем текущий `doMove`-флоу,
  просто дергаем его из нового UI-входа вместо старой кнопки «Переместить»
  внутри модалки — модалка «Переместить» тоже остаётся доступной, дублирование
  входов не проблема, тот же паттерн что у Казармы: тап по слоту ИЛИ кнопка
  внутри карточки).

## 3. Ростер (грид)

Показывает **всех** питомцев игрока (активный/пассивные/склад) — как в
Казарме, где грид юнитов показывает и тех, кто уже в отряде (с бейджем
слота). Сортировка: сначала занятые слотом (активный → пассивные по порядку),
потом склад — внутри каждой группы по убыванию редкости, затем уровня.

**Карточка** (аналог `bk-card`, новый CSS-блок `.zc-card` переиспользующий
паттерн `bk-*`, НЕ копипаста стилей — общие правила `.bk-card`/`.zc-card`
выносятся в один шаред-класс, разница только в контенте):
- Эмодзи вида (крупно) + имя + `Ур.X/10`.
- **Тонкая полоска усталости внизу карточки** (тот же `.fat-bar`/`.fat-fill`
  что и сейчас, просто уменьшенная высота под компактный грид) — пользователь
  явно попросил видеть её прямо в гриде, а не только в деталях.
- Бейдж «⚔️ Активный» / «🛡 Пассивный N» в углу карточки, если питомец в
  слоте (аналог `bk-insq`).
- Тап по карточке → модалка деталей (§4).

Список потенциально длинный (в отличие от Казармы с жёстким потолком в 16
юнитов, питомцев может быть много — каждая крутка гачи создаёт отдельную
запись). Пагинации/фильтров не добавляем (YAGNI, нигде в проекте длинные
списки так не фильтруются) — просто скроллящийся грид, как везде в приложении.

## 4. Модалка деталей питомца

Вся текущая функциональность `openPetModal()` сохраняется без потерь:
шапка (имя/редкость/слот-бейдж/описание вида), статы (уровень/дубликаты/
усталость), текущие бонусы, полная таблица всех 10 уровней с
diff-подсветкой новых бафов, кормёжка, применение предметов
(`renderPetItems`), перемещение между слотами.

Меняется только **визуальный язык**: сейчас это чисто инлайн-стили
(`style="..."` россыпью), переводим на классы в духе Казармы —
`.bk-info-head`-подобная шапка (стихия/роль/редкость/уровень одной строкой
чипами) → аналог для питомца (вид/редкость/слот/уровень чипами), рамка
модалки по редкости (`r-{rarity}`, уже есть паттерн, используется в Казарме
и косметике). Функционально — 1:1 то же самое.

## 5. Анимации (первая порция — остальное сайт-вайд отдельной спекой)

- Карточка ростера — лёгкое появление (fade+scale, мягче чем `chestPop`) при
  первом рендере грида.
- Питомец «влетает» в слот при перемещении (короткий transition карточки).
- Обе анимации — чистый CSS (`transition`/`@keyframes`), без JS-таймеров.
- Уважают существующую инфраструктуру: `body.no-fx` и `@media
  (prefers-reduced-motion: reduce)` полностью отключают (`animation: none`/
  `transition: none`) — эти конкретные анимации достаточно лёгкие, чтобы не
  нужен был отдельный «упрощённый, но не нулевой» промежуточный режим (в
  отличие от сайт-вайд спеки анимаций, где это будет отдельным решением per
  анимация).
