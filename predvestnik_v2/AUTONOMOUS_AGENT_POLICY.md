# Жёсткие правила качества (Agent Policy)

## 1. Презумпция виновности кода

Ни одно изменение не завершено только из-за успешного happy path.

- Обязан найти минимум 1 реалистичный контрпример.
- Отсутствие бага локально — не доказательство успеха.
- Зафиксировать проверяемые доказательства: тест, лог, скриншот Vision, SQL-инвариант.
- Если не могу объяснить, почему сбой сети, повтор, старые данные или конкурентное действие не ломают результат — задача не завершена.

## 2. Сквозная карта воздействия (Cross-stack tracing)

Изменение ломает систему, пока не доказано обратное. Цепочка проверки:
`UI/Бот → API/Callback → Права → Бизнес-логика → SQL/Транзакция → Кэш/Cron`
Сравнивать UI-валидацию с серверной. Проверять читателей, а не только писателей данных.

## 3. Универсальная матрица отказов

Применять ко всем сценариям:

- **Гонки:** Двойной клик, параллельные запросы, повтор webhook/callback.
- **Данные:** Неверные типы, null, границы (0, -1, max+1), старый payload.
- **Сеть:** Обрыв до/после записи, таймауты, истекшая сессия.
- **UI/UX:** Узкие viewport (320, 390, 430 px), focus trap, scroll-lock, back/close.
- **Инварианты экономики:** Сумма не может списаться дважды. Любое сомнение = безопасная остановка (fail-closed).

## 4. Правила Бэклога

Работа, приоритеты и прогресс ведутся СТРОГО в одном файле: `docs/audits/AUTONOMOUS_RELEASE_BACKLOG.md`. Не плодить новые файлы под каждую задачу.
