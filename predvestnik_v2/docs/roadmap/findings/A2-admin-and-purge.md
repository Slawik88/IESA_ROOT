# A2 · Админка и «Чистка» (исследование 2026-10-27)

Пути — от `predvestnik_v2/`. Номера строк на 27.10.2026: сверять с текущим кодом.

## Поправки к первоначальным предположениям

- **«Чистка» — это не удаление сообщений.** Это чистка неактивных участников по норме сообщений. Бот закрывает чат, по одному удаляет сообщения тех, кому писать
  нельзя (`bot/chat/purge.py:435-456`), шлёт досье по одному и принимает решения forgive/warn/mute/kick/ban. Массового `deleteMessages` нет; единственный
  `delete_messages` — в `services/patch_notes_send.py:77`.
- **Админка — отдельное SPA `/bot-admin`**, а не экраны в `app.NN.js`. Файлы: `FastAPI/static/bot-admin/` (`admin.js` 2424 строки, `admin-lists.js`, `admin.css`).
  Роутеры: `FastAPI/routers/bot_admin/*.py`. Сервисы: `services/admin_*.py`. Богаче, чем кажется: массовые действия, заметки, журнал, подтверждения.
- Процесс на проде и пул — см. `A1-stability-performance.md`.

## «Чистка»: где и почему лагает

Где: бот `bot/chat/purge.py`; веб `FastAPI/routers/purge_v1.py`; workflow `services/purge.py`; SQL `infrastructure/repositories/purge_sessions.py`; UI `FastAPI/static/app.07.js:17-205`.

Причины «огромного пинга» (по убыванию вероятности):
1. **Троттлер исходящих бьёт по всем методам с `chat_id`** (`bot/middlewares/outbound_throttle.py:38,101-105`). Слот 1.05 с применяется и к `getChatMember`, и к `deleteMessage`,
   и к `banChatMember`, хотя лимит 1/с относится только к `send*`. Слот резервируется необратимо: отмена `wait_for` его не освобождает. Веб-поллинг каждые 2 с
   (`app.07.js:34`) делает 1 `getChatMember` на запрос (`purge.py:506`). Решение делает 3 `getChatMember` (`:506,508,530`) плюс 1–2 вызова санкции: минимум 4–5 с, а
   `wait_for(8)` на проверку прав (`:490`) отдаёт 503 «Проверка прав затянулась». В тот же слот чата конкурируют: досье (`probe` + `sleep(0.4)`, `:279,297`), удаление каждого
   сообщения в закрытом чате (`:446`), `member_tags.backfill_task` (`services/member_tags.py:307-318`), `screen_violators` в боте (8 параллельных вызовов в один слот, за 40 с
   проверяется ~38 человек, `services/chat_bots.py:22-24`).
2. **Соединение БД держится на время ожидания Telegram.** Веб-хендлеры: `purge_v1.py:61,73` через `get_db`. Транзакция с advisory-lock держится на время Telegram-вызова
   до 40 с (`services/purge.py:95-106`). Хендлеры бота ждут троттлера, держа соединение. При ~8 доступных соединениях несколько зависших «чисток» останавливают весь
   Mini App и бота.
3. **Досье рассылаются через `asyncio.create_task` без сохранения ссылки** (`purge.py:353`, `purge_v1.py:93`). Деплой убивает рассылку насовсем; `unsent_targets()`
   (`purge_sessions.py:131`) нигде не вызывается; прогресса «отправлено N из M» в UI нет.
4. **Тяжёлый SQL в HTTP-запросе `start`.** `find_violators` (`purge.py:145-192`) считает по каждому участнику три коррелированных подзапроса. Для `moderation_logs` по
   `(chat_id,user_id,action)` есть только индекс `(chat_id,action)` (`bot/core/database.py:1316`). Запрос идёт под `statement_timeout` 30 с.
5. **`loadPurgeEntry`** (`app.01.js:649`, `app.07.js:54`) вызывается при каждом открытии «Ещё» у каждого игрока. Выполняет `COUNT` и подзапрос по `user_chat_stats` на каждый чат
   (`infrastructure/repositories/moderation_chats.py`).
6. Поллинг каждые 2 с вместо push, хотя WS-шина `notify` уже есть.

### Архитектурное исправление (для S03 и S05)

- **Троттлер:** ограничивать только `send*/edit*/forward/copy`; не резервировать слот для отменённых вызовов; приоритет «санкции/админка» над обычными ответами.
- **Права:** кэш `getChatMember` на 30–60 с для `(chat, actor)`; для решений — один `getChatMember(target)` плюс кэш прав бота.
- **Соединения:** паттерн A13 из `/profile/avatar`: короткая транзакция reserve → commit, Telegram-вызов вне соединения, короткая транзакция set_verdict. Состояние
  `sending/unknown` уже durable.
- **Фоновая очередь:** воркер по образцу `services/broadcasts.run`: durable-таргеты, возобновление при старте, flush порциями; отправляет досье и исполняет массовые санкции.
- **Прогресс:** `counts` плюс ревизия или ETag; WS-событие `data_changed{scope:'purge'}` через `notify`, поллинг 10–15 с только как запасной.
- **Удаление сообщений:** буфер по чату 300–500 мс и `bot.delete_messages(chat_id, ids[≤100])`.
- **SQL:** индексы `moderation_logs(chat_id,user_id,action,created_at)`, `(user_id)`, `(created_at)`; `start` отдаёт 202 + job id, подсчёт нарушителей идёт в воркере.
- **Общее:** отдельный пул или семафор для фоновых задач и `acquire(timeout=...)`.
