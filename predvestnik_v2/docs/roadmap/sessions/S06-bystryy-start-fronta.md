# S06 · Быстрый запуск фронта: CSS/JS, ленивые образы

**Блок A** · **Зависит от:** S01 (замеры холодного старта) · **Нужен «ок»:** нет, если вид не меняется (проверяется попиксельно) · Выкатка в master после проверок.

> **Промпт:** Выполни сессию S06 из `predvestnik_v2/docs/roadmap/sessions/S06-bystryy-start-fronta.md`. Начни с протокола старта из `predvestnik_v2/docs/roadmap/README.md`.

## Цель

Mini App открывается медленно и «подвисает» при старте: 55 блокирующих CSS (1.5 МБ), JS 1.15 МБ без минификации, GZip уровня 9 на каждый запрос внутри цикла событий, а после каждого деплоя все клиенты качают всё заново. Сократить время холодного старта и убрать работу из
горячего пути, **не меняя вид**. Контекст: `findings/A1-stability-performance.md` (п. 5), `findings/D-cosmetics.md` («Технические ограничения»).

## Границы

**Делаем:**
1. **Замер «до».** `python tools/ui_smoke.py --perf --device mid` и `--device low`, холодный старт в Playwright с троттлингом сети/процессора (Slow 4G, 4× CPU): время до первого содержимого, до интерактивности, переданные байты. Сохранить цифры в журнал.
2. **Ленивые CSS образов.** `skin-scene-{a..g}-v3.css` (≈830 КБ, 211 картинок) грузятся всем (`FastAPI/static/index.html:19-72`). Грузить только CSS надетого образа и тех, что открыты в «Образах» (подгрузка по требованию при открытии витрины/превью). Образ по умолчанию не тянет сцены вовсе.
   Не ломать: тема `app_tokens`, публичные карточки (чужой образ у VIP), топы, подарочные карточки, `skin-runtime-v3.js` игровых страниц.
3. **Критичный CSS.** Остальные CSS не блокируют первую отрисовку (`media="print"`-приём или объединение/разделение по экранам); не создать мерцание неподстилизованного контента (FOUC): проверить скриншотами до/после.
4. **JS.** Минификация (безопасная, без переименования глобалов, на которые ссылаются inline-обработчики/`_GV_GO`), список частей `_APP_JS_PARTS` (`FastAPI/main.py:499`) сохранить как источник; по возможности `defer`.
5. **Сжатие.** Прекомпрессия gzip/brotli при старте процесса (или при сборке) вместо GZip уровня 9 на каждый запрос (`FastAPI/main.py:309-325`); корректные `Vary`, `Content-Encoding`, `ETag`, `Cache-Control: immutable` для версионируемых файлов.
6. **`updates.json`** (234 КБ, `main.py:623`): ETag/304, отдача сжатой версии.
7. **Мёртвый `admin-legacy.css`** (478 строк, грузится всем, `index.html:20`; экранов уже нет): убрать подключение и обновить `FastAPI/main.py:502` и контракт-тест `tools/test_shell_v3_contract.py:226`.
8. **Хэш версии.** Сейчас любой деплой меняет `?v=` у **всех** файлов: версионировать каждый файл своим хэшем содержимого, чтобы деплой не обнулял кэш клиентов для неизменённых файлов.

**Не делаем:** редизайн, перерисовку образов (S17–S20), смену шрифтов (кроме `preconnect`/`display=swap`, если безопасно), серверные запросы к БД.

## Критерии готовности

- Холодный старт и байты в журнале «до/после» (цель: объём критичного пути минимум вдвое меньше; если нет — объяснить почему).
- Игрок с образом по умолчанию не загружает CSS сцен.
- Скриншоты экранов и образов совпадают до/после (кроме явно объяснённых).
- После пробного «деплоя» (смена одного файла) браузер перекачивает только его (проверка по заголовкам/хэшам в тесте).
- `admin-legacy.css` не подключается, тесты обновлены.

### Остаток

- **S06b — неблокирующие стили экранов** (сделано 2026-10-28, ждёт «ок», итог ниже): 21 файл стилей экранов, которые не нужны первой отрисовке (Мафия, задания, инвентарь, сундуки, тропа, Путеводитель, новости, пропуск, магазин, питомцы, казино, биржа и др.), грузить без блокировки. Проба на стенде: первая отрисовка 7,3 → 5,4 с, профиль 9,6 → 8,1 с. Нужны «ворота»: заставка и переход по ссылке из чата ждут, пока стили догрузятся, иначе на медленной сети мелькнёт неоформленный экран (окна поверх заставки). Это меняет поведение запуска — делать с проверкой снимками на медленной сети.
- `defer` для скриптов не ставился: `app.js` и так в конце страницы, а `defer` меняет порядок относительно встроенных обработчиков — выигрыша почти нет.
- Brotli не сделан: на проде нет пакета `brotli` (корневой `requirements.txt` общий с сайтом); gzip заранее даёт основной выигрыш по процессору.
- Шрифты уже подключены неблокирующе с `preconnect` и `display=swap` — не трогались.
