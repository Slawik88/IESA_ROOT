# S25 · Итоговая проверка и закрытие журнала

**Зависит от:** все остальные сессии (или решение владельца закрыть конвейер без части) · **Нужен «ок» владельца:** нет, кроме выводов · Выкатка: только документы и, возможно, мелкие исправления найденного.

> **Промпт:** Выполни сессию S25 из `predvestnik_v2/docs/roadmap/sessions/S25-itog.md`. Начни с протокола старта из `predvestnik_v2/docs/roadmap/README.md`.

## Цель

Убедиться, что весь конвейер действительно дал результат, который просил владелец: стабильность «на все 100%», быстрый сайт «без микрофризов», понятный Путеводитель, удобная админка и экраны, достойная косметика, работающие функции бота. Закрыть журнал честным списком: что сделано, что нет, что дальше.

## Границы

**Делаем:**
1. **Сверка журнала:** `STATUS.md` против `git log`: каждая сессия `готово` подтверждена коммитами и проверками; строки `SNNb` и «Находки по пути» собраны в один список остатка с приоритетами; «Нужны решения владельца» — какие приняты, какие нет.
2. **Замеры «до/после»** по данным S01 (таблица агрегатов): лаг цикла, ожидание пула, p95 по маршрутам, 401 по причинам, клиентские ошибки, время холодного старта (S06), число запросов Мафии/«Чистки»/профиля. Если на проде данных за достаточный срок нет — запросить цифры у владельца, а не придумывать.
3. **Сквозная проверка:** полный `ui_smoke.py --crawl --strict --widths 320,390,430` (включая админку после S11 и Мафию после S15), `--perf --device mid|low`, `tools/verify_production_http.py` на проде, основные Python/Node тесты областей; сценарий новичка «от `/start` до первого действия» с Путеводителем (Playwright, касания).
4. **Проверка требований владельца пунктами 1–9** (его слова — в `OWNER_REQUEST.md`): по каждому пункту «выполнено / частично / нет» с доказательством (ссылка на снимок, тест, цифру).
5. **Документация:** актуализировать `CLAUDE.md`/`AGENTS.md` ссылки на `docs/roadmap/`; в `docs/agent/` и `predvestnik_v2/docs/` убрать устаревшее, что конвейер сделал неверным; обновить `docs/PATCH_NOTES.md`/`PLAYER_COPY.md` только при изменении правил.
6. **CI и регрессии (предложение владельцу):** сейчас тесты при пуше в master не запускаются, а пуш = деплой (`.github/workflows/build-frontend.yml` относится к старой папке `frontend/`). Предложить минимальный CI (быстрые контрактные тесты + линт дизайна из S13) с оценкой стоимости; **не внедрять без «ок»**.
7. **Следующий цикл:** сформировать список следующих сессий (S26+) из остатка, по тому же шаблону.

**Не делаем:** новые крупные функции.

## Входные данные

`STATUS.md`, все файлы `sessions/` (раздел «Итог»), `findings/`, таблицы метрик S01 из админки (владелец приносит), `git log`.

## Шаги

1. Протокол старта; сверка журнала.
2. Замеры; запросить у владельца цифры, если надо.
3. Сквозные тесты и проверка пунктов 1–9.
4. Документация и список следующего цикла; журнальный коммит в master.

## Критерии готовности

- В журнале нет сессий в статусе `ждёт ок` без ответа владельца (или они явно перенесены); все строки `SNNb` либо выполнены, либо вынесены в следующий цикл.
- Таблица требований владельца 1–9 с честными статусами и доказательствами.
- Замеры «до/после» заполнены или помечены «нет данных: запросить».
- Список следующего цикла и предложение по CI в журнале.
