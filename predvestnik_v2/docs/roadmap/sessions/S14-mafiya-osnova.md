## Цель

Владелец: «мафия онлайн сделана как полуигровой документ офисный». Перед новым видом (S15) нужен фундамент: сервер должен отдавать данные для «стола игроков» (аватар, образ, регалии), состояние должно приходить по push, а не опросом раз в 2–10 с, и «Назад» не должна ломаться.
Контекст: `findings/C-design-and-mafia.md`, раздел «Мафия онлайн».

## Границы

**Делаем:**
1. **Данные игрока в payload** (`services/mafia_online_views.py:50`): расширить `{id,name,seat,…}` полями, нужными столу: публичный образ (`look`: id образа и тир, как в публичных карточках), аватар (с учётом правила видимости), регалии (если есть), признак «онлайн», «бот/человек». **Правило видимости: образ и аватар игрока показываются, только если у этого игрока активен VIP** (`services/appearance_public_v3.py`; решение владельца 2026-10-27 «только VIP» распространено на Мафию) — сохранить; остальным базовый вид и инициал/созвездие. **Скрытые роли и ночная информация не должны утекать**: добавить тест на редакцию (`redactions`) для каждого нового поля.
2. **Push вместо опроса:** использовать существующий WebSocket-канал (`FastAPI/static/app.01.js`, `FastAPI/notifications.py` шина `notify`): события `mafia_room_changed{room_id, version}` по изменению версии комнаты; клиент (`app.55.js:100 moPoll`) подгружает состояние по событию, опрос остаётся запасным с редкой частотой (15–30 с) и при потере соединения. Серверные циклы
   опроса (`services/scheduler.py:171-189`, `mafia_online_scheduler.py:31`) перевести на ожидание по ближайшему сроку, если безопасно (согласовать с S03, не дублировать).
3. **Нормализация клиентского кода** `app.55.js`/`app.56.js` (`app.56.js` — 239 строк, средняя длина 246 символов, максимум 3580): разбить на читаемые функции **без смены поведения**, по стилю соседнего кода и `CLEAN_CODE.md`; это нужно, чтобы S15 мог безопасно править вид.
4. **«Назад» и модалки** (поведение навигации: если оно меняет видимое поведение, выделить в ветку и строку `S14v`, иначе выкатить): `navBack()` должен закрывать открытую Мафию/листы, а не переключать страницу под ней (риск из разведки; проверить в браузере Playwright и описать, что нельзя проверить без Telegram).
5. **Игровые события для анимаций** (S15): единый список событий (смена фазы, раскрытие роли, голос, смерть, победа) в payload или отдельным полем, чтобы вид не выводил их из состояния (в журнале релиза `ONLINE-MAFIA-UX-20261025` такие события уже есть: переиспользовать).
6. **Данные для фаз:** для каждой фазы (`lobby/night/discussion/voting/paused/finished`) явные поля, чтобы вид не угадывал (время начала, длительность, чья очередь).

**Не делаем:** вид, цвета, арты, компоновку (S15); правила игры, баланс, награды; Telegram-адаптеры локальной Мафии (`bot/chat/mafia*.py`).

## Критерии готовности

- Число HTTP-запросов комнаты в минуту уменьшилось (замер до/после, цель −80%) при сохранении задержки обновления ≤1 с.
- Новые поля не раскрывают скрытые роли ни одной стороне (тест на все роли и фазы, включая выбывших и ночной совет).
- Поведение комнаты не изменилось: все существующие `test_mafia_online_*` зелёные без правки ожиданий (кроме добавленных полей).
- Читаемость клиента: максимальная длина строки в `app.55/56.js` разумная (проверка линтером/скриптом), логика разбита на функции.

### Что сделано

- Участники: пакетная публичная проекция `look/avatar/avatar_state/mark/level/is_bot`.
  Образ и фото только при действующем VIP владельца, без исключения «вижу себя»;
  без VIP — базовый вид и уровень для созвездия. Публичная регалия — как в Топе.
  Нет Telegram внутри запроса; отказ оформления изолирован savepoint, стол работает.
- `phase_state` — явные начало, длительность, срок, остаток, исходный этап паузы,
  тип очереди и собственная возможность хода. `paused_at` записывается при новой
  паузе; у старой начало/длительность null. `events[]` строится **из разрешённого
  снимка**, со стабильными id и без чужих проверок/ролей. Существующий `moEventFor`
  переиспользован; это факты для S15, а не журнал каждого перехода.
- PostgreSQL отправляет `mafia_room_changed{room_id,version}` через прежний WS-мост
  только после COMMIT. Данные игры в сигнал не попадают; сообщение будит только
  допущенных к его разговору, даже без изменения версии. Heartbeat молчит; финал
  получает список участников из состояния, а не из уже освобождённых мест.
- Клиент объединяет серию событий за 100 мс, не теряет событие во время GET,
  после восстановления WS перечитывает комнату, сразу дочитывает страницы по 80
  сообщений. Опрос раз в 20–30 с остаётся страховкой и обновлением присутствия.
- Цикл онлайн-Мафии ждёт ближайшего срока и отдельного LISTEN; при обрыве
  переподключается, без LISTEN использует 2 с, страховочный проход — 30 с.
  Локальная Telegram-Мафия и её scheduler не менялись. Ревью нашло третий direct:
  резерв исправлен до выпуска, default по-прежнему всего 10 (7 пул + 3 прямых).
- `app.55/56.js` разобраны на читаемые блоки и строки не длиннее 336 символов.
  Внешняя AST-сверка подтверждает неизменность выражений и каждого символа HTML
  вне отдельно проверенных функций обновления/остановки и одобренной прокрутки.
- `navBack` уже закрывал Мафию, не переключая страницу под ней; runtime навигации
  не менялся. Браузер проверяет настоящий callback, Escape вложенного листа,
  сохранение стека страницы и черновика. Нативный клиент Telegram не проверен.
- «Что нового» скрыто до включения `game_mafia_online`, патч-нот дня с `cover`
  подготовлен. Выключатель не менялся, в канал ничего не отправлено.

### Проверки и контрпримеры

Базовая линия снята на свежем origin/master. PG-наборы и Node-регрессии зелёные:
включая 34 полные партии (425 этапов, 1443 хода на базовой линии) и 15 партий аудита.
Первый запуск окружения остановился из-за Linux-only `env-setup.sh`; вместо него
поднята отдельная Windows PG17/ICU/UTC на 55414, выполнены миграция браков и
`bootstrap_test_db.py`. Общая база использует только тестовые аккаунты.

Старый браузерный стенд не знал `v3CurIn`/навигационных зависимостей общей `OM`,
а селектор меню сообщения находил две кнопки: стенд догнан до настоящих компонентов,
ожидания игры не ослаблялись. После этого прежний `test_mafia_online_ui.py` зелёный.
Отдельный дефект прокрутки воспроизведён и с исходными `app.55/56` в отдельном
внешнем каталоге: полоса события уменьшала высоту разговора на 73 px **после**
установки прокрутки. Исправление выделено как S14v и одобрено владельцем.

Проверены все `test_mafia_online_*` (17 наборов), в том числе:

- `foundation`: 134 сочетания ролей, этапов, живого/выбывшего и доступного канала;
  перестановка неизвестных ролей не меняет новые публичные поля; отдельный тест
  VIP/истёкшего VIP, фото, регалии, уровня и признака бота.
- `live.cjs`: 3 чтения за первую минуту вместо 30 у исходного poller (−90 %),
  серия сигналов объединяется; событие при том же version, гонка GET, готовность
  WS и устаревшая комната. Это виртуальные часы с исполнением настоящего poller.
- `live_pg`: тайный чат будит только команду, повтор и rollback не будят никого,
  heartbeat не создаёт цикл, финал доставляется после удаления мест; новая/
  укороченная дата будит пустой цикл (~0,33 с), LISTEN восстанавливается.
- `live_ui`: настоящие PG → production LISTEN/WS → настоящий `connectWS/moLive`

  черновик/фокус, восстановление пропущенного сообщения, Escape и «Назад».
- `audit_ui`: 782 проверки, 90 состояний на 320/390/430 и коротких экранах;
