# S17 · Образы: общие детали и тиры D–C (убрать «шаблонность»)

**Блок D** · **Зависит от:** S16 (стенд, концепты, список примитивов) · **Нужен «ок» владельца:** да · Ветка `feat/roadmap-S17-skins-base`.

> **Промпт:** Выполни сессию S17 из `predvestnik_v2/docs/roadmap/sessions/S17-obrazy-obshchee-D-C.md`. Начни с протокола старта из `predvestnik_v2/docs/roadmap/README.md`.

## Цель

Две общие проблемы, которые чинятся один раз для многих образов: (1) простые фигуры там, где нужны настоящие формы (многоугольные лепестки и круглые цветки вместо цветов; ромбы вместо звёзд); (2) на тирах D–C все не-личные образы выглядят как шаблон «цветное пятно + кольцо + 6 частиц + ник», то есть игрок
платит за образ, а видит различие только после дорогих тиров. Контекст: `findings/D-cosmetics.md` («Тиры: что меняется, что нет», «Два конкретных случая»), `findings/D2-cosmetics-audit.md` (список примитивов и концепты из S16).

## Границы

**Делаем:**
1. **Библиотека общих примитивов** (по списку S16): лепесток с выемкой, 5-лепестковый цветок, лист с прожилкой, снежинка, язык пламени, звезда с вогнутыми лучами, искра, волна, капля, перо… в трёх формах использования и **одним источником формы**:
   - SVG для сцен: `tools/scene_kit.py:31-37` (полигоны `d_poly`/`poly`) и `tools/scene_art_{a..g}.py`; ориентир лучшей отрисовки — `scene_art_c.py:264-341` (`PETAL`, `#f`, `sakura_branch`) и цветок кроны `#ornCBlossom` в `FastAPI/static/app.34.js:10`;
   - CSS-маски частиц: `FastAPI/static/appearance-stage-v3.css:58-81` (`petal` как прямоугольник с `border-radius`, искры как маска-восьмиугольник `--m-spark`);
   - Telegram-карточка: `bot/chat/skin_card_draw.py:76-99` (лепесток `petal`/`leaf` — `d.polygon` из 4 точек, искры — 8-конечный полигон): рисовать кривыми Безье и **с суперсэмплингом** (в 3–4× и уменьшение), а не полигонами.
2. **Различимость на D–C.** По концептам S16: у каждого образа свой видимый «характер» уже на D и C — собственный набор частиц (не только цвет), собственный элемент сцены, «намёк» на фирменную деталь (уменьшенный фрагмент `sig`, который сейчас появляется только на тире `sig_from`). Не смещать **цены, тиры и состав сетов**: это только отрисовка. Если для «намёка» нужно
   менять правило «деталь с тира X» (`core/skins_v3.py::signature_tier`) — это решение владельца: сначала показать на стенде.
3. **Бюджеты движения** (`tools/ui_smoke_checks.py` BUDGET anims ≤95, passes ≤14, area ≤24, bmf ≤24; `tools/test_skin_scenes.py`: до 24 слоёв, до 15 движущихся без `w2`): запрещены `filter` на предке движущегося, polygon `clip-path`, `mix-blend-mode`. Замер `ui_smoke.py --perf --device mid|low` до/после; не ухудшить.
4. **Размер ассетов.** Новые SVG запекаются в `skin-scene-*-v3.css` (`python tools/scene_art.py`, проверка `--check`); следить за приростом (после S06 CSS образов ленивые: новые файлы подключать тем же способом); цель — прирост ≤10% на образ.
5. **Telegram-карточки** (`bot/chat/skin_card_draw.py`, `core/skins_v3_chat*.py`): те же формы; время ≤0.9 с на картинку (кэш декора на пару образ+тир не сломать); SSS-видео (`skin_motion.py`) в бюджет 3 с.
6. **Откатываемость:** id, названия, тексты, цены не трогать; прежние классы остаются, пока новые не заменили их во всех местах.

**Не делаем:** отдельные образы «целиком» (S18–S20 — по индивидуальным концептам), тир/цены/id, интерфейс вне образов.

## Критерии готовности

- Многоугольников и круглых «цветков» в общих примитивах не осталось (автопроверка на форму в тесте: например, поиск `polygon`/`d_poly` в местах лепестков).
- На стенде D и C у любых двух образов, не относящихся к одному набору, **визуально различимы** без подписи (самопроверка по снимкам, список в журнале).
- Бюджеты и тесты зелёные; вес и скорость карточки в пределах.
- Владелец принял «после» (`ок`).
