## Цель

Владелец: «сделать анализ по косметике, детализировать детали, сделать элементы более продуманными: сейчас простые фигуры (цветочки сакуры — просто многоугольники); образ „Бездна“ очень странный: только палитра напоминает бездну. **По каждой косметике я хочу видеть стенд „до / после“ на каждый тир прокачки**
(не обязательно менять каждый тир каждого образа — только там, где уместно). Пройтись по КАЖДОЙ косметике. Возможно, лучше обыграть ник, аватарку, интерфейс сайта». Figma не используется. Контекст: `findings/D-cosmetics.md` (инвентарь, таблица 42 образов с оценками, «Два конкретных случая», тема интерфейса, ограничения).

## Границы

**Делаем:**
1. **Базовая линия «до».** Зафиксировать коммит кода образов (`git rev-parse origin/master` на старте, записать в журнал и в `findings/D-cosmetics.md`). «До» всегда строится из этого коммита через `git worktree` (хранить гигабайты снимков в git не нужно).
2. **Стенд.** Основа: `seed/nodb-render/` (без БД: профильная сцена любого образа и тира; 42 образа проверены) + `tools/ui_skin_lab.py --ladder` (с БД: профиль, кадры движения, `--device mid|low`, `--phase`). Собрать **страницу-сравнение**: строка = образ, колонки = тиры D…SSS, каждая ячейка = «до | после» (слайдер-шторка или пара),
   подсветка тиров, где есть изменение; режимы: профиль, ник и титул крупно, топ-строка, Telegram-карточка (`bot/chat/skin_card_draw.py`, Pillow), слабый телефон (`ap-lite`/`ap-low`), `reduced-motion`; фильтры по набору/редкости/оценке. Скрипт сравнения двух ревизий (`PIL.ImageChops`, процент отличий на ячейку) добавить в `tools/` (его сейчас нет;
   `pdiff`/`stagecap` из `docs/DESIGN_SESSION_BRIEF.md` лежали в `/tmp` и утеряны). Публикация: приватный Artifact (HTML + изображения, ≤16 МБ; сжимать WebP), чтобы владелец смотрел с телефона; если Artifact недоступен — сжатые снимки в папке ветки и ссылка на страницу в `findings/`.
3. **Аудит всех 42 образов** по таблице из `findings/D-cosmetics.md`: перепроверить оценки на текущем коде, добавить критерии: читаемость на D–C, уникальность от соседей по набору, использование общих примитивов, вес ассетов, соответствие названию/описанию (blurb). Результат: `findings/D2-cosmetics-audit.md`.
4. **Концепт каждого образа** (короткая карточка в том же файле): что именно нарисовано плохо (с путём и строкой), что предлагается нарисовать (конкретные детали: например, цветок сакуры — 5 лепестков с выемкой и тычинками, а не круг), **что меняется на каких тирах** (таблица D…SSS: «без изменений / добавляется X / заменяется Y»), как обыгрываются ник, титул, аватарка/рамка, фон профиля, строка в топе,
   Telegram-карточка и интерфейс (только токены/эффекты, без смены геометрии и порядка: гейты дизайна). Особое внимание: Ханами и сакура-набор, «Бездна» (воронка должна читаться с тира D, а не только с S), слабые (оценка ≤3). Для не-слабых образов — короткое «оставить / лёгкая доводка».
5. **Список общих примитивов**, которые нужно перерисовать один раз для многих образов (лепесток, цветок, лист, снежинка, язык пламени, звезда, искра, волна…) с местами использования (`tools/scene_kit.py`, `tools/scene_art_*.py`, `appearance-stage-v3.css` маски, `bot/chat/skin_card_draw.py`, `app.35–38,48,53.js`) — вход для S17.
6. **План S17–S20** обновить по реальным цифрам аудита (какие образы в какой сессии, бюджет движения и веса).
7. **Актуализировать устаревшие доки** `docs/SKINS_V3.md` и `docs/SKINS_CHAT_DESIGN_HANDOFF.md` (28 постоянных + 12 сезонных + 2 личных; 3 сезона) в том же коммите.

**Не делаем:** перерисовку образов (S17–S20), смену тиров, цен, id, правил владения.
