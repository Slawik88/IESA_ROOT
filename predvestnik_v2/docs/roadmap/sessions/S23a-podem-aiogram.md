# S23a · Подъём aiogram: 3.22.0 → новейшая проверенная версия

**Блок E (чат-бот)** · **Зависит от:** S01 (метрики и алерты: видеть ошибки после подъёма) · **Нужен «ок» владельца:** нет (решение владельца 2026-10-27: «обновляй!»), но **проверку прода делает владелец** · Отдельный коммит и **отдельный пуш в master** (затрагивает общий `requirements.txt`; в этом пуше также журнал и релизная запись, правило «один пуш на единицу работы»).

> **Промпт:** Выполни сессию S23a из `predvestnik_v2/docs/roadmap/sessions/S23a-podem-aiogram.md`. Начни с протокола старта из `predvestnik_v2/docs/roadmap/README.md`.

## Цель

Темы в личных чатах с ботом (`User.has_topics_enabled`, Bot API 9.3) появляются только с **aiogram 3.24.0**; в проекте стоит **3.22.0 (Bot API 9.2)** (`requirements.txt`). На 27.10.2026 новейшая на PyPI — **3.31.0 (Bot API 10.3)**. Поднять версию так, чтобы бот работал **ровно как раньше**, а S23 мог строить темы в личке.
Это самая рискованная сессия по зависимостям: девять минорных версий. Контекст: `findings/E-bot-dm-ship-article.md` (раздел 1, факты о библиотеке).

## Границы

**Делаем:**
1. **Выбор версии.** Проверить на PyPI актуальную (`pip index versions aiogram`). Цель: новейшая стабильная, у которой проходят все тесты; при несовместимости — самая новая из тех, где всё зелёное (минимум 3.24.0 для тем). Пин точный (`aiogram==X.Y.Z`), как сейчас.
2. **Разбор изменений.** Прочитать список изменений каждой версии между 3.22.0 и целевой (GitHub-релизы/`CHANGES` пакета; `core.telegram.org` из облака недоступен, PyPI доступен). Выписать **ломающие изменения** и всё, что касается используемого проектом: `Bot`, `Dispatcher`, роутеры, `types.*`, `FSM`, `ChatMemberUpdated`, `Message` (`business_connection_id`, `message_thread_id`), клавиатуры, `ReplyParameters`/`reply_to_message_id`, `allowed_updates`, `Bot.session`/таймауты/прокси, `parse_mode`/`DefaultBotProperties`, `CallbackQuery`, `web_app` кнопки, платежи Stars (`LabeledPrice`, `successful_payment`), `delete_messages`, `get_chat_member`.
3. **Поиск использований.** `grep` по `bot/`, `services/`, `FastAPI/`, `infrastructure/`, `tools/` на все эти символы; для каждого сверить сигнатуру в новой версии (скрипт-сверка по исходникам пакета, `python -I`, без запуска бота).
4. **Подъём и совместимость.** Изменить строку aiogram в корневом `requirements.txt` (и зависимые пины `pydantic`, `aiohttp`, `magic-filter` и др. по требованию пакета); **`requirements.txt` общий с сайтом IESA**: сайт aiogram не использует, но деплой пересобирает оба компонента → отдельный коммит, дифф только эти строки; перед пушем убедиться, что установка из `requirements.txt` на **Python 3.12** (как на проде, `runtime.txt`) проходит (`env-setup.sh` ставит подмножество; полную сверку зависимостей сделать `pip install --dry-run -r requirements.txt` для строк бота).
5. **Исправить только необходимое** для совместимости (устаревшие аргументы, переименования); **никаких** новых возможностей (темы и Business — S23/S24), никакой переделки.

**Не делаем:** темы в личке, Business, новые функции (S23, S24); смену других библиотек; рефакторинг.

## Шаги

0. **Имитация Telegram как страховка подъёма** (решение владельца 2026-10-27: реального Telegram и Premium нет, проверяем на имитации). В репозитории **уже есть** симулятор `tools/mafia_sim/` (`world.py`: `World` и `FakeSession(BaseSession)`, которая прогоняет вызовы через настоящий парсинг ответов aiogram; сейчас реализовано **9 методов** (`GetMe`, `SendMessage`, `SendPhoto`, `EditMessageText`, `EditMessageReplyMarkup`, `DeleteMessage`, `SendChatAction`, `AnswerCallbackQuery`, `GetChatMember`), остальные нужно добавлять; `harness.py`: `Harness` подаёт обновления в **настоящий `Dispatcher`** с роутерами и middlewares через `feed_update`: `say`, `edit`, `click`, темы `topic`, сбои `world.fail(...)`, `tick`).
   Использовать его как основу, **не переписывать**: добавить недостающее в `World` (методы `_m_...` для вызовов, которые используют бот и S23/S24 и которых нет: платежи Stars (`SendInvoice`, `AnswerPreCheckoutQuery`, `successful_payment`), `CopyMessage`/`SendMediaGroup`/`SendAnimation` при использовании, управление темами `CreateForumTopic` и пр., `GetBusinessConnection`, отправка с `business_connection_id`, обновления `business_connection`/`business_message`/`edited_business_message`/`deleted_business_messages` в `Harness`). Тесты Мафии (`test_mafia_*sim*`) остаются зелёными. **Ограничение симулятора:** `Harness` (`assert_dev_dsn`, `tools/mafia_sim/harness.py:13-22`) работает только с loopback-базой с именем **`predvestnik_preprod`** (общая база из `env-setup.sh`, а не `--fresh-db ИМЯ`); сценарии чистят за собой (`cleanup`).
   Набор сценариев `tools/test_bot_scenarios_sim_pg.py`: `/start` и глубокие ссылки, 15–20 основных команд (баланс, топ, я, профиль, варпы, игры, питомцы), кнопки-колбэки (идемпотентность двойного тапа), платёж Stars (успех и отмена), `my_chat_member` (бота добавили и выгнали), сообщения в темах, `Forbidden: bot was blocked` и лимиты (`TgError(429)`). **Прогнать набор на 3.22.0 (базовая линия) и на целевой версии: результаты сценариев должны быть идентичны.** Именно это заменяет проверку подъёма в реальном Telegram. Сценарии нужны и S23, S24: оформить как общий инструмент.
1. Протокол старта. **Базовая линия до подъёма:** запустить **все** тесты бота и PG (список: `ls tools | grep -E "^test_"`), записать результаты по файлам (`ENV.md`: часть тестов в облаке раньше не запускалась; тесты, красные уже на чистом `master`, записать и не считать результатом подъёма; известный красный: `test_current_game_docs.py`). Для массового прогона написать скрипт-обёртку в scratchpad (не в репозиторий), который запускает каждый тест с таймаутом и пишет сводку.
2. Разбор изменений (п. 2–3) → список рисков в «Итог».
3. Подъём версии в отдельной ветке; повторный прогон **всех** тестов; сравнение с базовой линией: **ни одного нового красного**.
4. Для каждого нового красного/предупреждения: исправление по п. 5 или откат на более старую версию из диапазона.
5. Сквозные проверки: запуск бота с моковым токеном до этапа подключения (`python -c "import bot.__main__"` без сети), импорт всех модулей `bot/`, `FastAPI` приложение стартует в `ui_smoke.py`/`ui_stand.py` (в нём бот-мост реальный), `test_chat_bot_pg.py` на свежей базе, платёжные пути Stars (тесты `payments`).
6. **Независимый read-only аудит** (определение в `README.md`): субагент проверяет дифф `requirements.txt` и исправления совместимости, ищет использование удалённых/изменённых API.

После пуша владелец проверяет прод **четырьмя пунктами**: в DigitalOcean деплой `Healthy`; `/api/health` и `/api/ready` отвечают; Mini App открывается; **пишет боту в Telegram `/start` и «баланс» и видит ответ** (меняется именно библиотека бота). Первый час после деплоя смотрит экран «Состояние» (ошибки бота) — если появились ошибки, откат: `git revert` + пуш (по его просьбе).

## Критерии готовности

- Версия aiogram поднята до целевой (не ниже 3.24.0), пин точный.
- **Ни одного нового красного теста** относительно базовой линии; список известных красных до/после совпадает; **сценарии имитации Telegram (`tools/test_bot_scenarios_sim_pg.py`) дают идентичный результат на 3.22.0 и на целевой версии**.
- Все `bot/` модули импортируются; приложение стартует; нет новых предупреждений об устаревших API (`-W error::DeprecationWarning` для импорта `bot` — результат в журнал).
- Аудит без блокирующих замечаний; список ломающих изменений и принятых мер в «Итог».
- Темы в личке и Business доступны для S23/S24 (проверка наличия `User.has_topics_enabled` и событий `business_*` в установленной версии).
