# Конвейер сессий «Предвестника»

Большой план работ владельца разрезан на **25 самостоятельных сессий** (`sessions/S01…S25`). Одна сессия = один
кусок работы, который можно довести до конца за один заход. Новая сессия стартует с чистого листа и узнаёт всё
из этой папки. Источник правды о ходе работ — [`STATUS.md`](STATUS.md).

## Универсальный стартовый промпт (его владелец вставляет в новую сессию)

> Ты рабочая сессия проекта «Предвестник» (папка `predvestnik_v2/`). Открой `predvestnik_v2/docs/roadmap/README.md`
> и действуй по нему: возьми первую по порядку сессию со статусом «не начата» (или ту, что я назову), прочитай её
> файл и выполни до конца. Журнал обновляй сама.

Короткий вариант с номером: «Выполни сессию S05 из `predvestnik_v2/docs/roadmap/sessions/`».

## Что где лежит

| Файл | Зачем |
|---|---|
| `STATUS.md` | Журнал: таблица сессий, «ждут ок владельца», «находки по пути», «нужны решения владельца» |
| `ENV.md` | Как поднять окружение в облачной сессии и чем проверять |
| `sessions/SNN-….md` | Готовый промпт одной сессии: цель, границы, входные данные, шаги, критерии готовности, проверки |
| `findings/*.md` | Результаты исследования кода от 27.10.2026 с путями и строками. Не переисследовать заново, а **сверять с текущим кодом**: строки могли сдвинуться |
| `seed/nodb-render/` | Заготовка стенда образов без базы данных (для S16) |

## Протокол старта (обязательно, по порядку)

1. Прочитать `CLAUDE.md` в корне репозитория и `predvestnik_v2/AGENTS.md`, дальше по его таблице:
   `CLEAN_CODE.md`, `AUTONOMOUS_AGENT_POLICY.md`; если сессия трогает тексты для игрока — `docs/PLAYER_COPY.md`;
   если видна игроку — `docs/PATCH_NOTES.md`; если визуальная — `docs/MINIAPP_DESIGN_RULES.md`.
2. Прочитать `STATUS.md`, свой файл `sessions/SNN-….md` и `findings/`, на которые он ссылается.
3. Проверить зависимости сессии: все должны быть в статусе `готово`. Нет — остановиться и сообщить владельцу, какая сессия нужна
   раньше (или честно взять только независимую часть).
4. Сверить журнал с реальностью: `git log --oneline -30 -- predvestnik_v2` и прочитать «Итог» зависимостей.
5. Поставить в `STATUS.md` статус `в работе` и сделать журнальный коммит в master (см. «Выкатка»).
6. Поднять окружение по `ENV.md`.

## Правила работы

- Работать **только** внутри `predvestnik_v2/`. Сайт IESA (Django) не трогать. Один коммит — один проект (`CLAUDE.md`, правило 1).
- Держаться границ своей сессии. Нашлось постороннее (баг, мусор, идея) — записать строкой в раздел «Находки по пути» в `STATUS.md`
  и **не чинить**.
- Нужно решение владельца (деньги, цены, данные игроков, правила, видимость чужого контента, новая механика) — записать строкой в
  «Нужны решения владельца» и **продолжить с безопасным дефолтом**: функция за выключенным флагом или минимальный вариант. Не гадать и не
  блокироваться.
- Секреты: ключи, токены, DSN прода не печатать и не коммитить.
- Чужие незакоммиченные изменения не трогать. Работать в чистой ветке от `origin/master` (`CLAUDE.md`, правило 4).
- Файлы большого размера (`app.NN.js` и др.) могли править сразу два ИИ (Claude и Codex): перед правкой смотреть `git log -p` по файлу.
- Тексты для игрока, подсказки, Путеводитель и ответы бота пишутся по `docs/PLAYER_COPY.md` (читатель-новичок, «ты», «ноль вопросов»).
- Новая механика = новая тема Путеводителя **в том же коммите**. Заметное игроку обновление = патч-нот дня и скриншот
  (`docs/PATCH_NOTES.md`).
- Тиры, цены и id образов не менять (решение владельца). Нужно — вопрос в «Нужны решения».
- Figma не используется: внешний вид согласуется через стенд «до/после» (S16) или скриншоты.

## Выкатка (master = прод, деплой автоматический)

| Что | Куда | Когда |
|---|---|---|
| Журнальный коммит (`STATUS.md`, файл сессии, `findings/`) | **всегда в master** | сразу, чтобы следующая сессия его увидела |
| Не-визуальный код (сервер, бот, тесты, измерения) | master | после прохождения проверок сессии и `AUTONOMOUS_AGENT_POLICY.md`; затем проверить, что деплой стал Healthy |
| Визуальный код (экраны, образы, меню, Мафия) | ветка `feat/roadmap-SNN-<тема>` | сразу, но в master **только после «ок» владельца** |

Визуальная сессия заканчивается так: код на ветке, стенд или скриншоты показаны владельцу, статус в `STATUS.md` = `ждёт ок`.
Владелец отвечает «ок» **в этой же сессии** (одна короткая реплика). Тогда сессия: перебазирует ветку на актуальный `origin/master`,
повторяет проверки, вливает в master (fast-forward, без `--force`), проверяет деплой, ставит `готово`. Если владелец написал замечания,
сессия их выполняет и снова ждёт «ок».

Порядок проверки прода после пуша: `/api/health` и `/api/ready` отвечают, деплой в DigitalOcean `Healthy`, в Runtime Logs нет ошибок старта.
Сломалось — немедленный откат (`git revert` + пуш) и сообщение владельцу. Каждый пуш в master перезапускает бота и сайт на секунды,
поэтому выкатку пакетируют: один пуш на сессию, а не на каждый коммит.

Опасное: миграции и индексы только безопасные (`CREATE INDEX CONCURRENTLY`, без удаления данных); для рискованных денежных операций и миграций —
PostgreSQL-гейт и независимый read-only аудит по `AUTONOMOUS_AGENT_POLICY.md`. Флаги Spot/Shorts биржи и любые экономические переключатели
сессии сами не включают.

## Протокол финиша (обязательно)

1. Все проверки из файла сессии зелёные. Красное — не коммитить «на потом».
2. Дописать в файле сессии раздел **«Итог»**: что сделано (с коммитами), что проверено и как, что осталось, что обнаружено.
3. Обновить строку сессии в `STATUS.md`: статус, дата, коммиты/ветка, одна строка «сделано», одна строка «осталось».
   Остаток, который не уместился, — отдельной строкой в «Находки по пути» или в файл следующей подходящей сессии (с пометкой «перенесено из SNN»).
4. Если из-за сессии изменился факт, описанный в документации, — обновить документ в том же коммите (`CLAUDE.md`, «Если документ устарел»).
5. Коммит-сообщения по правилам репозитория: `тип(predvestnik): суть` (`feat`, `fix`, `docs`, `test`, `chore`), в конце отдельной строкой `Roadmap: SNN` (так сессию находит `git log --grep "Roadmap: S05"`), затем атрибуция, которую требует среда. Журнальный коммит в master.
6. Кратко отчитаться владельцу по-русски: что сделано, что дальше, нужны ли от него «ок» или данные.

## Статусы сессии

`не начата` → `в работе` → `ждёт ок` (визуал на ветке) → `готово`. Либо `частично` (остаток записан и перенесён).

## Общие проверки (сверять с файлом сессии)

- Сервер/бот: тесты области (`BOT_TOKEN=1:x PYTHONPATH=. python tools/test_<имя>.py`; PG-тесты с `--dsn`), см. `ENV.md`.
- Экран: `python tools/ui_smoke.py --only <экран> --widths 320,390,430`, а при движении `--perf --device mid`.
- Тексты игроку: `tools/test_player_copy_contract.py`, `node tools/test_guide_navigation.js`.
- Патч-ноты: `tools/audit_release_whatsnew.py` и правила `docs/PATCH_NOTES.md`.
- Перед любым пушем в master: нет секретов, нет посторонних файлов, ветка на актуальном `origin/master`.
