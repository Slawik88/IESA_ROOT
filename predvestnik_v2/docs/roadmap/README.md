# Конвейер сессий «Предвестника»

Большой план работ владельца разрезан на **25 самостоятельных сессий** (`sessions/S01…S25`). Одна сессия = один кусок работы, который можно довести до конца за один заход. Новая сессия стартует с чистого листа и узнаёт всё из этой папки.
Источник правды о ходе работ — [`STATUS.md`](STATUS.md). Конвейер рассчитан на **одну сессию за раз**: владелец ждёт, пока она закончит, и открывает следующую (параллельный запуск — только для сессий из разных блоков, см. «Правила работы»).

## Стартовые промпты (владелец вставляет один из них в новую сессию)

**Обычный** (сессия сама выбирает следующую):
> Ты рабочая сессия проекта «Предвестник» (папка `predvestnik_v2/`). Открой `predvestnik_v2/docs/roadmap/README.md` и действуй по нему: возьми следующую сессию по правилу «Выбор сессии», прочитай её файл и выполни до конца. Журнал обновляй сама.

**Конкретная:** «Выполни сессию S05 из `predvestnik_v2/docs/roadmap/sessions/`. Начни с `predvestnik_v2/docs/roadmap/README.md`.»

**Влить одобренное** (визуальная сессия ждёт «ок», а владелец согласовал, но та сессия уже закрыта): «Владелец одобрил S05: влей её ветку по разделу «Режим: влить одобренное» из `predvestnik_v2/docs/roadmap/README.md`.»
Если владелец одобрил с замечаниями, он пишет их в этом же сообщении.

## Что где лежит

| Файл | Зачем |
|---|---|
| `OWNER_REQUEST.md` | Требования владельца (9 пунктов, его слова), принятые решения и таблица «пункт → сессии». Сверяйся, когда нужно понять намерение |
| `STATUS.md` | Журнал: порядок, таблица сессий, «ждут ок», «ждёт подтверждения прода», «нужны решения владельца», «находки по пути» |
| `ENV.md`, `env-setup.sh` | Как поднять окружение в облачной сессии и чем проверять (одна команда) |
| `sessions/SNN-….md` | Готовый промпт одной сессии: цель, границы, входные данные, шаги, критерии готовности, проверки |
| `findings/*.md` | Результаты исследования кода от 2026-10-27 с путями и строками. Не переисследовать заново, а **сверять с текущим кодом** (строки могли сдвинуться) |
| `seed/nodb-render/` | Заготовка стенда образов без базы данных (для S16) |

## Выбор сессии

1. Прочитать `STATUS.md`: строка «Порядок выполнения» и таблица.
2. Взять **первую в порядке выполнения сессию со статусом `не начата`, у которой все зависимости в статусе `готово`**. Зависимость в `ждёт ок` или `частично` не считается выполненной: тогда взять следующую доступную; если доступных нет, сказать владельцу, чего именно ждём.
3. Если владелец назвал номер, брать его; при невыполненных зависимостях сделать только независимую часть и честно записать остаток.
4. Не взять сессию, ветка которой уже существует: `git fetch --all -q; git branch -r | grep roadmap; git log origin/master --grep "Roadmap: SNN"`. Есть ветка `feat/roadmap-SNN-…` с коммитами, но строки в журнале нет — прошлая сессия оборвалась: продолжить с её ветки (прочитать её коммиты), а не начинать заново.

## Протокол старта (по порядку)

1. Выбрать сессию (выше). Статус `в работе` в master **не записывается** (иначе лишний деплой): о незавершённой работе говорит ветка.
2. Прочитать `CLAUDE.md` (корень репозитория) и `predvestnik_v2/AGENTS.md`, дальше по его таблице: `CLEAN_CODE.md`, `AUTONOMOUS_AGENT_POLICY.md`, `AUTONOMOUS_MODE.md` (протокол критика и повторных попыток). Если сессия трогает тексты для игрока — `docs/PLAYER_COPY.md`;
   если видна игроку — `docs/PATCH_NOTES.md`; если визуальная или правит админку — `docs/MINIAPP_DESIGN_RULES.md`; для git и выкатки — `docs/agent/06-git-and-release.md` (файл на `PRODUCTION_RELEASE_CHECKLIST.md` в нём устарел: такого файла нет, вместо него разделы «Выкатка» и «Проверка прода» ниже).
3. Прочитать свой файл `sessions/SNN-….md`, `findings/`, на которые он ссылается, «Итог» зависимостей и в `OWNER_REQUEST.md` пункты владельца, к которым относится сессия (таблица в конце файла).
4. Сверить журнал с реальностью: `git log --oneline -30 -- predvestnik_v2`, раздел «Ждёт подтверждения прода» в `STATUS.md` (если там есть строки, в первой же реплике коротко спросить владельца, подтвердил ли он прод; не блокироваться, если ответа нет).
5. Поднять окружение: `bash predvestnik_v2/docs/roadmap/env-setup.sh` (из корня репозитория), см. `ENV.md`. Снять **базовую линию**: запустить тесты области на чистом состоянии и записать результат (в `ENV.md` отмечено, что не все 330 тестов проверялись в облаке).
6. Создать рабочую ветку и работать в ней (см. «Выкатка»).

**Откуда запускать команды:** все команды в `sessions/` и `findings/` — из `predvestnik_v2/`, кроме `env-setup.sh` (из корня репозитория). Пути вида `FastAPI/…`, `services/…` считаются от `predvestnik_v2/`.

## Правила работы

- Код и данные — **только** внутри `predvestnik_v2/`. Сайт IESA (Django) не трогать. Единственное исключение: указатели в корневом `CLAUDE.md`, если факт изменился (`CLAUDE.md`, «Если документ устарел»). Один коммит — один проект.
- Держаться границ своей сессии. Нашлось постороннее (баг, мусор, идея) — строкой в «Находки по пути» в `STATUS.md`, **не чинить**.
- Нужно решение владельца (деньги, цены, данные игроков, правила, видимость чужого контента, новая механика) — строкой в «Нужны решения владельца» и **продолжить с безопасным дефолтом** (функция за выключенным флагом или минимальный вариант). Не гадать и не блокироваться.
- Секреты: ключи, токены, DSN прода не печатать и не коммитить.
- Чужие незакоммиченные изменения не трогать; работать в своей ветке от актуального `origin/master`.
- Большие файлы (`app.NN.js` и др.) правили сразу два ИИ (Claude и Codex): перед правкой смотреть `git log -p` по файлу.
- Тексты для игрока, подсказки, Путеводитель, ответы бота — по `docs/PLAYER_COPY.md`. Новая механика = новая тема Путеводителя **в том же коммите**. Заметное игроку обновление = патч-нот дня и скриншот (`docs/PATCH_NOTES.md`).
- Тиры, цены и id образов не менять (решение владельца). Figma не используется: внешний вид согласуется через стенд «до/после» (S16) или скриншоты.
- Параллельные сессии допустимы только из разных блоков с непересекающимися файлами; `STATUS.md` правят построчно, при конфликте — `git fetch` + `git rebase origin/master`.

## Выкатка (master = прод, деплой автоматический, каждый пуш в master перезапускает бота и сайт)

**Ветки.** Среда может назначить сессии свою ветку `claude/…`: работать в ней и пушить в неё (резервная копия). Если названа ветка по правилам репозитория — `feat/roadmap-SNN-<тема>`. В master — только fast-forward:
`git fetch origin master && git rebase origin/master && git push origin HEAD:master` (без `--force`, после повторных проверок). Если пуш в master запрещён правами или средой — **не обходить**: оставить всё в ветке, сообщить владельцу и поставить `ждёт ок`.

**Один пуш в master на сессию.** Код, документы, журнал (`STATUS.md`, файл сессии, `ENV.md`, `findings/`) выкатываются **вместе** одним пушем. Отдельный журнальный пуш допустим только когда кода в master нет (визуал ждёт «ок», сессия закрывается без кода).
Хэши коммитов в журнал не вписывать: сессию находят по строке `Roadmap: SNN` в конце сообщения коммита (`git log --grep "Roadmap: S05"`).

| Что | Куда | Когда |
|---|---|---|
| Не-визуальный код (сервер, бот, тесты, измерения), документы, журнал | master | после проверок сессии |
| Визуальный код | ветка `feat/roadmap-SNN-…` | в master только после «ок» владельца |
| Код, выкатываемый выключенным (`включение`) | master | выключатель по умолчанию off; включает владелец |

**Что считается визуальным:** всё, что видит игрок (экраны Mini App, меню, образы, тексты на экранах, сообщения бота), и любая смена вида админки. Служебный блок, добавляющий данные в существующую раскладку админки без смены вида (например, «Здоровье» в S01), «ок» не требует.

**Проверка прода из облака невозможна** (адреса прода из сессии недоступны, проверено: HTTP 000). Поэтому после пуша в master сессия: (1) прогоняет локально все проверки до пуша; (2) пробует `python tools/verify_production_http.py` и честно записывает «не проверено из облака»;
(3) ставит `готово` и добавляет строку в раздел «Ждёт подтверждения прода» в `STATUS.md`; (4) просит владельца подтвердить в трёх пунктах: в панели DigitalOcean деплой `Healthy`, `/api/health` и `/api/ready` отвечают, Mini App открывается. Сломалось — откат (`git revert` + пуш) по просьбе владельца.

**Определения, на которые ссылаются файлы сессий:**
- **PG-гейт:** все `*_pg.py` тесты затронутой области и новые PG-тесты на новые таблицы, индексы, запросы проходят на локальной PostgreSQL (`ENV.md`); схема идемпотентна (повторный `init_db` ничего не меняет); тесты, требующие пустую базу, запускаются на свежей (`env-setup.sh --fresh-db ИМЯ`);
  разрушающих DDL нет, индексы — только `CREATE INDEX CONCURRENTLY IF NOT EXISTS` вне транзакции.
- **Независимый read-only аудит:** отдельный субагент (только чтение: тип Explore или Plan) получает дифф и цель сессии и ищет регрессии, гонки, утечки скрытых данных, нарушения правил проекта (`AUTONOMOUS_MODE.md`, п. 1.4). Сессия исправляет найденное или аргументированно отклоняет; вердикт записывается в «Итог».
  Требуется там, где так сказано в файле сессии (деньги, права, приватность, пул и блокировки, миграции).
- **Стенд «до/после»:** снимки одного экрана или образа на базовой ревизии и на ветке (S16 создаёт инструмент; до него — `ui_smoke.py --shots` и `tools/admin_stand.py`).

**Связь с релизным журналом проекта.** По `AUTONOMOUS_AGENT_POLICY.md` (§4) история релизов ведётся в `docs/audits/AUTONOMOUS_RELEASE_BACKLOG.md`. Дорожная карта — план-уровень (по решению владельца 2026-10-27 лежит отдельно), а каждая **выкатка в master** дополнительно получает короткую запись в релизном журнале:
идентификатор `ROADMAP-SNN`, что выпущено, как проверено, что не проверено. Других новых файлов вне `docs/roadmap/` не плодить.

## Протокол финиша (обязательно)

1. Все проверки из файла сессии зелёные. Красное — не коммитить «на потом».
2. Дописать в файле сессии раздел **«Итог»**: что сделано (по коммитам: `git log --grep "Roadmap: SNN"`), что проверено и как, что осталось, что обнаружено.
3. Обновить строку сессии в `STATUS.md`: статус, дата, ветка (если есть), «сделано» и «осталось» по одной строке. Остаток, который не уместился, оформить **новой строкой `SNNб`** в таблице (статус `не начата`, те же зависимости, ссылка на раздел «Остаток» в файле сессии), а исходную пометить `готово` для сделанной части.
4. Если из-за сессии изменился факт, описанный в документации, — обновить документ в том же коммите.
5. Коммит-сообщения по правилам репозитория: `тип(predvestnik): суть` (`feat`, `fix`, `docs`, `test`, `chore`), в конце отдельной строкой `Roadmap: SNN`, затем атрибуция, которую требует среда.
6. Выкатка по разделу выше. Кратко отчитаться владельцу по-русски: что сделано, что дальше, нужны ли от него «ок» или данные.

## Статусы и особые случаи

`не начата` → `ждёт ок` (визуал на ветке) → `готово`. Статуса `в работе` в master нет (см. «Протокол старта»). `частично` не используется: недоделанное уходит в новую строку `SNNб`.
Колонка «Ок» в `STATUS.md`: `нет`; `да` (владелец смотрит снимки до выкатки в master); `включение` (код выкатывается выключенным, владелец включает сам по образцу); `да (экран)`/`да (интерфейс)` (серверная часть без «ок», интерфейсная — с «ок»).

**Режим «влить одобренное»:** найти ветку (`git branch -r | grep roadmap-SNN`), прочитать раздел «Итог» и замечания владельца, выполнить замечания, `git rebase origin/master`, повторить проверки сессии, влить в master (fast-forward), записать релизную запись, обновить журнал (`ждёт ок` → `готово`).
Если за время ожидания код в master изменился так, что снимки уже не отражают результат, пересобрать снимки и показать владельцу ещё раз.

**Если владелец не ответил на «ок»:** сессия заканчивается статусом `ждёт ок` с названием ветки и тем, что посмотреть; зависимые сессии ждут. Владелец вернётся промптом «влить одобренное».

## Общие проверки (сверять с файлом сессии)

- Сервер/бот: `BOT_TOKEN=1:x PYTHONPATH=. $PY tools/test_<имя>.py`; PG-тесты с `--dsn` (`ENV.md`).
- Экран: `python tools/ui_smoke.py --only <экран> --widths 320,390,430`, при движении `--perf --device mid`; админка — `python tools/admin_stand.py --tabs <вкладки>` (снимки на фикстурах без входа, 320/390/430, две темы).
- Тексты игроку: `tools/test_player_copy_contract.py`, `node tools/test_guide_navigation.js`.
- Патч-ноты: `tools/audit_release_whatsnew.py`, `tools/test_patch_notes_contract.py`, `tools/test_whatsnew_v3_contract.py`.
- Перед любым пушем в master: нет секретов, нет посторонних файлов, ветка на актуальном `origin/master`.
