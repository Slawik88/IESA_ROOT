# «Что нового»: лента обновлений игрока

Страница Mini App, где игрок узнаёт, что изменилось, и одним нажатием попадает на экран, где это появилось. Ревизия 12.10.2026: раньше это был плоский список из текстов, теперь вверху «Новое для вас», у записи есть значок раздела, строка в одну фразу, «Где искать» и кнопка «Открыть», а история делится по дням и разделам. Здесь только то, как это устроено; зачем и что просили, смотри `docs/DESIGN_SESSION_BRIEF.md` («Уточнения дизайна · 12.10.2026»).

## Что видит игрок

1. **Шапка**: «Обновления Предвестника», «Что нового» и строка по состоянию (ниже). Кнопка «‹ Назад» своя: ведёт туда, откуда пришли (меню открывает ленту с любого экрана), а без истории в профиль.
2. **«Новое для вас · N»**: всё, что новее прочитанного, не больше пяти записей, крупно. У записи залитый значок раздела, раздел и день, метка «Новое», заголовок, строка, «Где искать» и кнопка «Открыть …» (если у записи есть `open`). Нажатие на запись раскрывает подробности. Остальные новые уходят в историю с меткой «Новое».
3. **«История · N»**: остальное по дням («Сегодня, 12 октября», «Вчера», дальше дата, с годом, если он не нынешний), по 14 записей и «Показать ещё · N». Фильтр «Всё / Игры / Питомцы и вещи / Образы / Профиль / Бот в чате» появляется, только когда строк не меньше восьми и групп не меньше двух. В истории «Открыть» тихая ссылка, а «Где искать» лежит внутри подробностей.
4. **Исправления** (тег `Исправления`, `Исправлено`, `Фикс`, `Стабильность` или `"kind": "fix"`) тише: маленький значок, без «Открыть», подробности по нажатию.

| Состояние | Строка под заголовком | Что видно |
|---|---|---|
| Первый заход (прочитанного нет в ленте) | «Всё, что менялось в приложении. Сверху самое свежее.» | «Последние обновления»: три последние новинки без метки «Новое», исправления остаются в истории |
| Есть новое | «С прошлого раза: N обновлений. «Открыть» ведёт сразу на нужный экран.» | «Новое для вас» и история ниже |
| Всё прочитано | «Вы в курсе всех обновлений. Новое появится здесь.» | только история |
| Лента пуста | | «Пока тихо» |
| Не загрузилась | | сообщение и «Повторить» (`role="alert"`) |

## Прочитано и точки

- Id последней прочитанной записи лежит на сервере (`users.whatsnew_seen_id`, `POST /profile/whatsnew-seen`), `localStorage.wn_seen_id` только запасной вариант. Всё выше этого id считается новым.
- Страница снимает «прочитано» в момент захода, показывает «Новое» и только потом отмечает всё прочитанным (`_wnMarkSeen`), поэтому метки остаются на экране, пока игрок читает. Следующий заход видит «Вы в курсе».
- Страница читает ленту при каждом открытии (`openWhatsNew` убирает `news` из `_loaded`). Возврат кнопкой «Назад» из экрана, куда привела «Открыть», страницу не перерисовывает.
- **Точка на вкладке дока** (`.nb[data-wn]`): запись новее прочитанного, не исправление, её `open` ведёт на вкладку дока (в таблице переходов есть `tab`) и ей не больше 14 дней. Гаснет, когда игрок открыл вкладку (`switchPage` → `_wnTabVisit`) или ленту. Закрытые точки помнятся в `localStorage.wn_dot_ack` (до 80 id), без хранилища до закрытия приложения. Для скринридера в кнопку вставляется скрытое «, есть новое». Игроку, который ни разу не открывал ленту, точек нет: прошлое для него не «новое». Пересчёт идёт при каждом чтении ленты (`checkWhatsNewBadge`, `loadWhatsNew`).

## Запись ленты

`FastAPI/static/updates.json`, новые записи сверху. Обязательные поля проверяет `tools/audit_release_whatsnew.py`, остальные необязательны: без них запись читается, но хуже (запасные значения в таблице).

| Поле | Что это | Если нет |
|---|---|---|
| `id`, `date`, `tag`, `title`, `summary`, `details` | обязательны; `date` ISO, `details` непустой список строк | аудит и тест падают |
| `area` | раздел: значок, подпись, группа фильтра (таблица ниже) | по тегу (`Чат`, `Семья`, `Админка` → `chat`, `VIP` → `wallet`), иначе `app` |
| `short` | строка для списка, до 150 знаков, дополняет заголовок | первое предложение `summary` |
| `open` | куда ведёт «Открыть» (таблица переходов ниже) | кнопки нет |
| `where` | путь словами, как его видит игрок, до 48 знаков | строки «Где искать» нет |
| `flag` | ключ модуля (`pets_v2`): игрок видит запись, только когда модуль включён | запись видна всем |
| `kind` | `"fix"` делает запись исправлением, даже если тег другой | по тегу |
| `terms` | `[{term, definition}]`: слово в тексте становится пояснением по нажатию | без пояснений |

```json
{
  "id": "2026-10-12-chests-tab",
  "date": "2026-10-12",
  "tag": "Новое",
  "area": "chests",
  "open": "chests",
  "where": "Нижнее меню › Сундуки",
  "title": "Сундуки теперь в нижнем меню",
  "short": "Открывайте сундуки в один тап, без поиска по «Ещё».",
  "summary": "Сундуки вынесены на вкладку. Там же видно, что лежит в каждом.",
  "details": ["📦 Вкладка: слева от «Питомцев»", "🔑 Ключи: количество видно сразу"]
}
```

## Как писать записи

- **Заголовок** говорит, что стало: «Сундуки теперь в нижнем меню», а не «Обновление сундуков». **`short`** добавляет к заголовку и не повторяет его (тест следит). Без `short` берётся первое предложение `summary`, значит оно должно быть самостоятельным.
- **`details`**: пункты. Начало строки с эмодзи («🏠 Главный экран: …») становится значком пункта, слова до двоеточия (до 34 знаков, без точки) выделяются. Пункты нужны тем, кто раскрыл запись, поэтому там цифры и условия, а не повтор заголовка.
- **`open` и `where`** ставим, когда новое можно увидеть на экране. `where` пишем как путь игрока: «Игры › Ритм», «Кнопка-рюкзак вверху экрана». Для исправлений `open` не ставим: кнопки у них нет, тест не пропустит.
- Запись о модуле за флагом получает `flag`: про то, чего у игрока ещё нет на экране, не рассказываем.
- Каждая запись «Что нового» идёт ещё и в патч-ноут дня для официального канала (короче, проще, с картинкой): `docs/PATCH_NOTES.md`. Без пункта там тест `tools/test_patch_notes_contract.py` выпуск не пропустит.
- Выпуск без новой записи аудит не пропускает: новый `id` сверху, дата сегодняшняя. Текст про игрока, без названий файлов и функций.

## Как добавить раздел или переход

1. Раздел: строка в `_WN_AREA` (`name`, `group` из `_WN_GROUPS`, значок в `viewBox="0 0 24 24"`, тот же, что у вкладки) и строка в таблице выше.
2. Переход: строка в `_WN_GO` (`cta` до 24 знаков, `tab` только для вкладки дока, `run` вызывает функцию, которая уже есть в приложении) и строка в таблице выше. Тест проверяет, что функция определена, страница существует, вкладка есть в доке.
3. `python tools/test_whatsnew_v3_contract.py`: он же требует, чтобы каждый ключ был назван в этом документе.

## Проверка

```
python tools/test_whatsnew_v3_contract.py                  # подключение, формат записей, переходы, стили; внутри запускает node-тест
node tools/test_whatsnew_v3_behavior.js                    # только поведение страницы (нужен node)
python tools/test_release_whatsnew.py                      # формат ленты и правила выпуска
python tools/ui_smoke.py --only news,news-first,news-new,news-open --widths 320,390,430 --shots DIR   # смоук: четыре состояния страницы
```

Смоук задаёт «прочитано» до открытия страницы, поэтому состояния не зависят от порядка экранов. Стенд без особых флагов (`python tools/ui_stand.py --rich`) показывает всё, что нужно ленте.

## Известные границы

- Записи старше `_WN_ARCHIVE_BOUNDARY` (`2026-08-23-reconstruction-first-release`) игроку не показываются: они о прежнем продукте.
- Фильтр истории по группам, а не по каждому разделу: чипов должно быть не больше пяти.
- Поиска по тексту нет: историю читают по дням и разделам.
- Точка на вкладке зажигается только записью с `open`, у которого есть `tab`; записи про Инвентарь, Достижения, магазин и настройки точки не зажигают (у них нет вкладки в доке).
