# Онбординг боя — дизайн-спека

**Дата:** 2026-07-21
**Автор:** согласовано с владельцем в брейншторме
**Статус:** черновик на ревью
**Область:** Боёвка 4.0 «Клеточная тактика» (Врата) — ощущение, обучение, дофамин победы

## 1. Проблема

Боёвка «прикольная, но неудобная и непонятная новичку». Конкретно:

- **Враг ходит мгновенно** — весь ход врага считается на сервере за один запрос, клиент
  получает финальную доску и «доигрывает» только вспышки урона; движения не видно (телепорт).
- **«Конец хода» реагирует со второго тапа** — ввод залипает.
- **Скудные анимации, сырое ощущение** — токены телепортируются, победа = одна строка текста.
- **Непонятная карта** — значки укрытий/опасности/угроз/подсветок не читаются без объяснения.
- **Гайд не работает** — текстовая модалка на 3 экрана один раз перед боем; никто не читает
  текст про механику, которую ещё не пробовал.
- **Нет дофамина** — после победы игрок не видит красиво, что он выиграл и что получил;
  награды непонятны («что это, зачем, где взять, где применить»).

## 2. Цель и границы

**В границах (одна цельная спека «онбординг боя»):**

- **A. Ощущение боя:** пошаговая анимация хода врага (лента битов), движение токенов как
  первый класс, фикс залипания ввода.
- **B. Читаемая карта:** переосмысленный визуальный язык клеток + постоянная мини-легенда.
- **C. Скриптованный «Первый бой»:** реальный серверный бой против слабых врагов с мягким
  коуч-слоем, обучающим по одной механике за ход. Автозапуск при первом входе, повтор через «?».
- **D. Дофамин победы:** полноэкранный экран наград с анимацией и кликабельными наградами +
  переиспользуемый лист-описание («что / зачем / где взять / где применить»).

**Вне границ (отдельными фичами позже):**

- Раскатка листа-описания на ВЕСЬ сайт и авторинг контента для всех предметов инвентаря (#4).
  Здесь строится сам компонент и наполняется только для конечного набора боевых наград.
- Страница «Что нового» + модалка обновлений (#5).
- Балансные правки боя, новые этажи/юниты/механики.

**Утверждённые решения (из брейншторма):**

1. Гайд — **скриптованный «Первый бой»** (не коучинг поверх реального этажа, не песочница).
2. Анимация врага — **полный таймлайн хода** (сервер отдаёт ленту битов; не фронт-стаггер).
3. Карта — **читаемые клетки + постоянная мини-легенда** (не только туториал).
4. Победа — **полный экран наград #3 втащен в эту спеку**, включая кликабельные награды.
5. Архитектура туториала — **вариант А: реальный бой + мягкое ведение** (не фейк, не жёсткие рельсы).

## 3. Текущая архитектура (как есть)

- **Фронт:** `FastAPI/static/app.11.js` — Казарма, Врата, арена. Классический script (не ES-модуль),
  склеивается `main.py` из частей `app.01..app.11.js` → проверять `node --check`.
- **Бэк-логика:** `services/battle3.py` — сервер-авторитарный движок (AP/дальность/LoS/криты/ИИ).
- **Бэк-адаптер:** `FastAPI/routers/battle.py` (prefix `/combat2`) — тонкий, состояние в
  `repositories/battles.py`.
- **Форма ответа действия:** `_respond()` → `{**public_state(state, bid), **extra, "reward": reward}`,
  где `extra = {"turn": res}`. `res` из `apply_action`; для `end_turn` — `{"ok", "phase", "hits"}`.
  `hits` — плоский список ударов, клиент проигрывает их через `_b3PlayHitFx` (стаггер 240мс).
- **Ход врага:** `end_player_turn` → `_enemy_phase` (весь ход разом) → `_end_round`.
- **Рендер арены:** `_btRender(st, turn, reward)` в app.11.js — полный ре-рендер `innerHTML` оверлея.
- **Текущий «гайд»:** `_b3IntroOpen(kind)` / `_b3ShowIntro(kind)` — модалка на 3 шага, один раз
  через localStorage.
- **Текущая «победа»:** строка `headHtml` (`🏆 ПОБЕДА! +X 🌑`) + кнопка «Назад».

## 4. Дизайн по секциям

### A. Ощущение боя

**A1. Лента битов хода врага (ядро).**

- `battle3.py`: `_enemy_phase` / `_execute_enemy_plan` / `_enemy_attack` / `_enemy_aoe` /
  ульта врага **дописывают упорядоченный `timeline`** — список битов. Формат бита:
  ```
  {"actor": {"side":"enemy","i":int},
   "kind": "intent" | "move" | "attack" | "defend" | "aoe" | "ult" | "skip",
   "from": {"x","y"} | null,      # для move
   "to":   {"x","y"} | null,      # для move
   "target": {"side","i"} | null, # для attack/aoe
   "dmg": int | null, "crit": bool, "elem": str | null,
   "text": str}                   # готовая строка для лога/подписи
  ```
- Возвращаем ленту в `res` под ключом `timeline` (транзиентно, в БД не пишем). `hits` остаётся
  для обратной совместимости и финального settle.
- Тайминги — в `core/constants.py`: `B4_BEAT_INTENT_MS`, `B4_BEAT_MOVE_MS`, `B4_BEAT_HIT_MS`,
  `B4_BEAT_GAP_MS` (значения подбираем на 390px; ориентир: intent ~350, move ~260/клетка или
  общий ~300, hit ~200, gap ~180).

**A2. Проигрыватель на клиенте.**

- Новый `_b3PlayTimeline(timeline, finalState)` в app.11.js. Пока лента идёт — доска в
  «режиме проигрывания» (`_b3Playing=true`): панель действий и клетки залочены.
  Для каждого бита: подсветить активного врага (пульс) → показать намерение →
  **плавный слайд токена** (translate по grid-координатам) → удар с текущими hit-FX (`_b3OneHitFx`) →
  пауза `gap`. По завершении — `_btRender(finalState)` (settle).
- Тот же проигрыватель обслуживает многоударные СВОИ действия (AoE-навык, Триада) и ульту врага —
  единый язык движения. Для одиночных мгновенных действий игрока лента не нужна (как сейчас).
- **Скип:** тап по доске во время проигрывания — доиграть мгновенно и показать финал.
- **Reduced-motion / `no-fx`:** ленты нет — сразу финальное состояние + мгновенные hit-FX
  (ветка уже частично есть в `_b3PlayHitFx`).

**A3. Движение токенов как первый класс.**

- Токен получает CSS-transition на позицию. Ход игрока (`_b3Move`) — слайд, а не мгновенный
  ре-рендер. Слайд врага — внутри проигрывателя ленты.
- Реализация: рендер токена по абсолютной позиции клетки (grid → px) c `transition: transform`,
  либо FLIP между ре-рендерами. Выбор — на этапе плана (замер на 390px).

**A4. Фикс ввода.**

- **«Конец хода» со 2-го тапа** — диагностика через systematic-debugging. Гипотезы: `_b3Lock`
  глотает тап в окне ре-рендера; кнопка пересоздаётся в `innerHTML` под пальцем; двойное
  срабатывание touch/click. **Критерий приёмки:** одиночный тап всегда регистрируется на телефоне.
- Действия залочены во время проигрывания ленты, разлок по завершении (это же убирает часть
  гонок ввода).

### B. Читаемая карта

- **Клетки-состояния (CSS боевых стилей):**
  - ход — точки-следы на достижимых клетках (не сплошная заливка);
  - атакуемая цель — кольцо-прицел вокруг врага;
  - опасная `🔥` — явно «плохая» (красная штриховка/мягкий пульс);
  - укрытие `🪨` — явный «щит»-бейдж; препятствие `🌲` — глухая клетка;
  - намерение врага (⚔️→цель) — крупнее, с линией/стрелкой к цели.
- **Постоянная мини-легенда:** расширяем кнопку «?» → сворачиваемая панель «что значит каждый
  значок» (клетки, иконки угроз `B4_THREAT_ICO`, статус-эффекты `B3_FX_ICO`, ярость). Доступна
  всегда, не только в туториале.
- Все состояния проверяем скриншотами на 390px (мелкие тач-цели — риск); держим тач-цель ≥ ~40px.

### C. Скриптованный «Первый бой»

**C1. Режим и запуск.**

- Новый `mode="tutorial"`. Эндпоинт `POST /combat2/tutorial/start` — создаёт бой с
  **синтетическим отрядом** (2 захардкоженных юнита: DD + танк, НЕ отряд игрока) против 2 слабых
  скриптованных врагов. Не тратит вход дня (`count_today` не учитывает tutorial). **Без награды**
  (`reward=None`): туториал повторяем через «?», лут за повтор — эксплойт экономики; экран победы
  корректно рендерит пустую награду (поздравление без карточек лута). Отдельный генератор
  `tutorial_squad()` / `tutorial_enemy_squad()` в `battle3.py`, конфиг в `core/constants.py`.
- **Флаг завершения — в БД** (переживает смену устройства/чистку кэша): поле/метрика
  `tutorial_combat_done`. localStorage — быстрый путь, но источник правды — сервер (в
  `/combat2/gates` или отдельном флаге отдаём `tutorial_done`).
- **Автозапуск:** при первом входе в бой (Врата) с `tutorial_done=false` — предложить/запустить
  «Первый бой». Повтор — кнопкой «?» → «Пройти обучение заново».

**C2. Анти-фейл и детерминизм.**

- Флаг состояния `tutorial: true`. В `_apply_damage` — клампы: HP союзника не ниже 1; урон врага
  символический. ИИ врага детерминирован (без RNG-телеграфа) — чтобы коуч-марки совпадали с тем,
  что реально произойдёт.

**C3. Упрощённое поле.**

- 7×5, но с намеренно расставленными 1×🪨 укрытие и 1×🔥 опасная клетка на пути к врагу — чтобы
  уроки «укрытие» и «опасная клетка» имели конкретную клетку для подсветки.

**C4. Коуч-слой (клиент, data-driven).**

- Массив `TUTORIAL_STEPS`, каждый шаг:
  `{id, when(state)→bool, text, highlight(state)→{selector|cell}, suggest?, advanceOn(state,action)→bool}`.
- Слой хукается в `_btRender`: если `st.mode==='tutorial'`, найти первый незавершённый шаг, чей
  `when` истинен; показать пузырь-подсказку (снизу, mobile-first) с указателем на подсвеченный
  элемент/клетку, затемнить остальное; пометить done по `advanceOn`. **Мягко:** рекомендованное
  действие подсвечено, но игрок волен иначе — слой пересчитывается на следующем `_btRender`.
- **Учебный план (8 шагов):**
  1. Тапни своего бойца → выбор юнита.
  2. Клетки хода подсвечены — дойди до врага (подсветка рекомендованной клетки).
  3. Враг в дальности — тапни по нему (кольцо-прицел). Первый удар.
  4. Рядом 🪨 укрытие — встань туда: −30% урона.
  5. AP кончились — «Конец хода». **Тут впервые играет лента врага** (учим «вот как он ходит»:
     намерение → шаг → удар).
  6. Хватает AP на 🎯 навык — примени.
  7. Ярость 100 → 💥 ульта. Мягкий широкий QTE.
  8. Победа → экран наград (Секция D).
- Пузырь коуч-марки: снизу, указатель на цель, «Далее»/автопереход, «Пропустить обучение» мелким.
  Уважает reduced-motion.

### D. Дофамин победы

**D1. Экран победы** (полноэкранный `b3-ov`; заменяет строку `headHtml` + кнопку «Назад»):

- Последовательность: затемнение доски → штамп «🏆 ПОБЕДА» въезжает (scale + glow, haptic) →
  карточки наград появляются по одной со счётчиком-роллапом (🌑 +N, 🔷 +N, ◈ осколки юнита с
  эмодзи юнита) → бейдж мастерства при `reward_mult>1` («⚡×1.9 — без потерь / за скорость») →
  сдержанное confetti-lite (по DESIGN — НЕ «дешёвый кликер», золото/фиолет, короткое) →
  кнопки «⚔️ Ещё бой» / «↩ Назад».
- **Каждая карточка награды кликабельна** → `showItemDetail(key)`.
- Ветки reward уже приходят с сервера — рендерим по наличию полей: gates
  (`dark_mora`/`shards`/`unit_shards`/`reward_mult`), abyss (`shards`/`split`/`boss_key`/`unit_shards`),
  war (`damage`/`breached`/`wall_total`/`wall_hp_max`).
- **Экран поражения** — не голая строка: «☠️ Отряд пал», «Юниты восстановятся к следующему бою»,
  подбадривание, «⚔️ Ещё раз» / «↩ Назад».

**D2. Переиспользуемый лист-описание** `showItemDetail(key)`:

- Боттом-шит (сигнатурный `<dialog>` из DESIGN, как `OM`). Секции: заголовок (эмодзи+имя) ·
  чип типа/редкости · **Что это** · **Зачем нужно** · **Где взять** · **Где применить**.
- Контент из нового реестра `ITEM_INFO` (отдельный part-файл или расширение registry) для
  конечного набора боевых наград: `dark_mora` (🌑 Тёмная Мора), `abyss_shard` (🔷 Осколки Бездны),
  `unit_shard` (◈ осколки юнита) + generic-fallback по ключу. Структура — под раскатку на весь
  сайт (#4): там подключаем к остальным предметам и досыпаем контент, компонент не переписываем.

## 5. Изоляция и границы модулей

- **Timeline (бэк):** `battle3.py` пишет ленту в `res`; роутер прокидывает как есть. Движок не
  знает про анимацию — только про порядок событий. Другие режимы (abyss/war), не проигрывающие
  ленту на клиенте, продолжают работать (лента просто игнорируется, если клиент её не читает).
- **Проигрыватель (фронт):** `_b3PlayTimeline` — единственная точка, знающая про тайминги;
  `_btRender` остаётся чистым рендером состояния.
- **Коуч-слой:** отдельный модуль (`TUTORIAL_STEPS` + драйвер), хук в `_btRender` через один вызов;
  вне туториала не активен. Не дублирует боевую логику.
- **Лист-описание:** `showItemDetail(key)` + `ITEM_INFO` — самостоятельный компонент, не зависит
  от боя; вызывается из экрана победы и (позже) откуда угодно.

## 6. Данные и совместимость

- `timeline` — новое транзиентное поле ответа; старый клиент его игнорирует, новый — проигрывает.
  Существующие `hits`/`turn`/`reward`/`public_state` не меняем по смыслу.
- Новый `mode="tutorial"` в `battles`; `get_active_b3` и `count_today` учитывают его отдельно
  (не смешивать с gates-лимитом).
- Флаг `tutorial_done` — новое поле пользователя/метрика; миграция при необходимости.
- Новые константы боя — в `core/constants.py` (тайминги, конфиг туториала).

## 7. Ошибки и краевые случаи

- Лента пустая (враг всё пропустил / скован) → сразу settle, экран не зависает.
- Бой кончился внутри ленты (враг добил) → доиграть до момента смерти, затем экран поражения.
- Игрок вышел/свернул во время проигрывания → при возврате `public_state` уже финальный (лента
  транзиентна) — показываем актуальное состояние, без «застрявшей» анимации.
- Туториал: игрок делает не то, что подсвечено → коуч не ломается, ждёт корректного `advanceOn`,
  при необходимости переформулирует подсказку.
- Reduced-motion/`no-fx` — все новые анимации имеют мгновенную ветку.
- Прод Python 3.11 — f-strings проверять визуально (локальный 3.12 пропускает PEP 701 баги).
