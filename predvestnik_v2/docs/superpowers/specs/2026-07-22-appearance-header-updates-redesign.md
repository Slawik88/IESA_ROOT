# Спек: Шапка + «Внешний вид» + «Что нового» + авто-refresh

**Дата:** 2026-07-22
**Автор:** сессия с владельцем
**Статус:** на согласовании

## 1. Контекст и цель

Мини-апп «Предвестник» (FastAPI + classic-script SPA `app.js`, склеен из `app.01.js…app.11.js`).
Дизайн-система — `DESIGN.md` («Золото в темноте», Deep Space Gold v5): тёмная тема
единственная, золото = ценность/действие/награда, тактильность, боттом-шиты, эмодзи-иконки.

Владелец обозначил боль в четырёх местах. Этот спек покрывает **редизайн-подсистему**
(шапка, экран «Внешний вид», страница обновлений, реактивные апдейты). **Боёвка** —
отдельная подсистема, идёт **отдельным спеком** (баги-блокеры онбординга, мёртвые кнопки
«Выйти»/«Сдаться», инфо-модалки препятствий/врага, hand-holding обучения).

## 2. Объём и декомпозиция

**В этом спеке (редизайн):**
- **A. Двухслойная шапка** — валюты перестают скроллиться; в новом месте — вход «Что нового».
- **B. «Внешний вид» — полноэкранный редизайн** (косметика + галерея тем).
- **C. Страница «Что нового»** — заметная, сканируемая, с индикатором «новое».
- **D. Авто-refresh** — реактивный слой: контент/валюты сами обновляются после действий.
- **E. Аудит слабых мест косметики** — письменный список + мелкие дизайн-фиксы по ходу.

**Порядок:** Сессия 1 = **A + B + E**. Сессия 2 = **C + D**.
(Если владелец решит — блокеры боёвки идут раньше редизайна отдельным спеком.)

**Вне этого спека:** боёвка (отдельный спек), любая правка экономики/цен, новые
кнопки в игровой экономике без явного согласования.

## 3. Инварианты проекта (железно соблюдать)

- `services/` не импортирует `bot.*` / `FastAPI.*`; SQL — только в `infrastructure/repositories/`.
- `app.js` — **classic script** (не ES-модуль); `let/const` только вверху скрипта (TDZ);
  `${…}` только в backtick-строках; после правок — `node --check` на затронутой части.
- Правим нужную часть `app.NN.js` (main.py склеивает их в один скрипт), не плодим `<script>`.
- Прод на **Python 3.11** — бэкенд-правки проверять на 3.11-совместимость (f-string PEP 701).
- Статика читается в память при старте — на проде увидим только после рестарта DO.
- Тест фронта: готовый `tools/preview_server.mjs` (:8402, мок-эндпоинты) + puppeteer 390px.

## 4. Часть A — Двухслойная шапка

### Проблема
Сейчас `#app-header` — один ряд: `hdr-user` (аватар+имя+`Lv·🔥`) слева; справа `#curr-bar`
(🪙 💎 ✨+➕ 🌑 ⓘ) + `🔄`. На узком экране всё это не влезает → горизонтальный скролл,
валюты обрезаются. `🔄 refreshPage()` — костыль ручного обновления (уходит с частью D).

### Решение — два слоя
**Слой 1 (идентичность):** слева `hdr-user` (аватар + имя + `Lv N · 🔥streak`),
справа — **📣 вход «Что нового»** (`whatsnew-btn`) с золотой точкой-бейджем при непрочитанном.
`🔄` убираем (part D делает авто-refresh; на переходный период можно оставить крошечным,
но цель — удалить).

**Слой 2 (валюты):** `#curr-bar` на полную ширину ряда, `space-between`/`flex`, все валюты
`tabular-nums`, компактный формат (`12,3к`), ✨-чип с ➕. Тап по бару — модалка деталей
(`showCurrModal`, уже есть). 🌑 показывается только при `dark_mora > 0` (как сейчас).

### Визуальные правила (DESIGN.md)
- Оба слоя внутри фикс-`<header>` с `backdrop-filter: blur(14–16px)` на полупрозрачном
  `bg-panel`; тонкая нижняя граница `border2`.
- Золото — только на ➕ (действие пополнить) и на badge «новое» (ценность/сигнал).
  Никакой золотой заливки контейнеров ради красоты.
- Плотность мобильная (9–14px), чипы валют 11px/700, sub 9.5–10px `ink-muted`.
- `prefers-reduced-motion` и `body.no-fx` уважать (пульс валют уже есть — `cb-pulse`).

### Затронутое
- `index.html` — разметка `#app-header` (два `.hdr-row`), кнопка `whatsnew-btn`.
- `app.css` — стили `#app-header`, `.hdr-row-1/2`, `#curr-bar` (полная ширина), `whatsnew-btn` + badge.
- `app.02.js` — `updateCurrBar` (без изменения логики валют), новый хук badge «новое».

## 5. Часть B — «Внешний вид»: полноэкранный редизайн

### Проблема (корни)
Конструктор косметики (`app.10.js`, `openLooksModal`) и галерея тем (`app.05.js`,
`openThemeModal`) — модалки, где:
1. **Лаги:** каждая карточка сетки (`_looksSwatch`) рендерит **живой анимированный** мини-эффект
   (glow/рамка/частицы/градиент). N карточек = N одновременных CSS-анимаций → тормоза.
2. **«Крестик закрывает всё»:** тап по непокупленному предмету открывает **вторую модалку**
   (`_showCosmeticPreview` → «👁 Примерка»). Выход «назад» — только нижняя кнопка; рука тянется
   к верхнему ✕, который закрывает весь конструктор.
3. **«Ходить-кликать каждую тему»:** нет единого экрана — сравнение только через открытие
   каждого предмета в отдельной полноэкранной модалке.
4. **Тяжесть навигации:** `openLooksModal()` на каждый «назад»/«применить» заново тянет
   `/cosmetics/` + `/cosmetics/presets`.

### Решение — один полноэкранный экран
Новый full-screen overlay `pg-looks` (по паттерну `switchPage`/`.page`, открывается из Профиля):

- **Верхняя панель:** `‹ Назад` (слева, единственный выход → инстинкт совпадает) + заголовок
  + ряд вкладок-слотов (`✨ Ореол · 🖼 Рамка · 🌟 Гало · 🏷 Титул · 🖌 Фон · ❄️ Частицы ·
  🎬 Приветствие · 🎨 Темы`).
- **HERO-превью (постоянное, сверху):** крупная карточка профиля, **анимируется только она**;
  обновляется мгновенно по тапу предмета. Второй модалки «Примерка» больше нет.
- **Сетка предметов:** превьюшки **статичные / замороженные** (`animation-play-state: paused`
  или first-frame swatch). Тап = выбор → hero обновляется.
  - Владеешь → инлайн «Надеть / Снять».
  - Не владеешь → под hero выезжает **компактная плашка покупки** (цена ✨, VIP-warn, кнопка) —
    инлайн, без модалки.
- **Пресеты образов, «Сюрпризы/Крафт»** — сохраняются, встроены в экран (кнопки/секции),
  без ухода в отдельный слой без нужды.
- **Кэш:** навигация и «Применить» — из уже загруженного `_looksData`, без пере-запросов.
  Полный рефетч — только при первом открытии и после покупки (данные реально изменились).

**Темы:** галерея тем встроена вкладкой «🎨 Темы» того же экрана с тем же паттерном
«тап → превью в hero» (для тем hero = превью строки профиля; переиспользуем
`/themes/preview/{id}` raw-string). Никаких модалок-на-тему.

### Производительность — конкретика
- Grid-swatch: не запускать бесконечные анимации в сетке. Варианты: `animation-play-state:paused`
  через класс на контейнере сетки; либо статичный «первый кадр» swatch; анимируется только hero.
- Не создавать десятки `.card-fx`-частиц в сетке; частицы — только в hero.
- Убрать полный рефетч на каждый чих; локальный ре-рендер только затронутого блока.

### Затронутое
- `app.10.js` — переписать `openLooksModal`→`openLooksScreen` (overlay), рендер экрана,
  hero-превью, инлайн-покупку; выпилить `_showCosmeticPreview`-модалку (заменить hero).
- `app.05.js` — темы: рендер как вкладка экрана + hero-превью вместо `openThemeModal`.
- `index.html` — `<div id="pg-looks" class="page looks-screen">…</div>` (overlay-контейнер).
- `app.css` — стили экрана, hero, сетки со статичными swatch, плашки покупки.
- Точка входа из Профиля (`app.02.js:76` `openLooksModal()` → `openLooksScreen()`).

## 6. Часть C — Страница «Что нового»

### Данные
Файл `updates.json` (ведёт владелец как текст), пример записи:
```json
{
  "id": "2026-07-22-combat-cells",
  "date": "2026-07-22",
  "tag": "Фича",              // Фича | Фикс | Контент | Баланс
  "title": "Клеточная тактика в бою",
  "summary": "Бой теперь на поле 7×5 с очками действия и укрытиями.",
  "details": ["Короткий буллет 1", "Короткий буллет 2"],
  "terms": [{"term": "AP", "definition": "Очки действия — сколько ходов за раунд."}]
}
```
Отдаётся новым эндпоинтом (`/updates/` — список, newest-first). Термины — инлайн в записи
(владелец пишет человеческое объяснение; можно линковать в AI_KNOWLEDGE позже, YAGNI сейчас).

### Раскладка (не простыня)
- Вертикальная лента компактных карточек: `дата-чип + тег + заголовок + 1 строка сути`.
- Тап карточки = раскрыть `details` (аккордеон). По умолчанию всё свёрнуто → быстрый скан.
- Термины в тексте подсвечены (dotted underline); тап = поповер с человеческим объяснением
  (маленький, на месте, не модалка на весь экран).

### Индикатор «новое»
- `whatsnew-btn` в шапке (part A) получает **золотую точку-бейдж**, когда есть записи новее
  «последнего просмотра».
- На странице непрочитанные записи помечены `● Новое` + мягкая подсветка; прочитанные —
  обычные. Пропустил 3 обновы — видишь все, новейшие сверху.
- Открыл страницу → `last_seen_update` обновляется (все текущие → прочитано), badge гаснет.

### Хранение «последнего просмотра»
Per-user в БД (кросс-девайс, премиально): поле/строка в настройках игрока
(`repositories`, значение = `id`/`date` последней прочитанной записи). Фолбэк — localStorage,
если пользователь не залогинен.

### Затронутое
- `updates.json` (новый, в корне `predvestnik_v2/` или `FastAPI/static/`).
- `FastAPI/routers/updates.py` (новый) — `GET /updates/`, `POST /updates/seen`.
- `infrastructure/repositories/…` — get/set `last_seen_update`.
- `app.NN.js` — рендер страницы, аккордеон, поповер терминов, badge-логика.
- `index.html`/`app.css` — контейнер страницы + стили ленты/чипов/поповера.

## 7. Часть D — Авто-refresh (реактивный слой)

### Проблема
SPA уже на `fetch`, но после мутаций секции не перерисовываются → игрок жмёт F5.
Пример владельца: крутишь гачу за бесплатный жетон — счётчик жетонов не меняется.

### Решение
Единая точка: мутирующие вызовы `api()` (POST/PUT/DELETE) при успехе триггерят
(debounced) реактивный апдейт:
1. **Бар валют** — `refreshCurrBar()` (уже есть), расширить, чтобы покрывал все счётчики-кошельки,
   включая жетоны бесплатных круток гачи.
2. **Активный экран** — ре-рендер через реестр подписчиков: `_activePage`/подэкран регистрирует
   свою `refresh`-функцию; после мутации она вызывается. Переиспользуем существующий паттерн
   `_loaded.has(page)` + `loadX()` (уже так делают WS-события в `app.01.js`).

**Безопасность:** debounce (не долбить сервер), opt-in по экранам (не все мутации требуют
рефреша всего), не конфликтовать с оптимистичными локальными апдейтами (флаг «уже обновил сам»).

### Точечные дыры (пройти списком и починить явно)
- Жетоны бесплатных круток гачи после крутки (пример владельца).
- Валюты после купил/надел/крафт/пополнение.
- Счётчики после кормёжки питомца.
- (собрать полный список при реализации — часть проверки.)

### Затронутое
- `app.01.js` — `api()` (детект мутирующих методов + эмит события), реестр рефрешеров.
- `app.02.js` — `refreshCurrBar` (расширить покрытие).
- Точечные вызовы в местах действий (гача/маркет/зоо и т.п.).
- Удалить кнопку `🔄 refreshPage()` из шапки (стала не нужна) — согласовать в part A.

## 10. Риски / открытые вопросы

- **Полноэкранный overlay vs роутинг:** `pg-looks` как `.page` вне нижнего дока (открытие из
  профиля, `‹ Назад` возвращает в профиль). Проверить, что `switchPage`/`_loaded` это переваривают.
- **Размещение 📣:** в слое 1 справа. Если тесно на узких — вынести в компактную иконку.
- **`updates.json` расположение:** static (отдаётся напрямую) vs корень + роутер. Реализация
  выберет по тому, как проще кэш-инвалидировать при правках владельцем.
- **Объём:** A+B+E за сессию 1 реалистично; C+D за сессию 2. Боёвка — отдельно.
