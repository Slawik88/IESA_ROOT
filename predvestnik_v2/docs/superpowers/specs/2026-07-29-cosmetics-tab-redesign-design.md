# Редизайн вкладки «Внешний вид» — design spec

**Дата:** 2026-07-29 · **Статус:** дизайн утверждён владельцем, готов к планированию реализации.

## Контекст и цель

После перехода косметики с системы «редкость» на тематические линейки (7 коллекций,
см. `core/cosmetics.py::LINEUPS`) и закрытия 5-пунктового бага/UX-аудита, владелец
запросил **полную концептуальную переработку** живой вкладки «Внешний вид»
(`FastAPI/static/app.10.js` + `app.css`) — не патчи, а новую структуру и подачу.
Явный запрос: «реально классный, приятный экран выбора косметики».

Дизайн собран через `superpowers:brainstorming` + visual companion, ~9 больших
раундов итерации. Все мокапы — в `predvestnik_v2/.superpowers/brainstorm/` (не в
git, см. `.gitignore`). Механические правила оформления карточек/иконок линеек
вынесены отдельно в **`predvestnik_v2/COSMETICS_COLLECTION_DESIGN_RULES.md`**
(зарегистрирован в `BASE_PROMPT.md`) — этот спек на него ссылается, не дублирует.

## Архитектура: гибридный переключатель

Экран сохраняет общую «рамку»: шапка, sticky-превью, VIP-бар, ряд «Образы»
(см. ниже), кнопка «Сюрпризы и Крафт», секции «Вход»/«Темы». Внутри — новый
**переключатель режима отображения косметики**, сразу под sticky-превью:

- **«По коллекциям»** (режим по умолчанию) — 7 карточек-линеек.
- **«По слотам»** — прежняя логика (6 секций по слотам), но переработанная.

Оба режима читают ОДНИ И ТЕ ЖЕ данные (`_looksData.slots`), различается только
группировка/подача. Выбранный режим запоминается (последний использованный
открывается по умолчанию при следующем визите).

## Режим «По коллекциям»

**Карточка коллекции** (сетка 2×N):
- Медальон — авторский анимированный SVG-сигиль линейки (не эмодзи), правила
  геометрии/анимации — см. `COSMETICS_COLLECTION_DESIGN_RULES.md` §1–2.
- Кольцо-прогресс (`conic-gradient`) вокруг медальона — % собранного, на глаз,
  без открытия.
- Двойная рамка «трейдинг-карты» + тихий диагональный засвет цветом линейки
  (§3). Золото — только на действии, никогда на заливке.
- Полоска из 6 иконок реальных слотов игры (✨🖼🌟🏷🖌❄️) — ярко/тускло по
  владению — самый точный уровень «что именно не хватает».
- Текст: цена всегда с единицей `"N✨/предмет"`, статус — честный
  (`"✓ собрано"` / `"N не куплено"` / `"не начато"`), НИКОГДА `"✓ надето"` на
  уровне коллекции (нельзя «надеть» 12 предметов сразу — у игрока 6 слотов).
- **Тап по карточке — только открывает** коллекцию, ничего не покупает/надевает
  сам по себе.

**Открытая коллекция (детальный экран):**
- «Алтарная» шапка — тот же медальон крупнее (74px+), статичный (не бегущий)
  засвет + виньетка по краям, 2–3 крупные медленные фоновые частицы в духе
  линейки.
- Сегментный измеритель — **N делений = N предметов линейки** (не гладкий %),
  собранные светятся мягким пульсом. Подпись: `"X из Y собрано"` / `"Z не
  куплено · цена/предмет"`.
- Сетка 6 плиток по слотам (✓ твоё / 🔒+цена), тап — инлайн примерка+покупка
  как сейчас.
- Отдельная явная кнопка **«Купить всё недостающее»** — раскладка (N предметов
  × цена = итого), сверка с балансом, блокируется при нехватке. Не побочный
  эффект тапа по карточке.

## Режим «По слотам»

Компактный «умный ряд» вместо двух рядов чипов (было: линейка-чипы + статус-чипы):
- 🔍 Поиск по названию (реальный `<input>`, фокус — тонкое фиолетовое свечение,
  не золото — золото зарезервировано под покупку).
- Пилюля выбора линейки (тап → лист: сортировка + список линеек). Точка-индикатор
  цвета: конкретная линейка — сплошная точка её цвета; «Все линейки» — 3 мелкие
  точки внахлёст (НЕ единая conic-gradient точка — на 7px сливается в пятно).
  `max-width` + ellipsis, чтобы длинное имя не сжимало поиск.
- Кнопка-переключатель статуса (∅ все / ✓ куплено / 🔒 не куплено, тон фона
  меняется по состоянию), один тап циклит — не отдельный ряд чипов.
- Видимая высота всех трёх элементов ~28–32px (**не** `min-height:44px` на
  самом элементе — раздувает в «кирпичи», см. правило в DESIGN_RULES §4). Тап-зона
  ≥44px делается невидимым padding на родительской обёртке.

Заголовок каждой секции-слота — мини-измеритель (тот же язык, что в детальном
экране коллекции, только мельче) вместо текстовой пилюли.

Карточки предметов — свотч имитирует НАСТОЯЩИЙ эффект (светящийся текст для
ореола, кольцо-свечение для рамки — не плоская иконка-заглушка), тихий угловой
засвет цветом линейки предмета, 2 колонки (не 3 — на 3 эффект не считывается).

Пустое состояние фильтра — пунктирная рамка с приглушённой иконкой (не голая
строка текста, как было раньше).

## «Сейчас → Станет»

Полностью пересобрано — раньше два маленьких кружка-аватарки не показывали
реальное изменение дизайна.

- Компактная «Сейчас»-полоска сверху (не отнимает места).
- Большая «Станет» — **настоящая карточка**, с переключателем:
  - **«Как видишь ты»** — упрощённая личная карточка.
  - **«Как видят другие»** — честная копия РЕАЛЬНОГО `renderGlobalProfile()`
    (`app.06.js`, класс `.gp-card`, чипы `.gp-chip` «полного образа») — это
    существующая механика окна «Профиль игрока», не новый компонент с нуля.
    Изменённые (примеряемые) чипы подсвечены золотом.

## Покупка и «Образы»

Три способа купить, без скрытых побочных действий (4-й — «Купить всё
недостающее» — это НЕ дубль п.2, а отдельная кнопка внутри конкретной открытой
коллекции, см. предыдущий раздел; п.2 ниже относится к текущей ПРИМЕРКЕ у
превью и может включать предметы из разных линеек/слотов одновременно, тогда
как «Купить всё недостающее» — только предметы ОДНОЙ открытой линейки):
1. Поштучно (как сейчас, инлайн-плашка под превью).
2. **Весь примеренный образ разом** — новая кнопка у превью «Сейчас→Станет»,
   раскладка суммы (N предметов не куплено в текущей примерке × цены = итого).
3. **«Образы»** — единый горизонтальный ряд карточек, ОБЪЕДИНЯЮЩИЙ:
   - личные сохранённые пресеты игрока (метка `💾 твой`);
   - готовые кураторские сеты от линеек (метка с иконкой линейки, напр.
     `🔥 Инферно`) — заранее собранные комбинации, тап примеряет весь сет разом
     в превью (не покупает сразу).
   Раньше это были два разных места на странице (отдельный ряд пресетов +
   отдельная лента сетов) — объединены по решению владельца (одна и та же идея
   «названный набор, применяется в тап», просто источник разный). Карточка
   «Сохранить текущий» — плюсик в конце того же ряда.
   Аватар карточки — кольцо+засвет в цвете источника, не плоский серый круг.

## QoL-функции (все 6 подтверждены владельцем)

1. **Сортировка** внутри слота (по цене / алфавиту / сначала некупленное) —
   не отдельная кнопка в умном ряду, второй раздел в уже существующем листе
   выбора линейки.
2. **Избранное/вишлист** — звёздочка (☆/★) в углу карточки непокупленного
   предмета, кросс-слотовый счётчик-кнопка рядом с превью.
3. **«Удиви меня»** — кнопка рядом с превью, подставляет случайный набор из
   УЖЕ купленных предметов (не предлагает непокупленное — это примерка, не
   рулетка).
4. **Бейдж «Новое»** — пульсирующая золотая точка на карточке предмета и на
   чипе линейки, если внутри есть непросмотренная новинка.
5. **Экран-праздник за полную коллекцию** — триггер: куплен последний
   недостающий предмет линейки (N/N). Срежиссированное одноразовое появление
   (вспышка → медальон-пружинка → SVG-кольцо ЗАПОЛНЯЕТСЯ `stroke-dashoffset`
   от пусто до полного круга, тот же смысл что ring-прогресс на карточке
   коллекции → N искр по очереди, N = число предметов линейки → текст
   построчно), после чего остаётся только 2 бесконечных слоя (дыхание
   свечения + мерцание символа, как на обычной карточке — НЕ бесконечное
   вращение/множественные одновременные петли, см. уроки в DESIGN_RULES §4).
   Кнопки: «Надеть весь образ разом» + «Похвастаться в профиле» (ведёт к уже
   спроектированной публичной gp-card).
6. **Значок-уведомление на нижней навигации** — не новый UI-паттерн, донор —
   существующий канал «Что нового» 📣 (см. память `project_whatsnew_feed_location`),
   источник данных общий с бейджем «Новое» (п.4).

## «Вход» / «Темы»

Структуру не меняли (жалоб не было) — только визуальная согласованность:
та же «резная» глубина карточек (градиент фона + inset-тень), тот же стиль
чипов, что в умном ряду «По слотам». Иконки/orb получили цвет/свечение вместо
плоских серых кружков (orb приветствия светится изнутри, ярче на выбранном;
иконка темы берёт цвет из собственного акцента темы `t.accent`, не общий серый).

## Данные и бэкенд — что понадобится для реализации

Дизайн в основном фронтенд, но часть QoL требует новых данных:

- **Избранное/вишлист** — новое хранилище (таблица или JSON-поле), API
  добавить/убрать/получить список. Ничего похожего сейчас нет.
- **Бейдж «Новое»** — нужен способ определить «этот предмет/линейка новые для
  ЭТОГО игрока». MVP-вариант без личного трекинга: глобальный порог по дате
  добавления в каталог (проще, не требует новой таблицы per-user); полноценный
  вариант — переиспользовать механизм `web_notifications`/«Что нового».
  Решить при планировании, не изобретать здесь.
- **Готовые сеты линеек** — сами комбинации нужно где-то определить (новый
  словарь в `core/cosmetics.py`, например `LINEUP_LOOKS`, по 2–3 сета на
  линейку: id слотов → cosmetic_id). Контента пока не существует, его придётся
  либо сгенерировать по правилу (напр. топ-N по цене на слот), либо
  прописать вручную по линейке.
- **Экран-праздник** — детектируется на фронтенде (сравнение владения слота до/
  после покупки), backend-изменений не требует.
- **Публичная карточка в превью** — переиспользует существующий
  `renderGlobalProfile()`/`get_active_cosmetics()`, только с гипотетическим
  (примеряемым), а не сохранённым набором — фронтенд-задача, реальных данных
  для НЕ-своего профиля дёргать не нужно.
- **Сортировка/поиск/статус-фильтр** — чистый фронтенд, без изменений бэкенда.

## Явно отложено на будущее (НЕ делать в рамках этой реализации)

- **Поштучные цены** вместо одной цены на линейку — владелец считает текущую
  модель нелогичной (фон и титул не должны стоить одинаково), но прямо
  попросил отложить.
- **Разрыв визуального стиля с остальным приложением** (там всё ещё плоские
  эмодзи без анимации) — зафиксировано как задача на будущее, решение
  (подтягивать остальной интерфейс или сознательно оставить эту карточку
  «флагманом») не принято.
- **Уникальный игровой бонус за 100% сбора линейки** (не просто визуальный
  праздник, а реальный эффект/награда) — вопрос экономики, не дизайна, нужно
  отдельное решение владельца.

## Технический долг / открытые вопросы

- **`prefers-reduced-motion` / `no-fx`** — НЕ спроектировано. Проект уже
  уважает это в других местах этой же вкладки (см. `_looksJump()` в
  `app.10.js`). Для новых анимаций (иконки линеек, экран-праздник) нужно
  решить при реализации: что показывать вместо анимации (скорее всего —
  статичный последний кадр, без циклов).
- **Производительность** нескольких одновременно анимированных SVG на слабых
  устройствах — по прямому указанию владельца не учитывалась в дизайне,
  проверить на реальном устройстве при/после реализации, не как блокер сейчас.

## Что переиспользуется, а не изобретается заново

- Публичная карточка → `renderGlobalProfile()` / `.gp-card` (`app.06.js`).
- Slot-иконки (✨🖼🌟🏷🖌❄️) → уже используются по всему приложению, не новые.
- Правило «золото = действие/награда, не декорация» → из `DESIGN.md`.
- Правило «тонированного чипа» (альфа фона ~13%, не сплошная заливка) → из `DESIGN.md`.
- Значок-уведомление → существующий канал «Что нового».
