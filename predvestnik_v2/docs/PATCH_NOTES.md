# Патч-ноуты в официальный канал — правила для каждого, кто выпускает обновление

> **Обязательно для любой ИИ-модели и любого человека, который меняет Предвестника.**
> Выпуск, после которого игрок что-то заметит, не готов, пока в патч-ноут дня не добавлен пункт.
> Тест `tools/test_patch_notes_contract.py` не пропустит выпуск без него.

Канал: <https://t.me/predvestnik_official>, тема «Обновления»: <https://t.me/predvestnik_official/4>.
Бот: `@IIIPredvestnikIIIBot`. Отправляет **только создатель** кнопкой в админке (раздел «Патч-ноуты»),
после того как сам всё проверил и, если хочет, поправил текст и фото. Сами по себе посты не уходят никогда.

Это не «Что нового». «Что нового» (`FastAPI/static/updates.json`, `docs/WHATS_NEW_V3.md`) — подробная лента
внутри приложения. Патч-ноут — **короткий пост в канал на день**: главное, человеческим языком, с картинкой.

## Как это устроено

1. Выпуская обновление, ты добавляешь пункт в файл дня `FastAPI/static/patch-notes/ГГГГ-ММ-ДД.json`
   (дата — та же, что у записи «Что нового»). Файла нет — создай. Есть — допиши пункт в `items`.
2. Скриншот кладёшь в `FastAPI/static/patch-notes/img/` и указываешь в пункте. Нечего снять — `"image": "cover"`,
   бот нарисует фирменную обложку.
3. После выкладки создатель открывает админку → «Патч-ноуты», видит готовый пост ровно как в Telegram,
   правит что угодно (текст до буквы, фото, порядок, кнопку) и жмёт «Отправить».
4. Пост дня уже отправлен, а ты дописал пункт в тот же файл — он не потеряется: в админке появится
   отдельный пост-дополнение только с новыми пунктами.

Файлы и картинки не публичны до отправки: их читает только админка.

## Что попадает в патч-ноут, а что нет

| В пост | Не в пост |
|---|---|
| Новая игра, режим, раздел, предмет, скин, питомец, награда | Рефакторинг, тесты, логи, CI, документация |
| Заметное улучшение: удобнее, быстрее, понятнее, красивее | Изменения админки и инструментов персонала |
| Исправление, которое игрок замечал («раньше ломалось — теперь нет») | Исправление, которого игрок не мог заметить |
| Изменение баланса, цен, наград — честно, даже если игроку невыгодно | Внутренние названия, флаги, таблицы, файлы |

Запись «Что нового» без пункта в патч-ноуте допустима только с явной причиной в `skipped` (см. формат).
Например: функция выключена флагом и игроки её ещё не видят, или это техническая запись.

## Как писать: клиенто-адаптированно

Пишешь **для обычного игрока**, который открыл канал с телефона между делами.

- **Язык игрока, не разработчика.** Никаких «рефакторинг», «эндпоинт», «кеш», «флаг», «таблица», «фронт»,
  «WebSocket», «API», «баг в рендере». Не «оптимизировали загрузку ассетов», а «Сапёр открывается быстрее».
- **Польза первой.** Сначала что стало у игрока, потом где это найти. «Скин теперь виден и в чате: …».
- **Где искать — словами экрана.** «Игры › Ритм», «Профиль › Образы», «команда «бот я» в чате».
- **Коротко.** Пункт новинки — 1–3 предложения (до 420 знаков). Исправление — одна строка (до 170).
  Весь пост — до 4000 знаков; если меньше 1024 и одна картинка, он уйдёт подписью под фото — это лучше всего.
- **Без простыни.** Структуру собирает бот: заголовок дня, подводка, блоки новинок с эмодзи и жирным
  заголовком, блок «Исправили» списком (длинный список сам сворачивается). Ты пишешь только содержание.
- **Разметка Telegram внутри текста** — точечно: `<b>жирным</b>` команду или кнопку, `<i>курсив</i>`,
  `<tg-spoiler>`, `<a href="https://…">ссылка</a>`. Знаки `<` и `&` в тексте — как `&lt;` и `&amp;`.
- **Эмодзи** — одно в начале пункта (поле `emoji`), по смыслу: 🎮 игры, 🐾 питомцы, 🎨 образы, 🌳 семья,
  💬 чат, 🏆 топ, 🎒 инвентарь, ⚡ скорость. Не ставь эмодзи в каждое предложение.
- **Честно.** Не обещай того, чего нет, не преувеличивай («революция», «невероятно»). Ухудшение баланса
  называй прямо и объясняй зачем.
- **Без личных данных.** Ни ников, ни ID, ни сумм реальных игроков, ни скриншотов чужих профилей.
- **Тон** — дружелюбный и спокойный, на «вы» не обращаемся к каждому, а говорим о функции:
  «Теперь можно…», «Стало видно…». Без канцелярита («осуществлена доработка»).

Плохо: «Рефакторинг skins_chat: рамки через Unicode box-drawing, кеш по тиру».
Хорошо: «🎨 **Рамки скина в сообщениях бота** — со скином ответы бота о вас выглядят как карточка: разделы
в рамках из символов вашего скина. Наберите в чате <b>бот я</b>.»

## Картинки: тоже для игрока

- **Новинка (`new`) — картинка обязательна**: настоящий скриншот экрана или `cover`.
  Улучшение (`better`) — желательно. Исправление (`fix`) — никогда.
- Скриншот — **реальный интерфейс**, как его видит игрок на телефоне (ширина 390–430 px, Retina ×2–×3),
  тёмная тема, без отладочных панелей, без личных данных (тестовый персонаж стенда — можно).
  Обрежь до того, что показывает новинку; можно одну-две пометки (стрелка, обводка).
- Снять экран: локальный стенд `python tools/ui_stand.py --rich` + браузер (Playwright/Chromium) в эмуляции
  телефона, либо `python tools/ui_smoke.py --only <экран> --widths 390 --shots <папка>`.
- Формат: PNG или JPEG, 2 КБ–9 МБ, имя латиницей: `2026-10-21-skins-frames.png`. В `image_alt` — одной
  фразой, что на картинке (создателю для проверки).
- В посте до 10 картинок; больше одной — уйдут альбомом, а текст с кнопкой следом.

## Формат файла

```json
{
  "date": "2026-10-21",
  "headline": "Скины ожили в чате",
  "intro": "Сегодня обновление для тех, кто любит красивый профиль.",
  "button": "looks",
  "items": [
    {
      "id": "2026-10-21-skins-chat-frames",
      "kind": "new",
      "emoji": "🎨",
      "title": "Рамки скина в сообщениях бота",
      "text": "Со скином ответы бота о вас выглядят как карточка. Наберите в чате <b>бот я</b>.",
      "image": "2026-10-21-skins-frames.png",
      "image_alt": "Карточка «бот я» в рамке скина Пустота",
      "open": "looks",
      "covers": ["2026-10-21-skins-chat-frames"]
    },
    {"id": "2026-10-21-quest-reward-fix", "kind": "fix", "text": "Награда за квест больше не теряется при отмене удаления."}
  ],
  "skipped": [{"id": "2026-10-21-admin-thing", "why": "изменение только для персонала"}]
}
```

| Поле | Что это |
|---|---|
| `date` | день выпуска, `ГГГГ-ММ-ДД`; имя файла — та же дата (можно `ГГГГ-ММ-ДД-вечер`, латиницей) |
| `headline` | заголовок поста, до 70 знаков, без разметки: суть дня («Скины ожили в чате»), не «Обновление» |
| `intro` | необязательная подводка, до 240 знаков |
| `button` | раздел для кнопки под постом; нет — берётся `open` первой новинки, иначе «Открыть Предвестника» |
| `items[].id` | уникальный id пункта, обычно id записи «Что нового» |
| `items[].kind` | `new` новое · `better` улучшили · `fix` исправили |
| `items[].title` | заголовок пункта, до 80 знаков, без разметки (у `fix` не нужен) |
| `items[].text` | текст пункта с разметкой Telegram |
| `items[].image`, `image_alt` | файл из `img/` или `"cover"`; описание картинки |
| `items[].open` | раздел приложения, куда ведёт кнопка: `games pass looks quests pets top family inventory achievements zarniki vip settings news home` |
| `items[].flag` | ключ модуля, если функция за выключателем: админка предупредит, если он выключен |
| `items[].covers` | какие записи «Что нового» описывает пункт (по умолчанию его `id`) |
| `skipped` | записи «Что нового», которые сознательно не идут в канал, с причиной `why` |

Пределы и таблица кнопок — `core/patch_notes.py`; проверка — `services/patch_notes_format.py`.

## Чек-лист перед выпуском

1. Есть запись в «Что нового»? Значит есть пункт в патч-ноуте дня (или строка в `skipped` с причиной).
2. Текст прочитан глазами игрока: нет ни одного технического слова, понятно, где искать.
3. У новинки есть картинка, и на ней нет личных данных.
4. `python tools/test_patch_notes_contract.py` — зелёный.

## Где что в коде

| Файл | Что |
|---|---|
| `core/patch_notes.py` | пределы, кнопки, адрес канала (через `core/official_updates.py`) |
| `services/patch_notes_format.py` | проверка файла и разметки, сборка текста поста |
| `services/patch_notes_images.py` | обложка и чистка загруженных фото (EXIF, размер) |
| `services/patch_notes.py` | черновики из файлов, правка, отправка с защитой от дублей, сверка |
| `services/patch_notes_send.py` | как пост уходит в Telegram (текст / фото с подписью / альбом + текст) |
| `infrastructure/repositories/patch_notes.py` | таблицы `patch_notes`, `patch_note_uploads`, `official_update_topic` |
| `FastAPI/routers/bot_admin/patch_notes.py` | API раздела, только создатель |
| `FastAPI/static/bot-admin/admin-patchnotes*.js` | экран админки: список, редактор, предпросмотр, отправка |
| `tools/test_patch_notes_contract.py` | формат всех файлов и покрытие «Что нового» |
| `tools/test_patch_notes_pg.py` | черновики, правки, дополнения, отправка и сверка на настоящем PostgreSQL |

Отправка: только из production, только рабочим ботом, только если бот — админ группы с темами и уже видел
сообщение в теме. Повтор нажатия не шлёт дубль; потерянный ответ Telegram блокирует новые отправки до
ручной сверки («Пост есть» / «Поста нет»). Если Telegram отказал на середине (альбом ушёл, текст нет),
бот сам удаляет отправленные части.
