# Вылазка с питомцем — тренировочный запуск

Ветка `codex/pet-practice`, база `fcecff0d`. Это клиентская тренировка,
доступная при включённом `pets_v2`. Публикация в production этим документом
не подтверждается.

## Пользовательский контракт

- Вход: Питомцы → Ещё → Вылазка или карточка конкретного питомца.
- Питомец может быть занят долгим заданием и иметь нулевую энергию.
- Сила, здоровье и два рывка здесь тренировочные. Реальная сборка пока не влияет.
- Никаких наград, расходов, зачёта квестов или изменения долгих заданий.
- Три цели, три варианта местности, родник/эхо, дневники, связанные печати,
  прогноз намерений врагов, чутьё по направлениям и маршрут по известной тропе.
- Враги отвечают только после действия игрока. Осмотр и обдумывание бесплатны.
- Маяк: свободный выбор пути либо обязательная линза от стража/сундука.
  Рекорды разделены по правилам, цели, seed, местности и выбранному/фактическому пути.
- Сохранение локальное, отдельное для аккаунта и питомца. Между устройствами
  не синхронизируется. Выход во время ответа врагов откатывает незавершённый ход.
  При запрете storage доступна память текущей страницы с видимым предупреждением.

## Границы реализации

`app.48.js` проверяет `/profile/me` и `/pets-v2/me` с неизменившимися credentials.
В ребёнка передаются только имя/значок питомца и локальный снимок игры.
`sandbox="allow-scripts"` не даёт игре доступ к origin/credentials/storage родителя.
Сообщения проверяются по source, origin, nonce, поколению запуска и последовательности.
Снимки ограничены 16 KiB. Дочерний CSP запрещает connect-src, формы и изображения;
вложенная цепочка Telegram Web разрешена только для `web.telegram.org`.
Host принимает сообщения только от родителя с origin URL документа игры.
Фоновые перерисовки питомцев сохраняют существующий iframe.

`pet-practice-game.js` содержит механику; host адаптирует сохранения и значки,
`pet-practice.html/css` — отдельный документ. `main.py` явно разрешает только
три нужных статических ресурса и включает их в content hash. Новых SQL/API writers нет.

## Воспроизводимая проверка

Из корня checkout:

```powershell
node predvestnik_v2/tools/test_pet_practice.cjs
# NODE_PATH должен указывать на установленный пакет playwright.
node predvestnik_v2/tools/test_pet_practice_browser.cjs
```

Браузерный тест использует установленный Edge; другой channel задаётся
`PRACTICE_BROWSER`. Все HTTP-запросы — локальный fixture. Синтетическая цепочка
`web.telegram.org → practice.invalid → sandbox` исполняет настоящий CSP без
обращения к этим внешним сайтам. Это не ручная проверка Telegram-клиента.

Проверяются реальные 36 политик прохождения, восстановление между ходами,
разделение рекордов, альтернативные пути, busy-питомец, opaque origin/CSP,
незавершённый ход, повторное открытие/refresh/reload, поздние ответы при смене
аккаунта, появление login overlay и недоступный storage.

ASGI static delivery, public routes, Trail contract, What's New contract,
чистые правила питомцев и PostgreSQL flow проверяются существующими tools.
Полный `ui_smoke.py` содержит `trail-practice` и `trail-practice-picker`.
В init-script тестового раннера storage настраивается только у верхнего документа:
opaque game frame по контракту не имеет localStorage.

Политики — доказательства существования проходимых маршрутов, не доказательство
оптимальности или идеального баланса. Сохранение редактируемо пользователем:
это допустимо только пока игра не связана с настоящими наградами.

## Следующая экономическая версия

Награды, влияние реальных характеристик, серверные рекорды и квесты требуют
отдельного согласования и серверного состояния/валидации. Нельзя подключать
их простым доверием к локальному `won` или localStorage.
