# Первый видеопилот Предвестника

## Новая версия после замечаний владельца

Первый файл ниже **отклонён владельцем как слайд-шоу**. Новая версия:
`out/motion_v2/predvestnik_motion_v2.mp4`, 18 секунд, 1080×1920, 30 fps.
Постановочный сюжет «12 сообщений. Кикаем?» → человек на смене →
индивидуальное решение в настоящей панели → остаётся в чате.
Анимированные сообщения, непрерывное движение камеры/курсора, смена состояния
fixture после клика, локальная русская синтетическая озвучка Pavel,
оригинальные бит и эффекты. Это демонстрация; реальные действия не выполняются.

Сборка из этого каталога:

1. PowerShell: `./narrate_motion.ps1` — озвучка установленным Windows OneCore Pavel.
2. Python с Pillow/numpy/imageio-ffmpeg: `python render_motion.py`.

`--preview-only` создаёт раскадровку. `out/motion_v2/verification.json` фиксирует
полное декодирование без ошибок и отсутствие пересечений голосовых фраз.
Удержание не измерялось. Раскадровка проверяет композицию, но не доказывает
успешность монтажа; синтетическую озвучку нужно оценивать при воспроизведении.

## Отклонённая первая версия

`out/predvestnik_cleanup_pilot.mp4`: 19 секунд, 1080×1920, 24 fps, H.264/AAC.
Сюжет: бот готовит кандидатов; администратор оставляет одного и предупреждает другого.

Это **демонстрация**, не запись production. Интерфейс взят из неизменённого
`FastAPI/static/app.07.js::loadPurgePanel` и текущего CSS; ответы API — вымышленные
fixtures, участники ненастоящие. Telegram и рабочая БД не вызываются. Постоянная
пометка в ролике поясняет источник. Музыки и голоса нет; звуки синтезированы нами.

Сборка:

1. Node.js + Playwright; `PREDVESTNIK_PLAYWRIGHT` при необходимости указывает путь
   к модулю. Браузер Edge запускается headless, без пользовательского профиля.
2. Python + Pillow + imageio-ffmpeg (`.runtime/` исключён из Git).
3. `node capture_cleanup.cjs`
4. `python render_cleanup.py --preview-only` — раскадровка для проверки.
5. `python render_cleanup.py` — полный MP4.

Сценарий и оригинальная звуковая дорожка определены в `render_cleanup.py`.
Файлы capture_manifest и pilot_manifest фиксируют источник UI и состояние ролика.
До публикации владелец должен просмотреть итог и подтвердить актуальность
username/брендинга и пригодность демонстрационной подачи. Самостоятельной публикации нет.
