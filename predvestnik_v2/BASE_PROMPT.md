# PREDVESTNIK V2 — BASE PROMPT

Ты работаешь над `predvestnik_v2` — Telegram-бот + Django веб-панель (игровой бот с экономикой, питомцами, браком, модерацией). Придерживайся следующих принципов без исключений.

---

## АРХИТЕКТУРА — ЗАКОН СЛОЁВ

```
core/           ← константы и реестры. Нет внешних зависимостей.
services/       ← бизнес-логика. Нет импортов из bot.* или django.*
infrastructure/ ← репозитории БД (aiosqlite). Только SQL, нет логики.
bot/            ← адаптер Telegram. Handlers → services + infrastructure.
dashboard/      ← адаптер Django. Views → core + services + infrastructure.
```

**Железные правила:**
- `services/` и `infrastructure/` никогда не импортируют из `bot.*` или `django.*`
- Новая DB-операция → только `infrastructure/repositories/*.py`
- Новая бизнес-логика → только `services/*.py`
- Handler — только UI: форматирование, вызовы, отправка ответа

---

## КАК ПИСАТЬ КОД

**Функции, не классы.** В `services/` используй только standalone async-функции с `db` первым аргументом. Классы-сервисы (типа `class AdminService`) — не допускаются.

**Инъекция конфига.** `developer_id` и `timezone_offset` — всегда параметры функций (`developer_id: int = 0`), не читаются из конфига внутри services/. ConfigMiddleware (`bot/middlewares/config_mw.py`) инжектит их через `data["developer_id"]`.

**Импорты.** Только вверху файла. Никаких инлайн-импортов внутри функций. Никаких дублей. Удаляй неиспользуемые.

**Комментарии.** Только если WHY неочевиден (скрытый инвариант, обход бага, нелогичное поведение). Не описывай ЧТО делает код — это видно из имён.

**Константы.** Все игровые числа — только в `core/constants.py`. Хардкод числа в handler = ошибка.

**Плавающая точка.** `int(mora * MULT) - mora`, НЕ `int(mora * (MULT - 1.0))`.

**Tree-форматирование.** Последний элемент всегда `└`, промежуточные `├`. Правильно: `text[:text.rfind("├")] + "└" + text[text.rfind("├")+1:]`. НЕ используй `text[-2:].replace(...)` — это ломается на многобайтовых символах.

**Деструктивные действия** (удаление питомца, развод, бан) — всегда через диалог подтверждения с кнопками ✅/❌.

**Время экспедиций** показывай как `"X ч. Y мин."`, не `"X.Y ч."`.

## СИСТЕМА ПИТОМЦЕВ — КАК РАСШИРЯТЬ

### Добавить нового питомца
1. `core/registry.py` → добавить в `PET_SPECIES`: `{"name": "...", "rarity": "...", "default_role": "active/passive", "desc": "..."}`
2. `core/constants.py` → константа для бонуса: `CAT_SAVE_CHANCE: float = 0.15`
3. Бонус → в нужный сервис (таблица ниже)
4. Описание в `desc` должно точно описывать механику (из него игрок понимает бонус)

### Где реализовывать бонус питомца
| Тип бонуса | Файл | Способ |
|---|---|---|
| Мора/XP/алмазы/скорость экспедиции | `services/expedition.py` → `calculate_reward()` | параметр `has_X: bool, X_level: int` |
| Усталость (суточный прирост) | `infrastructure/repositories/zoo.py` → `apply_fatigue_decay()` | добавить в блок wolf/unicorn |
| Кормление питомца | `bot/handlers/zoo.py` → `cb_zoo_feed_all()` | после основного цикла |
| XP от сообщений | `services/leveling.py` | проверка `has_active_species` |
| Экономика (магазин/баланс) | `services/economy.py` | |
| Модерация | только с явного разрешения | крайний случай |

### Обязательные паттерны при реализации
```python
# 1. Проверка наличия питомца — ВСЕГДА через get_active_species_level
level = await get_active_species_level(db, user_id, "species_id")  # 0 = нет/устал
if level > 0:
    mult = get_level_multiplier(level)  # из core.constants
    bonus = BASE_BONUS * mult

# 2. Добавление параметра в calculate_reward
def calculate_reward(..., has_species: bool = False, species_level: int = 1) -> dict:
    if has_species:
        mult = get_level_multiplier(species_level)
        ...

# 3. Новая константа — в core/constants.py, не хардкод
SPECIES_BONUS: float = 0.15  # всегда именовано

# 4. Новая колонка — в bot/core/database.py
new_schema_columns = [
    ...
    ("table_name", "column_name", "TYPE DEFAULT value"),
]
```

### `calculate_reward()` — соглашение о сигнатуре
- Принимает `has_X: bool, X_level: int = 1` для каждого питомца-бонусника
- Scheduler (`services/scheduler.py`) запрашивает уровни через `get_active_species_level` и передаёт их
- Никогда не делает DB-запросы — только математика
- Всегда возвращает `{"mora": int, "xp": int, "diamonds": int, "buff_message": str}`

## АНТИ-АБЬЮЗ — ОБЯЗАТЕЛЬНАЯ ПРОВЕРКА ПЕРЕД РЕАЛИЗАЦИЕЙ

Перед добавлением любой новой механики пройди этот список. Если хоть один пункт «да» — или добавь защиту, или откажись от механики.

### ❌ Запрещённые паттерны

| Паттерн | Пример злоупотребления | Что делать |
|---|---|---|
| Бонус с каждого перевода | +3% с перевода → альт-ферма | Запрещено. Убрать. |
| Бот пишет в ЛС без подписки | "покажи подсказку в ЛС" → спам | Запрещено. Только через `user_notifications` таблицу с явным opt-in |
| Автоотмена бана/мута | Феникс-автобан → обход модерации | Запрещено. Смягчение — можно (1 предупреждение прощает), автобан — нельзя |
| Бонус за каждое сообщение кого угодно | Кракен: все пишут → -1 усталость | Только если источник: `messages_all_time > 50` в этом чате |
| Квест "совершить перевод" | Фарм переводами с альта | Если нужен: минимум 200 Моры + получатель ≠ ты + max 1 зачёт в сутки с одного человека |
| Автоответ/первый нажавший | Викторина → автокликер | Только текстовый ввод с проверкой содержания, не кнопка |
| PvP-ставка без ограничений | Дуэль как способ передать мору без комиссии | Ставка ≤ 500 Моры, кд с одним игроком 24ч |

### ✅ Безопасные паттерны

- **Пассивный доход** — всегда с CAP и ручным сбором (никогда автозачисление)
- **Активность** — квесты на сообщения, экспедиции, открытие яиц — трудно абьюзить
- **Уведомления** — только по явной подписке: `бот уведомления вкл.`
- **Временные бонусы** — с явным cooldown в `core/constants.py`
- **Комиссия с торговли** — 2–5% идёт в "банк чата", не возвращается ни одной стороне

## НА ЧТО ОБРАЩАТЬ ВНИМАНИЕ ПРИ ИЗМЕНЕНИЯХ

1. **Добавляешь новую константу?** → `core/constants.py`, не хардкод.
2. **Добавляешь новый DB-запрос?** → новая функция в `infrastructure/repositories/`, не raw SQL в handler.
3. **Добавляешь бизнес-правило?** → `services/`, проверь что не импортируешь `bot.*`.
4. **Новый handler?** → принимает `developer_id: int = 0` если нужны права, `db` для БД.
5. **Деструктивное действие?** → добавь подтверждение через InlineKeyboard.
6. **Форматируешь список?** → последний элемент через `rfind("├")`, не `[-N:]`.
7. **Время/даты?** → храни в UTC, показывай с учётом `timezone_offset`.

## ДИЗАЙН-СИСТЕМА БОТА (соблюдай везде)

**Заголовки сообщений** — всегда формата:
```
<emoji> <b>НАЗВАНИЕ В CAPS</b>
```
Пример: `🐾 <b>ПИТОМНИК:</b> {username}`

**Разделы внутри сообщения** — отделены пустой строкой, заголовок раздела жирным CAPS с emoji:
```
🌐 <b>СТАТУС И ОТНОШЕНИЯ</b>
├ 🌍 Глобально: <b>X</b>
└ 🏘️ В чате: <b>Y</b>
```

**Деревья** — `├` для всех кроме последнего, `└` для последнего. Замену делать через `text.rfind("├")`.

**Числовые значения** — в `<code>...</code>` (моноширинно).
**Имена** — жирным `<b>{safe_html(name)}</b>`.

**Кнопки** — emoji в начале текста, действие глаголом:
```
✅ Согласиться | ❌ Отказаться | 🔥 Отпустить
🛡 Защитить    | ⚔️ Атаковать  | 🔙 Назад
```

**Ошибки** — единый формат: `❌ <b>Отказ:</b> {причина}` или `❌ {описание одной строкой}`.

**Подсказки** — `ℹ️ <b>Использование:</b> <code>/cmd [args]</code>\n{пояснение}`.

**Успех** — `✅ {сообщение}` или `🎉 <b>...</b>` для значимых событий (брак, level-up).

**Пустое состояние** — `<i>{описание + что сделать}</i>`. Не показывай голый блок.
