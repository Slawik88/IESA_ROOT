# BATTLE_VFX_CONCEPT.md — визуальная динамика Боёвки 3.0 (блок 2 «улучшения боя»)

**Статус:** согласовано с пользователем 2026-07-10, реализуется в этой же сессии.
**Баланс не трогается** (ни одно число урона/шанса не меняется). Но, как выяснилось
при реализации, бэкенд всё же нужно тронуть по мелочи: `state.log`/`turn` сейчас
хранят урон только внутри готовой ТЕКСТОВОЙ строки лога («⚔️ Змей бьёт Голема: −42»)
— структурированного «кто кого на сколько ударил» нигде нет, а парсить русский текст
с эмодзи на фронте — плохая идея (хрупко, ломается при любой правке текста лога).
Поэтому `services/battle3.py` получает маленький параллельный список `hits_round`
(накопление в том же месте, где сейчас пишется строка лога — `_apply_damage`),
который роутер прозрачно домешивает в уже существующий `{"turn": res}` как новое
поле `hits`. Это ЧИСТО ДОБАВЛЕНИЕ (доп. read-only телеметрия одного раунда для
визуала), ничего из существующей логики/расчётов не меняется и не переставляется.

## Зачем

Пользователь: «Система боёвки, сделай её динамичней! используй красивые анимации,
экшен анимации, изменяй экран при каких-то действиях». Согласован уровень —
**умеренно**: чёткий фидбек на каждое действие, не отвлекающий от тактики (руны/цель
должны читаться так же легко, как сейчас).

## Текущее состояние (для контекста)

Уже есть: `bt-flash`/`bt-flash-{perfect,good,miss}` (вспышка, но только на QTE-грейд,
не на обычные ходы), `bt-ring` (кольцо QTE на крит/ульту), `b3-ult-btn` (пульс при
готовой ульте — уже уважает `no-fx`), плавный переход ширины rage-бара.

Нет вообще: фидбека на обычную атаку/руну без QTE (большинство ходов боя), чисел
урона, анимации смерти юнита (сейчас мгновенный `opacity`/`grayscale` без перехода),
акцента на экране победы/поражения (сейчас просто текстовая строка в общей вёрстке).

Известный пробел: `bt-flash`, переход rage-бара и QTE-кольцо **сейчас не уважают
`body.no-fx`/`prefers-reduced-motion`** — только `b3-ult-btn` и `.zc-*` это делают.
Чинится в этом же блоке заодно (тот же принцип применяется ко всем battle-анимациям
разом, не только к новым).

## Цветовая схема по стихии юнита

Новая, нигде раньше не существовала как единая палитра. Значения подобраны так, чтобы
не спорить визуально с уже занятыми акцентными цветами (`--gold`/`--green`/`--red`
у существующих QTE-грейдов и currency-бара):

| Стихия (`core/units.py::ELEMENTS`) | Эмодзи | Цвет |
|---|---|---|
| `fire` | 🔥 | `#ff7a3d` |
| `ice` | ❄️ | `#5fc6ff` |
| `storm` | ⚡ | `#f7e04a` |
| `earth` | 🪨 | `#a97c50` |
| `dark` | 🌑 | `#7a3bd6` (тон уже занят у `.frame-abyss`/`.halo-void` — переиспользуем, не изобретаем новый) |

Новая JS-константа `B3_ELEMENT_COLORS` в `app.11.js` (или рядом, там где уже есть
похожие мелкие константы этого файла) — `{fire:'#ff7a3d', ice:'#5fc6ff', ...}`.

## VFX 1 — Обычная атака/руна (без QTE)

Сейчас: `_btRender` просто перерисовывает карточки после каждого раунда, разницы
между «до» и «после» визуально не видно, кроме изменившихся чисел HP/лога.

Новое: после каждого ответа с `turn.hits` (round/qte/ult), ДО полного `_btRender`, для
каждого хита с известным `src_side`/`src_i` на карточке атакующего юнита на секунду
включается класс `b3-act-pulse` (короткий scale-pulse,
цвет обводки = цвет стихии атакующего, через inline `style="--el-color:..."`, т.к.
цвет динамический и в статичный CSS-класс на 5 стихий его заводить избыточно — один
keyframe, один CSS custom property). На карточке цели — `b3-hit-shake` (лёгкая тряска,
~0.3s) + `bt-flash`-подобная вспышка, но окрашенная в цвет стихии атакующего вместо
текущих трёх грейд-цветов (эта вспышка используется ТОЛЬКО для обычных ходов; QTE
по-прежнему красит вспышку по грейду — свой смысл, не путаем).

## VFX 2 — Числа урона

Новый элемент `<div class="b3-dmg-num">-{urон}</div>`, появляется поверх карточки
цели в момент нанесения урона, всплывает вверх на ~24px и гаснет за ~0.6s (`ease-out`).
Цвет — цвет стихии атакующего (VFX1). Криты — `b3-dmg-crit` модификатор: крупнее
шрифт + золотой цвет (переиспользует `var(--gold)`, тот же язык, что у
`bt-flash-perfect`).

Источник числа: новое поле `turn.hits` (см. вводную секцию про `hits_round`) — список
`{side, i, dmg, elem, crit, src_side, src_i}` за раунд/под-шаг (`side`/`i` — кто
получил урон, `src_side`/`src_i` — кто его нанёс, `None` для DoT-статусов вроде
ожога без живого источника в моменте). Фронт по каждому элементу выпускает один
`b3-dmg-num` над карточкой цели (`side`+`i` — те же координаты, что уже использует
`state.enemy.units[i]`/`state.ally.units[i]` для рендера карточек) и, если есть
`src_side`/`src_i`, применяет VFX1 (пульс) к карточке атакующего.

## VFX 3 — Смерть юнита

Сейчас: `.b3-dead { opacity:.3; filter:grayscale(1); }` — применяется мгновенно,
без transition, в `_btRender` при перерисовке.

Новое: `.b3-card` получает `transition: opacity .4s ease, filter .4s ease,
transform .4s ease`, `.b3-dead` дополнительно к текущим `opacity`/`grayscale` получает
`transform: translateY(4px)` — лёгкое «оседание» вместо чистого затемнения. Никакой
новой JS-логики не нужно — класс `b3-dead` уже навешивается по `!u.alive`, transition
на уже существующем CSS-переключении отрабатывает сам.

## VFX 4 — Экран победы/поражения

Сейчас: `headHtml` — просто `<div class="skg-head skg-won/lost">`, статичный текст
в общей вёрстке `.b3-mid`.

Новое: при первом рендере состояния `finished` (win/lost) — на `.b3-ov` (весь оверлей
арены) на один цикл вешается класс `b3-outcome-won`/`b3-outcome-lost`: цветная вспышка
через весь экран (`::before` слой поверх, `radial-gradient` золотой/тёмно-красный,
инициальная `opacity:1`→`0` за ~0.6s), затем гаснет и остаётся обычный статичный
`headHtml`-баннер, как сейчас. Это ПЕРВЫЙ кадр момента, не постоянное состояние —
исход должен ощущаться мгновенно, но не мешать читать итоговый экран/лог после.

## `no-fx` / `prefers-reduced-motion`

Единое правило для ВСЕХ анимаций этого блока плюс трёх существующих гэпов
(`bt-flash`, rage-бар, `bt-ring`): при `body.no-fx` или системном
`prefers-reduced-motion: reduce`, каждая анимация переключается на **мгновенное
состояние без движения**, а не убирается совсем:
- `b3-act-pulse`/`b3-hit-shake` → `animation: none` (обводка/вспышка событие всё
  равно происходит на 1 кадр через class toggle, просто без плавности/тряски).
- Числа урона (`b3-dmg-num`) → появляются и пропадают без подъёма/фейда
  (`animation: none`, просто `opacity` дискретно на короткий `setTimeout`).
- Смерть юнита → `transition: none` (было — мгновенно, останется мгновенно).
- Победа/поражение вспышка → `animation: none` (полностью убирается — единственное
  исключение, т.к. это буквально ОДНОКРАТНАЯ decorative вспышка без информационной
  нагрузки, а не постоянный статус-индикатор вроде остальных).
- Retrofit: `bt-flash`, rage-бар transition, `bt-ring` — те же правила, что уже
  применены к `.b3-ult-btn`/`.zc-*` (см. текущие блоки `@media(prefers-reduced-motion)`
  + `body.no-fx` в `app.css` ~2412-2413/2449-2450) — просто расширяем список
  селекторов в уже существующих блоках, не создаём новые.

## Файлы

- `services/battle3.py` — `hits_round` список: накопление в `_apply_damage` (единая
  точка, куда уже стекается весь урон — `_exec_attack`/`_exec_skill`/enemy-фаза все
  идут через неё), `state.pop("hits_round", [])` во всех точках возврата
  `_process_queue`/`_finish_round`/`resume_qte`/`request_ult` (там же, где сейчас
  флашится `events_round`→`log` — тот же жизненный цикл, один раунд может дать
  несколько ответов клиенту из-за QTE-пауз, каждый должен нести СВОИ хиты, не всё
  накопленное с начала раунда).
- `FastAPI/routers/battle.py` — `res["hits"]` уже приходит из `b3.play_round`/
  `resume_qte`/`request_ult` как часть `res`, роутер ничего доп. не делает (`{"turn":
  res}` и так прокидывает всё, что вернул сервис).
- `FastAPI/static/app.css` — новые keyframes (`b3ActPulse`, `b3HitShake`,
  `b3DmgFloat`, `b3OutcomeFlash`), классы `.b3-act-pulse`/`.b3-hit-shake`/
  `.b3-dmg-num`/`.b3-dmg-crit`/`.b3-outcome-won`/`.b3-outcome-lost`, transition на
  `.b3-card`/`.b3-dead`, расширение существующих `no-fx`/`reduced-motion` блоков.
- `FastAPI/static/app.11.js` — `B3_ELEMENT_COLORS`, триггер новых классов в
  `_btRender`/`_b3Api` по данным `turn.hits` (после каждого раунда/qte/ult/triad-
  ответа), вставка/удаление `b3-dmg-num` элементов, разовый `b3-outcome-*` класс при
  первом рендере `finished`.

## Проверка результата

- `node --check` на `app.11.js` + полная склейка всех 11 частей.
- Playwright на статик-стенде не подходит для живой боёвки (сложное состояние —
  руки рун, HP, ярость; поднимать полноценный мок боя ради CSS-анимаций избыточно
  для этого блока) — проверка вручную в браузере: обычный ход → пульс атакующего +
  тряска+вспышка цели по цвету стихии; смерть юнита → плавное оседание, не мгновенный
  скачок; победа/поражение → цветная вспышка на первом кадре; включить «Отключить
  анимации» в Настройках → все эффекты остаются как мгновенная обратная связь
  (класс/цвет меняется), но без движения/пульса/подъёма чисел.
