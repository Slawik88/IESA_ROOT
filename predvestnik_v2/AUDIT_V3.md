## 🔴 БАГ-1 — Сундук: "cannot start a transaction within a transaction"

**Симптом:** При нажатии кнопки сундука — ошибка в консоли, пользователь не получает награду.

**Лог:**
```
ERROR | bot.handlers.events:cb_chest_claim:128 - 
Chest claim error: cannot start a transaction within a transaction
```

**Корень:** `cb_chest_claim` делает `await db.execute("BEGIN IMMEDIATE")`, но middleware
(`streak_mw`, `pet_bonuses_mw`) уже открыл неявную транзакцию на том же соединении.
В aiosqlite вызов `BEGIN` внутри активной транзакции → исключение.

**Доп. проблема:** callback_query события также проходят через `db_middleware` и вызывают
`leveling.process_message_xp` (так как `event.message` у колбэков ТОЖЕ установлен — это
сообщение, к которому прикреплена кнопка). Это значит:
- Пользователь получает XP за КАЖДОЕ нажатие любой инлайн-кнопки
- Стрики срабатывают от кнопок
- Это отдельный критический баг экономики (см. БАГ-2)

**Файлы:** `bot/handlers/events.py` → `cb_chest_claim`, `bot/middlewares/db.py`

**Фикс:**
1. В `cb_chest_claim` убрать `BEGIN IMMEDIATE`, заменить на INSERT OR IGNORE + проверку количества
2. В `db_middleware` добавить проверку: выдавать XP только если это настоящее сообщение от пользователя, а не callback:
   ```python
   # В db_middleware — проверять что это Message, не CallbackQuery
   from aiogram.types import Message as TgMessage
   if user and chat_obj and isinstance(event, TgMessage):
       await leveling.process_message_xp(...)
   ```

## 🔴 БАГ-2 — XP за клики кнопок (экономика сломана)

**Симптом:** Каждое нажатие инлайн-кнопки выдаёт XP пользователю как за сообщение.
Пользователи могут бесконечно кликать на кнопки гачи/аукциона/зоопарка и набирать уровни.

**Корень:** В `db_middleware` проверка `if user and chat_obj and event.message:` срабатывает
для callback_query потому что `event.message` у колбэков = сообщение с кнопками (не None).
Левелинг, стрики, квесты — всё срабатывает от кнопок.

**Файлы:** `bot/middlewares/db.py`

**Фикс:**
```python
from aiogram import types as aiogram_types
# Заменить:
if user and chat_obj and event.message:
# На:
if user and chat_obj and isinstance(event, aiogram_types.Message):
```

**Экономический ущерб от этого бага:**
- Пользователь может нажимать кнопку "🔄 Обновить" в акции → бесконечный XP
- Стрики засчитываются от кнопок, а не от реальных сообщений
- Квесты `messages_in_chat_today` могут выполняться от кликов

## 🔴 БАГ-3 — `бот ранг, @юзер` не работает с пробелом

**Симптом:**
```
Пользователь: Бот ранг , @Buy_me_Acoffee 5
Бот: ❓ Команда бот ранг не найдена. Возможно, вы имели в виду: бот ранг
```

**Корень:** `WrongSyntaxCmd` фильтр проверяет `clean_text.startswith(alias + " ")` но
если пользователь написал `ранг ,` (пробел перед запятой), ни `WrongSyntaxCmd` ни
`TextCmd` не матчит. Запрос падает в `unknown_cmd_router` с `bot_cmd_text = "ранг"`.

**Файлы:** `bot/filters/text_commands.py`

**Фикс:**
В `TextCmd.__call__` нормализовать пробелы вокруг запятой:
```python
clean_text = text[3:].lstrip(" ,.").strip()
# Нормализуем "ранг , @юзер" → "ранг, @юзер"
clean_text = re.sub(r'\s*,\s*', ', ', clean_text)
```

## 🟡 БАГ-4 — `бот dev баланс` неправильный синтаксис

**Симптом:**
```
Пользователь: бот dev баланс, @Buy_me_Acoffee мора 99999999
Бот: ✅ Баланс установлен ... Мора: 0.00
```

**Корень:** Команда ожидает `@ник, [мора], [алмазы]` (через запятые), но пользователь
написал `@ник мора 99999999` без запятых. Парсинг `parts = [p.strip() for p in text_args.split(",")]`
возвращает `["@Buy_me_Acoffee мора 99999999"]` → мора и алмазы берутся из отсутствующих частей = 0.

**Файлы:** `bot/handlers/dev.py` → `cmd_dev_balance`

**Фикс:**
1. Более гибкий парсинг (принимать числа без запятых)
2. Добавить понятное сообщение об ошибке с примером

## 🟡 БАГ-6 — Help tabs не переключаются (кешированные сообщения)

**Симптом (из лога):** Разные пользователи после разных команд получают разные вкладки
(экономика, статистика), хотя нажимали просто `бот помощь`.

**Корень:** `бот помощь` определяет начальную вкладку. Но колбэк `HelpCallback(tab=X)` показывает
конкретную вкладку, выбранную в меню. Если у пользователя открыта СТАРАЯ клавиатура
со старым `tab` параметром — она продолжает показывать старый контент. Не баг сам по
себе, но запутывает.

```

```
