# Правила оформления карточек коллекций косметики

Родилось из ~6 раундов визуальных итераций (брейншторм 2026-07-29, редизайн вкладки
«Внешний вид»). Цель файла: при добавлении НОВОЙ линейки/коллекции агент делает
правильный дизайн с первого раза, без переспрашивания владельца. Каждое правило —
результат конкретной поправки, не абстрактный вкус.

## 0. Где что применяется

- **Медальон-иконка** — на карточке коллекции (56px) и в шапке открытой коллекции (74px+, там она «герой» экрана, крупнее).
- **Кольцо-прогресс** — только на карточке коллекции, вокруг медальона.
- **Сегментный измеритель** — только в шапке открытой коллекции (детальный экран).
- **Полоска слот-иконок** — и на карточке, и (в виде сетки плиток) в детальном экране.

Эти три индикатора прогресса **не взаимозаменяемы** — каждый отвечает на свой вопрос
и должен присутствовать на своём месте, не подменяя другой:
- Кольцо = «сколько в процентах», беглый взгляд, даже не открывая коллекцию.
- Сегментный измеритель = «сколько именно штук», когда уже открыл коллекцию.
- Полоска слотов = «КОНКРЕТНО каких слотов не хватает» — самая точная деталь.

## 1. Иконка-сигиль линейки

- Свой inline SVG, **не эмодзи**. Голый эмодзи в медальоне читается дёшево — владелец
  явно забраковал первую версию за это.
- `viewBox="0 0 24 24"` — общий масштаб на все иконки набора.
- Толщина линии контуров ~1.1–1.3px, одинаковая на всех иконках — иначе набор не
  читается как гарнитура.
- Заливка **всегда через градиент** (linear/radial), не плоский однотонный цвет —
  плоская заливка = «дёшево». Пример: `linearGradient` светлый край → тёмный, имитация
  света сверху.
- Иконка обязана иметь **минимум 2 слоя движения**:
  1. сам символ анимирован (мерцание/покачивание/пульс/вращение);
  2. что-то ЕЩЁ движется/светится ВОКРУГ символа (частицы/искры/угли/лучи).
  Одна плоская форма или простой цикл «туда-обратно» в 2 кадра — недостаточно,
  владелец явно просил «залипающие» анимации.
- Анимация — **3+ фазы**, не только A→B→A (иначе выглядит как метроном). Тайминги
  между разными иконками **расфазированы** (разная длительность/задержка), чтобы
  несколько карточек на экране не мигали синхронно.
- У каждой иконки — своя игровая «личность», не абстрактная геометрия ради
  геометрии. Уже придуманные примеры (переиспользовать логику для новых линеек):

  | Линейка | Символ | Слой движения №2 |
  |---|---|---|
  | 🌲 Лесной Странник | 3 яруса кроны (полигоны, градиент) | светлячки летят по кривой (2 оси + затухание) |
  | 🔮 Порог | арка/портал (двойной контур) | свет реально проходит СКВОЗЬ портал снизу вверх |
  | ❄️ Изморозь | 3 пересекающиеся линии-снежинка | покачивание ±6°, мерцающие кончики-лучи |
  | 🔥 Инферно | силуэт пламени (градиентная заливка) | угольки разлетаются в стороны + пульсирующий жар позади |
  | ✨ Небесное Сияние | 4-лучевая звезда-сигиль (градиент) | вращение + пульсирующее ядро + мерцающие лучи-спицы |
  | 🌌 Бездна | кольцо + тёмный диск-затмение | диск покачивается орбитой (translate, НЕ rotate+translate+counter-rotate — см. §4) + рой искр |
  | ⚡ Артефакт | гранёный кристалл с рёбрами | бегущий блик по граням (clip-path + sweep) + случайные вспышки-искры |
  | 🌸 Ханами | ветвь сакуры на свитке | цветы дышат вразнобой + отдельный лепесток опадает |
  | 🪷 Лунный Лотос | луна и перламутровый цветок | лотос качается над водой + рябь расширяется |
  | 🐉 Прилив Рюдзина | драконья волна суми-э | поток меняет изгиб + редкая золотая вспышка кинцуги |

## 2. Медальон-оправа (общая для всех, не меняется от линейки к линейке)

```css
.sig-med { border-radius:50%; position:relative; overflow:hidden; }
.sig-med::before { /* radial-gradient тёмный центр → чуть светлее край, inset box-shadow для объёма */ }
.sig-med::after  { /* тонкая 1px обводка цветом линейки, opacity ~.4 */ }
```
Кольцо-прогресс (только на карточке) — `conic-gradient` в цвете линейки поверх
`::after`, с тёмной маской внутри (`.ring-mask`), не отдельный SVG-круг.

## 3. Карточка коллекции

- **Двойная рамка** («трейдинг-карта»): внешняя граница + внутренняя тонкая линия,
  отступ ~3px — не толстая однобокая полоса-акцент. Толстая цветная полоса СБОКУ
  карточки — запрещена, это узнаваемый штамп ИИ-дизайна (поймано design-lint хуком
  проекта на первой попытке, см. `/impeccable`).
- Диагональный засвет цветом линейки (`radial-gradient` из угла, где сидит медальон,
  ~8–14% альфы) — карточка должна выглядеть как единое светящееся целое, а не
  «иконка отдельно, рамка отдельно».
- **Золото — только на действии** («докупить →», кнопки), никогда как заливка цвета
  линейки. Правило из `DESIGN.md`, не локальное — не нарушать.
- **Полоска из 6 реальных слот-иконок** внизу карточки (`✨🖼🌟🏷🖌❄️` — те же эмодзи,
  что использует остальная игра для слотов, НЕ путать с сигилем линейки, это разные
  вещи): ярко-цветная там, где у игрока есть предмет этого слота из линейки,
  тускло-серая (`filter:grayscale(1); opacity:.25`) — где нет.

## 4. Известные баги-ловушки (не повторять)

- **`rotate(...) translate(...) rotate(-...)` для орбиты** — даёт рваный край/скол на
  границе маски при определённых углах (поймано на Бездне). Правильно: простой
  `translate(Xpx,Ypx)` по нескольким keyframe-точкам небольшого радиуса, круг того же
  radius, что и кольцо-основа — без компаунд-трансформов.
- **Бегущий диагональный блик по всей карточке** (`linear-gradient` полоса,
  анимированная `translateX`) — читается как дешёвый баннерный эффект «loading
  shimmer». Не использовать. Вместо этого — статичный (или мягко «дышащий» через
  `opacity`) `radial-gradient` засвет + `inset box-shadow` виньетка по краям.
- **Две CSS-анимации на одном элементе, меняющие ОДНО и то же свойство**
  (например обе трогают `opacity`) — конфликтуют непредсказуемо, дают визуальные
  рывки/дёрганье. Пойман на лучах-короне экрана-праздника (`reveal-up` фейд-ин +
  отдельное мерцание, обе на `opacity` одного элемента). Если нужно и появление,
  и последующая петля — либо объединить в ОДИН набор keyframes, либо развести по
  РАЗНЫМ свойствам (одна анимация трогает `opacity`, другая — `transform`).
- **Декоративная форма, придуманная ПОД анимацию, при остановке этой анимации
  может остаться бессмысленным осколком.** Пример: кольцо-спиннер с прозрачной
  половиной рамки (`border-top-color`+`border-right-color`, остальное прозрачно) —
  форма имела смысл ТОЛЬКО пока вращалась (читалась как «бегущий свет»). Когда
  вращение убрали (после жалобы на «слишком много движения разом»), забыли, что
  сама ФОРМА тоже была частью анимации — осталась необъяснимая полу-дуга без
  функции (владелец: «этот полукруг тут для чего?»). Правило: при остановке
  анимации всегда пересматривать саму форму элемента, не только факт движения —
  и по возможности заменять на форму с самостоятельным смыслом (в этом случае —
  на SVG `stroke-dashoffset`-кольцо, переиспользующее смысл conic-gradient
  прогресс-кольца с карточки коллекции, а не произвольное украшение).
- **`min-height:44px` (или любой явный крупный размер) на самой ВИДИМОЙ пилюле/
  кнопке ради тап-зоны** — раздувает мелкие элементы (10px текст, тонкие иконки)
  в непропорционально толстые «кирпичи», особенно на плотных панелях фильтров.
  Поймано на панели навигации режима «По слотам» (владелец: «кнопки жирные,
  переделывай всё полностью»). Правильно: видимая пилюля остаётся тонкой
  (~28–32px), а тап-зона ≥44px делается НЕВИДИМО — padding на родительской
  обёртке вокруг пилюли, не на самой пилюле.

## 5. Текст на карточке/в детальном экране

- Цена — **всегда с единицей и честным диапазоном**: `"310–590✨"` на карточке
  коллекции и `"310–590✨ за предмет"` в коммерческой информации. Голое число
  без подписи путает. Итог `Купить всё недостающее` всегда складывается из цен
  конкретных отсутствующих предметов, а не умножает количество на базу линейки.
- Статус — **честный текст**, никогда не подразумевает, что коллекцию можно
  «надеть» целиком (у игрока 6 слотов, а не N слотов на линейку!): `"✓ собрано"` /
  `"N не куплено"` / `"не начато"`. Бейдж `"✓ надето"` на уровне КОЛЛЕКЦИИ — запрещён,
  это была реальная ошибка первой версии (владелец: «как ты можешь одеть 20 предметов
  сразу?»). `"✓ надето"` уместен только на уровне ОДНОГО предмета внутри слота.

## 6. Шапка открытой коллекции (детальный экран)

- Тот же медальон, что на карточке, но **крупнее** (74px+) — здесь он герой экрана,
  не мелкая деталь. Никогда не откатываться на голый эмодзи «для простоты» — это
  прямая деградация качества и уже была поймана как ошибка.
- «Алтарная» рамка: двойная обводка + статичный/дышащий радиальный засвет сверху +
  vignette по краям. Никакого бегущего блика (см. §4).
- Фоновая атмосфера — 2–3 крупные, МЕДЛЕННЫЕ, малозаметные частицы в духе линейки
  (угли/снежинки/светлячки/искры — тот же тип, что у иконки, но крупнее и медленнее,
  раз это фон всего экрана, а не деталь 56px иконки).
- Сегментный измеритель — **N делений = N предметов линейки** (не гладкая процентная
  полоса). Заполненные — светятся (`box-shadow`, мягкий пульс). Подпись под ним одной
  строкой: `"X из Y собрано"` слева, `"Z не куплено · min–max✨"` справа.

## 8. Открытые вопросы (НЕ считать решёнными)

- Согласованность стиля с остальным приложением (там всё ещё плоские эмодзи без
  анимации) — сознательно отложено на будущее, см. project-memory
  `project_cosmetics_tab_redesign_2026-07-29`.
- Производительность нескольких одновременно анимированных SVG на слабых
  устройствах — по прямому указанию владельца сейчас не учитывается.

## 9. Совместимость рамки и гало

- Рамка и гало — два разных слоя, в том числе когда игрок смешивает предметы из
  разных линеек. Рамка остаётся близкой к краю аватара; гало живёт снаружи и не
  повторяет ту же геометрию.
- Запрещено одновременно рисовать два скруглённых квадратных контура: это выглядит
  как случайно наложенные неоновые коробки и особенно ломает контрастные сочетания
  вроде огненной рамки с ледяным гало.
- Базовая совместная форма гало — мягкая круглая световая орбита без border. Цвет
  сохраняется от самого гало, поэтому смешанный образ остаётся выразительным, но
  рамка и гало не спорят за одну и ту же кромку.
- Проверять нужно не только полный сет одной линейки, но и минимум одну контрастную
  пару из разных линеек на реальной карточке профиля, крупным кропом до/после.

## 10. Статическая фаза эффектов

- `no-fx` и `prefers-reduced-motion` должны не просто отключать `animation`, а
  оставлять каждый эффект в специально заданной спокойной фазе. Базовое CSS-значение
  может совпасть с пиком вспышки: именно так `cfx-nova` замерзал на полной яркости и
  пересвечивал карточку.
- Для полноэкранного `card_fx` отдельно ограничивать максимальную прозрачность как
  в статике, так и в пиковом keyframe. Декорация остаётся видимой, но не снижает
  читаемость ника, прогресса, силы и характеристик.
- Линейные сканирующие слои и фольга должны иметь маску над зоной идентичности:
  нельзя проводить яркую полосу через аватар, ник и титул даже краткой фазой.
- Угловой эффект начинается от края карточки. Светлые овалы с центром внутри
  поверхности выглядят обрезанными пятнами; для инея и похожих текстур центр
  радиального градиента ставится в сам угол, а не рядом с ним.
- Регрессия обязана проверить одновременно статическую фазу и яркость анимированного
  пика, а визуальная ревизия — минимум две реальные комбинации каждой линейки.
