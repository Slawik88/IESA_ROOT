# IESA — Система профилей и статусов пользователей

> Документ написан для передачи контекста другому ИИ-ассистенту.
> Здесь описано как работают все виды профилей, статусы, права доступа и связанные функции.
> **Без кода — только словами.**

---

## 1. Типы пользователей

В системе есть несколько типов пользователей, которые не являются взаимоисключающими — один человек может одновременно быть, например, участником (member) и партнёром.

### 1.1 Обычный пользователь (зарегистрированный, но не подтверждённый)
- Может зарегистрироваться на сайте и войти в аккаунт.
- Имеет доступ к личному кабинету (My Cabinet).
- Может читать посты, смотреть события, галерею.
- **Не может** публиковать посты самостоятельно — посты уходят на модерацию со статусом "pending".
- Видит бейдж "Pending verification" на своём профиле.
- Имеет QR-карту (генерируется автоматически при активации карты), но без активного членства она не используется для подтверждения визитов.

### 1.2 Верифицированный пользователь (`is_verified = True`)
- Флаг `is_verified` включается администратором вручную.
- Показывает зелёный бейдж "Verified" на публичном профиле.
- Сам по себе не даёт доступ к Member Cabinet или PIN — это отдельный статус.
- Важен для отображения в поиске и публичном профиле как "проверенный участник сообщества".

### 1.3 Активный участник / Член организации (`membership_status = 'active'`)
- Этот статус включается администратором вручную или через систему верификации.
- Даёт доступ к **Member Cabinet** — личному кабинету с PIN-кодом.
- PIN-код генерируется автоматически через TOTP (меняется каждые 12 минут).
- Участник может показать PIN партнёру для подтверждения визита.
- В шапке сайта (дропдаун профиля) появляется пункт "PIN Cabinet".
- Имеет активную QR-карту (если `card_active = True`) — сканирование ведёт на публичный профиль.
- Показывает бейдж "Member" на профиле.

### 1.4 Партнёр (`is_partner = True` ИЛИ существует связанная запись `partner_profile`)
- Партнёр — это бизнес (магазин, спортзал, ресторан и т.д.), который регистрирует визиты участников.
- В шапке сайта появляется пункт "Partner Portal" в дропдауне профиля.
- Партнёр имеет отдельную страницу управления — Partner Dashboard.
- Показывает бейдж "Partner" на профиле.
- Партнёр может как иметь отдельный аккаунт, так и быть тем же пользователем (is_partner на User + запись в таблице Partner).

### 1.5 Администратор / Персонал (`is_staff = True`)
- Показывает бейдж "Admin" на профиле.
- Имеет доступ к Django Admin панели.
- Может верифицировать пользователей, менять membership_status, активировать карты.
- Может делать impersonation (входить под другим пользователем через `/users/impersonate/<id>/`).

## 2. Поля модели пользователя (User)

Каждый пользователь хранит следующие данные:

**Базовые:**
- `username`, `email`, `first_name`, `last_name` — стандартные поля Django
- `password` — хэшированный пароль
- `avatar` — фото профиля (до 5 МБ, загружается в `avatars/`)
- `date_of_birth` — дата рождения
- `phone_number` + `is_phone_hidden` — телефон и флаг приватности

**Идентификация:**
- `permanent_id` — UUID, неизменяемый, используется для QR-карты и стабильных ссылок
- `card_active` — активирована ли физическая карта
- `card_issued_at` — когда была выдана карта

**Статусы:**
- `is_verified` — верифицирован ли пользователь (включается администратором)
- `is_partner` — является ли партнёром
- `membership_status` — `'active'` или `'inactive'`

**PIN и защита:**
- `totp_secret` — секретный ключ TOTP для генерации PIN (генерируется автоматически)
- `failed_pin_attempts` — счётчик неудачных попыток ввода PIN
- `pin_lockout_until` — блокировка после превышения лимита попыток

**Gamification:**
- `activity_points` — очки активности (10 за пост, 2 за лайк полученный, 1 за комментарий)
- `total_posts`, `total_likes_received`, `total_comments_made` — кэшированная статистика

**Социальные ссылки:**
- `github_url`, `discord_url`, `telegram_url`, `website_url`, `other_links`

**Псевдоним:**
- `pseudonym` — опциональный псевдоним (отображается в поиске вместе с именем)

**Telegram интеграция:**
- `telegram_chat_id` — ID чата в Telegram (привязывается через бота или виджет)
- `telegram_linked_at` — дата привязки

## 3. Уровни активности (Achievement Level)

Основаны на `activity_points`. Уровни:

| Уровень | Минимум очков | Цвет |
|---------|--------------|------|
| Beginner | 0 | серый |
| Intermediate | 50 | зелёный |
| Advanced | 200 | синий |
| Expert | 500 | жёлтый/amber |
| Legend | 1000 | красный |

Отображаются в личном кабинете (My Cabinet) с прогресс-баром до следующего уровня. Страница `/users/activity-levels/` объясняет систему уровней.

## 4. Страницы профилей

### 4.1 My Cabinet (`/users/profile/`)
Личный кабинет самого пользователя. Доступен только авторизованному пользователю.

**Что видит пользователь:**
- Своё фото, имя, username, email
- Бейджи статусов (Admin, Partner, Member, Verified/Pending)
- Статистика: посты, лайки, комментарии, очки активности
- Уровень активности с прогресс-баром
- Карточка Telegram: подключён/не подключён, кнопки "Подключить"/"Отключить"
- PIN-карточка (только если `membership_status = 'active'`) — текущий 6-значный PIN с обратным отсчётом, кнопка копирования
- QR-код (только если `permanent_id` есть) — ссылка на публичный профиль через QR
- Социальные ссылки (GitHub, Discord, Telegram, Website)
- Таблица своих постов: название, статус, дата, лайки/просмотры
- Быстрые действия: Edit Profile, Create Post, My Events, View Public Profile, Partners, и т.д.
- Кнопки: Edit Profile, QR Code (скачать), Partner Dashboard (если партнёр), Member Cabinet (если участник)

### 4.2 Member Cabinet (`/users/cabinet/`)
Специальная страница для активных участников. Показывает:

- Текущий PIN-код (6 цифр, обновляется каждые 12 минут)
- Таймер до обновления PIN
- Кнопка копирования PIN
- QR-код пользователя
- История визитов у партнёров (дата, место, сервис, стоимость, статус верификации PIN)
- Статистика посещений

Эту страницу используют участники, чтобы показать PIN партнёру при посещении.

### 4.3 Edit Profile (`/users/profile/edit/`)
Форма редактирования собственного профиля. Поля:
- Аватар, имя, фамилия, псевдоним, дата рождения, телефон
- Флаг видимости телефона
- Социальные ссылки (GitHub, Discord, Telegram, Website, другие)
- Биография / about

### 4.4 Публичный профиль по username (`/users/user/<username>/`)
Доступен всем (в том числе незарегистрированным). Показывает:
- Аватар, имя, username
- Бейджи: Verified, Member Card, Admin
- Социальные ссылки
- Статистика: посты, уровень активности
- Информация (возраст, если не скрыт, псевдоним)

### 4.5 Публичный профиль по QR / permanent_id
- Два URL: `/users/card/<permanent_id>/` и `/users/profile/<uuid>/public/`
- Первый — публичная страница (видят все, кто сканирует карту)
- Второй — используется при верификации у партнёра (partner dashboard сканирует этот QR)
- Показывает: фото, имя, бейджи, статус членства
- Партнёр на этой странице видит форму "Log Visit" — записать визит участника

## 5. Система партнёров

### 5.1 Модель Partner
Партнёр — отдельная запись, связанная с пользователем через OneToOne. Хранит:
- Название компании
- Тип бизнеса (магазин, услуги, спортзал, ресторан, другое)
- Дата создания

### 5.2 Partner Dashboard (`/users/partner/dashboard/`)
Главная панель партнёра. Функционал:
- Список последних визитов, которые логировал партнёр
- Кнопка "Log New Visit" — начать запись нового визита
- Поиск участников по имени/username/ID
- Статистика: общее кол-во визитов, уникальных участников
- Ссылка на аналитику

### 5.3 Логирование визита (`/users/partner/visit/<member_id>/`)
Партнёр открывает анкету визита для конкретного участника:
- Тип сервиса (покупка, консультация, тренировка, событие, другое)
- Описание сервиса
- Стоимость (опционально)
- Комментарий
- PIN-код участника (для верификации — опционально)
- Кнопка сохранить

Если PIN введён и верен — `pin_verified = True` у записи визита.

### 5.4 История визитов (`/users/partner/member/<member_id>/`)
Вся история визитов конкретного участника у данного партнёра.

### 5.5 Редактирование и отмена визита
- Визит можно отредактировать в течение 20 минут после создания (`/users/partner/visit/<id>/edit/`).
- Отмена визита доступна в течение 20 минут (`/users/partner/visit/<id>/cancel/`).
- После редактирования статус меняется на `EDITED`, после отмены — `CANCELLED`.

### 5.6 Partner Analytics (`/users/partner/analytics/`)
Расширенная статистика для партнёра — графики посещений по дням, топ участников и т.д.

### 5.7 Partner Profile Edit (`/users/partner/profile/`)
Редактирование профиля компании партнёра (название, тип бизнеса).

## 6. Модель Visit (Визит)

Каждый визит хранит:
- Кто посетил (member — FK на User)
- Где посетил (partner — FK на Partner)
- Тип сервиса: purchase, consultation, training, event, other
- Описание сервиса
- Стоимость (опционально)
- Комментарий (опционально)
- `pin_verified` — подтверждён ли PIN при визите
- Статус: ACTIVE, EDITED, CANCELLED
- Метка времени (auto_now_add)

## 7. PIN-система (TOTP)

- Каждый пользователь при создании аккаунта получает уникальный `totp_secret` (случайные 20 байт, закодированные в Base32).
- Из этого секрета через TOTP с интервалом 720 секунд (12 минут) генерируется текущий 6-значный PIN.
- PIN автоматически меняется каждые 12 минут.
- При верификации принимается небольшое "окно" (current ± 1 интервал = до 36 минут).
- Защита от брутфорса: счётчик `failed_pin_attempts`, блокировка `pin_lockout_until`.
- PIN показывается только самому участнику в Member Cabinet.
- Партнёр вводит PIN вручную при логировании визита.

---

## 8. QR-карта

- Каждый пользователь имеет `permanent_id` (UUID, неизменяемый).
- QR-код генерируется как изображение по URL `/users/qr/<permanent_id>/`.
- QR хранится в `MEDIA_ROOT/cards/<permanent_id>.png`.
- Если файл отсутствует — генерируется на лету.
- QR кодирует URL публичного профиля: `/users/profile/<uuid>/public/`.
- `card_active = True` означает, что физическая карта выдана участнику.
- Сигнал `post_save` на модели User автоматически генерирует QR при активации карты.

## 9. Telegram интеграция

Два способа привязки Telegram:

**Метод A — через бота (код):**
- Пользователь идёт на `/users/connect-telegram/` и получает уникальный код.
- Вводит этот код в бот IESA в Telegram.
- Бот отправляет webhook, Django привязывает `telegram_chat_id` к аккаунту.

**Метод B — Telegram Login Widget:**
- Виджет на сайте авторизует через официальный виджет Telegram.
- Callback на `/users/telegram/login-callback/` обрабатывает результат.

**После привязки:**
- Пользователь получает уведомления о визитах через Telegram.
- В My Cabinet показывается дата привязки и кнопка "Disconnect".
- Отвязать можно через POST на `/users/disconnect-telegram/`.

## 10. Уведомления

Приложение `notifications` с моделью `Notification` отправляет уведомления:
- При регистрации нового визита у партнёра (через Telegram и/или email).
- При изменении статуса поста (опубликован/отклонён).
- Другие события сообщества (лайки, комментарии).

В шапке сайта: колокольчик с бейджем непрочитанных. При клике — HTMX дропдаун с последними уведомлениями. Бейдж обновляется каждые 5 минут через HTMX polling.

## 11. Поиск пользователей

### Поиск в шапке (глобальный, HTMX)
- Иконка лупы в навбаре открывает дропдаун с полем поиска.
- Поиск работает через HTMX (`/blog/search/`) — ищет по постам, пользователям, событиям, партнёрам.
- Минимум 2 символа для поиска.

### Страница поиска пользователей (`/users/search/`)
- Отдельная страница поиска только по участникам.
- Поиск по username, имени, фамилии, email, псевдониму, permanent_id.
- Поддержка двухсловных запросов ("Иван Петров").

## 12. Дропдаун профиля в шапке (навбар)

Для авторизованного пользователя в навбаре справа:

- **Аватар + username** + стрелка — кнопка открытия дропдауна
- **My Cabinet** — всегда доступен
- **PIN Cabinet** — только если `membership_status = 'active'`
- **Edit Profile** — всегда доступен
- **Partner Portal** — только если `is_partner = True` ИЛИ есть `partner_profile`
- **Logout** — открывает модальное окно подтверждения

Для неавторизованного: кнопки "Sign In" и "Register".

## 14. Техническая архитектура (кратко)

- Django 4.x, PostgreSQL (production), SQLite (dev).
- Приложение `users` содержит: модель User (AbstractUser), Partner, Visit.
- Вьюхи разделены: `views.py` (основные профили) и `views_verification.py` (Partner/Visit/Telegram/PIN).
- Email: `email_service.py` — синхронная отправка через Django SMTP (CleverReach API для маркетинга).
- Telegram: `cleverreach_client.py` + webhook views.
- TOTP PIN: библиотека `pyotp`, интервал 720 сек.
- QR-коды: генерируются через `qrcode` library, хранятся как PNG файлы.
- Уведомления: приложение `notifications` с моделью Notification.
- Сессии: стандартные Django сессии в БД.
- Безопасность: rate limiting на чувствительных эндпоинтах, brute-force защита PIN.
