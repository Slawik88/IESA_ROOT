# 06 · Git и выкатка на прод — решения принимает Claude

Пользователь **доверяет Claude решать, когда коммитить, куда пушить и когда выкатывать на прод**.
Эти правила — рамка этого доверия. Главный факт: **`master` = прод** (`03-hosting-and-deploy.md`),
пуш в него пересобирает оба компонента (сайт + Предвестника).

## Рабочий цикл

1. **Определи проект** (`01-project-boundaries.md`) и состав изменений. Один коммит — один проект.
2. **Не работай в «грязном» дереве пользователя.** Если `git status` показывает чужие правки или текущая
   ветка не `master`, сделай изолированную ветку:
   ```bash
   git fetch origin
   git worktree add -b <тип>/<тема> ../IESA_ROOT_<тема>_wt origin/master
   # скопируй туда ТОЛЬКО свои файлы, дальше все git-команды — из этой папки
   ```
   Тип ветки: `feat/`, `fix/`, `docs/`, `chore/`. Окончив, `git worktree remove ../IESA_ROOT_<тема>_wt`.
   Ветки `backup/*` — архивные, **их не пушить в master** и не использовать как основу.
3. **Коммить сам**, когда завершена логическая единица и её проверки зелёные — не жди просьбы. Не коммить
   сломанное «на потом». Сообщение: `тип(область): суть` + при необходимости список пунктов; в конце —
   строка атрибуции, которую требует среда (системное напоминание про Co-Authored-By).
4. **Ветку с работой пушь сам** (`git push -u origin <ветка>`): это безопасно и даёт резервную копию.
5. **В `master` (на прод) пушь сам, если выполнены ВСЕ условия:**
   - проверки пройдены: для сайта — полный `python manage.py test` + `makemigrations --check`; если менялись
     шаблоны/статика — ещё прогон «как на проде» (`07-local-run-and-tests.md`, раздел про DEBUG=False);
     для Предвестника — `predvestnik_v2/AUTONOMOUS_AGENT_POLICY.md` и `python predvestnik_v2/tools/run_fast_tests.py --changed <файлы>`
     (полный набор: `--all`); для Домового — `python -m pytest tests -q` и `python -m ruff check .` из `domovoy/`;
   - в диффе файлы **одного** проекта (общие `requirements.txt`/`Procfile` — только осознанно и с пометкой);
   - нет секретов, `.env`, баз `*.sqlite3`, `node_modules`, логов;
   - ветка основана на актуальном `origin/master` (фаст-форвард). Если `origin/master` ушёл вперёд —
     `git fetch`, перебазируй свою ветку (`git rebase origin/master`), перезапусти тесты;
   - пользователь не просил «подожди/не выкатывай».
   Команда: `git push origin <ветка>:master` (без `--force`).
6. **После пуша обязательно проверь прод**: деплой в DO дошёл до `Healthy` (Activity/Overview), страницы
   `/`, `/auth/login/`, `/auth/register/` отвечают, в Runtime Logs нет ошибок старта. Сломалось —
   откатывай сразу: `git revert <коммит>` + пуш, либо Rollback в DO (Activity → предыдущий деплой), и
   сообщи пользователю.
7. **Отчитайся коротко**: что запушено, куда (ветка/master), результат проверки прода.

## Что делать нельзя (без явного разрешения пользователя)

- `git push --force` / `--force-with-lease` в `master`; переписывать историю `master`; `reset --hard` чужих правок.
- Пушить в `master`, если тесты красные, дифф смешанный (сайт + бот) или есть невычитанные секреты.
- Обходить хуки (`--no-verify`), подпись, проверки.
- Менять/удалять данные прода руками (Console/БД) без явной просьбы; деструктивные команды вроде
  `prune_bot_accounts --delete` — только после показа dry-run и согласия.
- Коммитить чужие незакоммиченные файлы пользователя (`AGENTS.md`, `.vscode/`, `predvestnik_v2/…`).
- Удалять и пересоздавать ветки пользователя; трогать `backup/*`.

## Осторожнее (пушить можно, но проверь вдвойне и скажи пользователю)

Миграции с потерей данных/переименованием полей; смена `AUTHENTICATION_BACKENDS`/сессий (риск разлогинить всех);
правки `settings.py` (`SECURE_*`, `CSRF_*`, `ALLOWED_HOSTS`), CSP, `Procfile`, `requirements.txt` (затрагивает
и бота); изменения DNS/почты.

## Хук перед пушем в `master` (`~/.claude/hooks/pre_push_master.py`)

По порядку, дешёвое первым: секреты в пушимом диффе → напоминание о патч-ноуте Предвестника → **новые миграции
сайта** → **линт изменённых `.py`** → тесты проекта. Блокирует только реальная находка.

- **Документы.** Правка хостинга/деплоя (`Procfile`, `start.sh`, `run_bots.sh`, `settings.py`, `storage.py`, бэкап)
  без `docs/agent/03`, или авторизации/антибота (`users/views/auth.py`, `antispam.py`, `middleware.py`, шаблоны входа)
  без `docs/agent/04` — разовая остановка на коммит. Документ и так верен — повтори ту же команду пуша.

- **Миграции.** `IESA_ROOT/scripts/check_migration_safety.py` отклоняет новую миграцию с `RunSQL`, `RemoveField`,
  `DeleteModel`, `RenameField`, `RenameModel`. Если так и задумано — сделай в два шага (сначала код перестаёт
  пользоваться полем, удаление — следующим релизом) или запиши в файл миграции строку
  `# migration-safe: <почему это безопасно>` (без причины не считается).
- **Линт.** ruff `E9,F63,F7,F82` (синтаксис, неопределённые имена) и pyright только по правилам-багам:
  `reportUndefinedVariable`, `reportUnusedExcept` (недостижимый `except`), `reportMissingImports` для своих модулей.
  Остальные ~3000 находок pyright — шум типизации, они не блокируют.
- **Предвестник.** `predvestnik_v2/tools/run_fast_tests.py --changed …`: быстрые тесты без базы (параллельно, ~1–2 мин)
  + тесты с PostgreSQL, связанные с изменёнными файлами, на локальном одноразовом кластере
  (`<main>/.local/preprod-postgres`, `127.0.0.1:55432`; хук сам его запускает). Какие тесты требуют базу и какие
  уже падают на `master` (карантин с причиной) — в `predvestnik_v2/tools/test_gate.json`; пересобрать:
  `python tools/run_fast_tests.py --refresh-manifest` (~20 мин). Полный прогон: `--all`.

## Обновление зависимостей

`requirements.txt` (прямые зависимости) + `constraints.txt` (точные версии **транзитивных**, как на проде;
подключён строкой `-c constraints.txt`). Оба компонента — сайт и контейнер ботов — ставятся из одного файла,
поэтому любая библиотека может уронить сразу Предвестника и Домового. Порядок:

1. Отдельное venv на Python 3.11 (рабочее `.venv` не трогать): A = текущие файлы (эталон прода),
   B = с обновлением. `pip check` в обоих.
2. В A и B: полный `manage.py test`; `pytest tests -q` + `ruff check .` в `domovoy/`; импорт всех модулей
   Предвестника и Домового; пробный `python -m bot` обоих ботов с ненастоящим токеном (оба должны дойти до
   отказа Telegram «Unauthorized» одинаково); в B — `predvestnik_v2/tools/run_fast_tests.py --all`
   (сравнивать с карантином в `test_gate.json`).
3. Чистая установка из нового `requirements.txt` должна дать ровно набор B (`pip freeze` побайтно);
   для обновлённых пакетов — Linux-колёса cp311 (`pip download --platform manylinux_2_28_x86_64`).
4. Новые версии транзитивных пакетов вписать в `constraints.txt` тем же коммитом. Один коммит — одна фаза.

## Полезное

- Состояние деплоя без панели: `git log origin/master -1`; панель показывает хеш в Source (`Hash: …`).
- История коммитов Предвестника идёт вперемешку на `master` (сообщения `feat(ui): …`) — коммиты сайта
  помечай областью (`auth`, `site`, `i18n`), чтобы их было видно.
- Предупреждения `LF will be replaced by CRLF` — норма на Windows; не «лечить».
