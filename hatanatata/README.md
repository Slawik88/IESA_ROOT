# HataNatata

Личный Telegram-бот `@HataNatata1Bot` для уведомлений о новых совпадениях аренды
в Швейцарии. Доступ — только двум ID из `HATANATATA_ALLOWED_IDS`, исключительно в ЛС.
Каждый получатель один раз открывает бота и нажимает **Старт**.

## Настройки в ЛС

`/menu` открывает главный экран со сводкой поиска, числом подходящих вариантов,
избранным и состоянием сайтов. Нажатия обновляют одно сообщение; команды открывают
новый экран внизу чата. Удалённое или недоступное для изменения сообщение заменяется
новым. Все экраны позволяют вернуться на главную.

`/settings` открывает кнопки бюджета, комнат, городов, площади, сайтов, частоты
проверок и исключаемых слов. Сохранение подтверждается; при неверном вводе бот
объясняет ошибку прямо в настройке с сохранением текущего значения. Быстрые суммы,
±100 CHF, диапазоны комнат, города и площадь выбираются кнопками; бюджет можно
ввести как `1 500 CHF`. `/cancel` отменяет ввод. Настройки получателей независимы.

Начальный профиль: Wetzikon ZH, до 1500 CHF/месяц, 1.5–2.5 комнаты, без минимальной
площади. Города вводятся латиницей, до пяти. Собственные ссылки поиска:
`/url huusbro https://huusbro.ch/de/mieten/wetzikon`, сброс — `/url huusbro reset`.
Смена городов сбрасывает собственные ссылки. Для Flatfox карта строится автоматически.
Ссылки принимаются только с HTTPS и точным доменом соответствующего портала.

`/current` показывает до 100 подходящих вариантов, увиденных за последние сутки:
по одной карточке, кнопками «Предыдущее»/«Следующее», со временем проверки и прямой
кнопкой перехода на сайт. Сортировка — цена или время последней проверки (не время
публикации). «Обновить» перечитывает локальную подборку без дополнительных HTTP-запросов.
Старые кнопки после обновления списка не сохраняют случайную другую карточку.
Варианты могут уже быть сняты: действительность проверяется на сайте.

`/favorites` — личное избранное. Сохранение доступно и под автоматическим уведомлением.
Избранное переживает перезапуск, смену фильтра и очистку кэша объявлений; удаляется
только самим пользователем. Данные дополняются более свежими проверками, когда они
есть. Для сохранённых карточек явно предупреждаем о возможном снятии с публикации.

`/status` показывает компактную сводку, а по нажатию на сайт — проверку по городам,
последнюю успешную загрузку, ошибки, паузу повторных запросов и частичный охват.
Проверка только части выбранных городов не обозначается как полный успех источника.
`/pause` и `/resume` управляют личными уведомлениями.

Квартиры/дома; распознанные WG, парковки, склады и обмены исключаются. Неизвестная
цена или число комнат не проходят ограничивающие фильтры. Минимальная площадь
также отклоняет объявления с неизвестной площадью. Бюджет сравнивается с полной
арендой, когда портал даёт её явно; иначе сообщение предупреждает проверить NK.
Свободное описание может противоречить карточке — окончательные условия уточняются
у автора. Особые условия Flatfox Priority отмечаются, платный доступ не обходится.

## Частота и ограничения

Один процесс asyncio, один сборщик без Chromium и без AI API. Совпадающие запросы
двух пользователей объединяются. Интервал — 3 минуты по умолчанию, настраивается
от 2 до 60 минут, плюс до 15 секунд случайного сдвига и длительность прохода.
Между запросами к одному домену не менее 2 секунд; HTTP timeout 25 секунд,
ответ до 5 MB, до пяти страниц выдачи на источник/город. Для Flatfox максимум
100 объектов на карту, потом запрашиваются детали по ID; фильтры границ на
`public-listing` самим сайтом игнорируются, поэтому используется `/pin/`.
Для координат города — официальный публичный поиск geo.admin.ch с постоянным кэшем.

Учитываются robots.txt, ETag/Last-Modified, Retry-After и увеличение пауз.
HTTP 403 приостанавливает домен минимум на 30 минут. Ошибки разбора и CAPTCHA
показываются как ошибки. Сервер сайтов может обновлять выдачу с задержкой;
гарантировать мгновенное обнаружение или полный охват всех порталов нельзя.

Проверка с ПК 16.11.2026: Rentumo, Huusbro, Homematch, RealAdvisor и Flatfox
отдают публичные данные. Homegate и ImmoScout24 защищают прямые запросы.
На RealAdvisor часть карточек имеет только JS-переход вместо ссылки: такие
карточки не рассылаются, источник помечается как частичный. Часть объявлений
Homegate/ImmoScout24 доступна через агрегаторы, однако полнота не гарантирована.
Названия и маршруты городов отличаются у порталов: для неподдержанного маршрута
используйте собственную ссылку поиска, а для проблем с Flatfox уточните кантон.

Rentola добавлена восьмым источником 16.11.2026. Публичная выдача читается без входа
и браузера, контактный/платный доступ не используется. URL — `/en/for-rent/<город>`,
для Wetzikon — `wetzikon-zh`. Число комнат берётся из исходного заголовка, включая
2½ и 2.5; округлённое значение схемы используется только когда заголовок его не даёт.
Переходы по страницам используют общий предел пяти страниц и общий кэш/интервалы.
Сайт возвращает 0 результатов для Wetzikon и Hinwil, 50 для Uster на момент проверки.

При первом запуске обновления Rentola один раз добавляется к включённым сайтам
существующих профилей. Бюджет, города, пауза и очередь прежних уведомлений сохраняются.
Полностью выключенный список сайтов остаётся выключенным. После ручного отключения
Rentola перезапуск её не включает. Первая синхронизация — тихая, текущие варианты
появляются в `/current`. Кнопка «Сайты» позволяет управлять Rentola отдельно.
Быстрый live smoke без токена и production SQLite:
`python -m hatanatata.check_sources --source rentola --city Uster`.

Для отката после добавления Rentola используйте исправленный выпуск с сохранённым
ключом `rentola` в реестре источников: старый код до этой интеграции не понимает
новый ключ в профилях/избранном. Не заменяйте SQLite старой копией ради отката кода.

Первый успешный проход каждого нового поиска создаёт тихую исходную точку,
чтобы не отправить пачку старых объявлений; варианты доступны через `/current`.
Дальше новые совпадения попадают в SQLite-очередь отдельно для каждого получателя.
При временном сбое Telegram отправка повторяется. История сохраняется при
перезапуске, одинаковые URL и точные межсайтовые совпадения адреса/комнат/площади/
цены подавляются. Новые уведомления содержат кнопки открытия и сохранения объявления.
В аварийном промежутке между успешным sendMessage и записью
результата возможен повтор: Bot API не имеет идемпотентного ключа отправки.
После изменения фильтров очередь старых совпадений очищается; перед отправкой
фильтр и пауза проверяются повторно. После 24 часов неотправленное совпадение
считается просроченным. Данные объявлений хранятся 30 дней, ключи доставки — постоянно.

## Развёртывание

Только личный `projects-fra1`, `104.248.46.216`. Перед изменениями прочитайте
`docs/agent/03-hosting-and-deploy.md` и серверный `/etc/iesa/OPERATIONS.md`.

- Код: `/opt/hatanatata/releases/<SHA>/hatanatata` из проверенного Git-коммита.
- Отдельный venv Python 3.11.14: `/opt/hatanatata/venvs/<SHA>`.
- Root-only env `/etc/iesa/hatanatata.env`: `HATANATATA_BOT_TOKEN`,
  `HATANATATA_ALLOWED_IDS` (ровно два положительных ID через запятую),
  `HATANATATA_STATE=/var/lib/hatanatata/state.db`.
- Служба `hatanatata.service`, пользователь `hatanatata`, состояние `0700`,
  MemoryHigh 128 MB / MemoryMax 220 MB, CPUQuota 15%, Nice 10.
- Нет публичного порта, nginx-маршрута, PostgreSQL-пула, нового платного ресурса.
- Перед установкой unit замените `RELEASE_SHA` в шаблонах `deploy/` на SHA.
- Запуск: `systemctl enable --now hatanatata`; проверка: `systemctl status
  hatanatata`, журнал, MemoryCurrent, состояние источников и реальный ответ меню.
- Откат: остановить только `hatanatata`, указать прежние проверенные release/venv
  в unit, daemon-reload, start. SQLite/env не откатывать без согласования состояния.

Проверки (отдельное окружение, тесты не используют Telegram/production DB):

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r hatanatata/requirements-dev.txt
.venv/Scripts/python.exe -m pytest hatanatata/tests -q
.venv/Scripts/python.exe -m ruff check hatanatata
.venv/Scripts/python.exe -m hatanatata.check_sources
```

На сервере `python -m hatanatata` запускается только единственным systemd-процессом;
файловая блокировка предотвращает второй локальный polling. Наличие webhook останавливает
запуск. HTTP-ошибки не логируют токен или URL Telegram.

## Копии и восстановление

Отдельный `hatanatata-backup.timer`: каждый час на 17-й минуте, чтобы не совпадать
с `iesa-backup`. Выполняется существующим `/opt/iesa/venv311/bin/python` с уже
установленными boto3/cryptography, окружение других ботов не меняется.
SQLite снимается online backup API с integrity_check. В AES-256-GCM архив входят
состояние, env, три unit-файла, OPERATIONS и SHA выпуска; секретов в открытом виде
в резервной папке нет. Используются существующий `/etc/iesa/recovery.key` и
личный закрытый `makss-projects-backups`, отдельный префикс `hatanatata/`.
Локально — `/var/backups/hatanatata`, хранение 14 дней, общий предел бакета 8 GB.
Загруженный архив скачивается и сверяется SHA-256. Ключ никогда не попадает в R2.
Первая копия проверяется вручную до завершения выпуска.

Для восстановления остановить только HataNatata, скачать нужный `.enc`, проверить
его SHA-256 по доверенной копии/метаданным. Формат `IESACFG1`: header первые 24 байта,
nonce 24:36, ciphertext 36:, AAD=header. Расшифровать сохранённым ключом, проверить
тег GCM и все `snapshot.json.sha256`. Не делать непроверенный extractall. Сначала
восстановить state.db в отдельную папку и проверить integrity_check, users,
очередь/настройки, SHA кода и зафиксированные зависимости. Production-состояние
заменять только после согласования; env root:root 0600, состояние hatanatata:hatanatata
0700/0600. Таймеры и другие боты не переключать.

Обновление интерфейса 16.11.2026 добавляет только таблицу `favorites` и ключи состояния
экранов в существующую `kv`. Прежние настройки, очередь и история не меняют формат.
Предыдущий код может работать с новой SQLite, игнорируя эти дополнения. Избранное
входит в обычную зашифрованную копию состояния; отдельного хранилища ему не нужно.
